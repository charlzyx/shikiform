# 校验

校验要回答两件事：规则是什么，以及字段不在页面上时还查不查。

## 规则

`rules` 接受一条内置规则、一个 [Standard Schema](https://standardschema.dev)（Zod、Valibot、ArkType），或它们的数组：

| 内置规则 | 含义 |
|---|---|
| `required` | 空值失败（也可以直接写 `required` 属性） |
| `min` / `max` | 数字上下限（含） |
| `minLength` / `maxLength` | 字符串长度 |
| `pattern` | 正则 |
| `format: 'email' \| 'url'` | 内置格式 |
| `isTrue` | 必须为 `true`（同意条款） |
| `validator(value, ctx)` | 返回错误文案、空值或它们的 Promise；`ctx` 有 `record`（最近的对象）、`parent`（跳过数组的上一层）、`root`、`get(path)`、`signal`，它们和 `value` 读的是同一轮校验开始时的值。抛错或 reject 时，错误的 `message` 就是这个字段的提示 |
| `message` | 覆盖这条规则的文案 |

```tsx preview play=schema
import { useState } from 'react';
import { Button } from 'antd';
import { z } from 'zod';
import { Field, Form, Watch, useForm, type Draft } from 'shikiform';
import { Checkbox, FormButtonGroup, FormItem, FormLayout, Input } from 'shikiform/antd';

type Values = { username: string; email: string; password: string; confirm: string; agree: boolean };
const TAKEN = ['admin', 'root'];

export default function App() {
  const [result, setResult] = useState('');
  const form = useForm<Values>({
    initialValues: { username: '', email: '', password: '', confirm: '', agree: false },
    fields: {
      username: { asyncDebounceMs: 300 }, // 停止输入 300ms 后才跑异步规则
      confirm: { virtual: true }, // 参与校验，不进提交结果
    },
    // 跨字段：返回 path → 文案
    validate: (values) => (values.confirm && values.confirm !== values.password ? { confirm: '两次密码不一致' } : undefined),
  });
  return (
    <Form form={form} onSubmit={(values) => setResult(JSON.stringify(values))}>
      <FormLayout labelCol={{ span: 5 }} wrapperCol={{ span: 19 }}>
        <Field name="username" title="用户名" required decorator={[FormItem]} component={[Input]}
          rules={[
            z.string().min(3, '至少 3 个字符'),
            { validator: (value, { signal }) => new Promise<string | null>((resolve) => {
              const timer = setTimeout(() => resolve(TAKEN.includes(String(value)) ? '用户名已被占用' : null), 400);
              signal?.addEventListener('abort', () => clearTimeout(timer));
            }) },
          ]} />
        <Field name="email" title="邮箱" required rules={{ format: 'email' }} decorator={[FormItem]} component={[Input]} />
        <Field name="password" title="密码" required rules={{ minLength: 6, message: '至少 6 位' }} decorator={[FormItem]} component={[Input.Password]} />
        <Field name="confirm" title="确认密码" required decorator={[FormItem]} component={[Input.Password]} />
        <Field name="agree" rules={{ isTrue: true, message: '请先同意条款' }} decorator={[FormItem, { wrapperCol: { offset: 5, span: 19 } }]}>
          <Checkbox>我已阅读并同意条款</Checkbox>
        </Field>
        <FormButtonGroup.FormItem>
          <Watch select={(d: Draft<Values>) => d.$submitting}>
            {(submitting) => <Button type="primary" htmlType="submit" loading={submitting}>注册</Button>}
          </Watch>
        </FormButtonGroup.FormItem>
      </FormLayout>
      <pre aria-live="polite">{result}</pre>
    </Form>
  );
}
```

输入 `admin`：异步规则在停止输入后运行，较新的输入会中止旧请求（`signal`）并丢弃迟到的结果。被中止的规则不会拖住提交，即使它的 Promise 永远不 resolve；用 `signal` 清掉定时器或取消请求即可。

整表也可以交给一个 schema：`useForm({ validate: z.object({ … }) })`，issue 的 `path` 会落到对应字段（`['items', 0, 'name']` → `items.0.name`）。字段上的 schema 校验这个字段的值，issue path 相对字段。

## 什么时候校验

- 默认在失焦（`onBlur`）和提交（`onSubmit`）时；表单级改 `validateTrigger: ['onChange', 'onBlur', 'onSubmit']`。控件必须把 blur 交回 `field.onBlur`（接好的 antd 控件已经做了）。已经显示错误的字段，之后每次修改都会重新校验，改对即消失，不必等失焦。
- 手动：`form.validate()` 校验全表，`form.validate('items')` 校验一棵子树，都返回 `FieldError[]`（`{ path, messages }`）。
- `submit` 先等进行中的异步规则再校验；通过才调用回调。校验期间值又变了，就按新值再校验一轮（最多 3 轮），交出去的永远是刚校验过的值。值没变时并发的两次 `submit`（双击）都成功，各自调用自己的回调；要防重复提交，按钮用 `$submitting` 禁用。

## 提交结果

`submit()` 从不 reject，结果按 `reason` 区分：

| 结果 | 含义 |
|---|---|
| `{ ok: true, values }` | 校验通过，`onValid` 已执行完 |
| `{ ok: false, reason: 'invalid', errors }` | 校验失败，没有调用 `onValid` |
| `{ ok: false, reason: 'error', error }` | `onValid`（或表单级 `validate` / `resolver`）抛错，`error` 是抛出的值 |
| `{ ok: false, reason: 'superseded', message }` | 值一直在变，3 轮都没稳定；不是校验错误，`errors` 为空，再提交一次 |

`<Form>` 把结果交给回调（antd 的 `<Submit onSubmit>` 也接受同样三个回调）：

```tsx
<Form
  form={form}
  id="profile"
  onSubmit={save}                                   // 通过校验后调用，可以是 async
  onInvalid={(errors) => scrollToField(errors[0].path)}
  onSubmitError={(error) => message.error(String(error))}  // save 抛错；不传就 console.error
>
  …
</Form>
<button type="submit" form="profile">保存</button>   {/* 其余属性透传给 <form> */}
```

## 内置文案

内置规则、引擎和 `shikiform/antd` 组件的默认文案都是中文。`messages` 按 key 覆盖，没写的 key 用默认值；规则自己的 `message`、组件自己的属性（`title`、`okText` …）永远优先：

```ts
import { createForm, enUS, setDefaultMessages } from 'shikiform'

createForm({ messages: enUS })                       // 整套英文
createForm({
  messages: {
    required: 'Required',
    minLength: ({ minLength }) => `At least ${minLength} characters`,  // 函数拿到参数
    enum: ({ value }) => `${value} is not an option`,
  },
})
setDefaultMessages(enUS)                              // 全应用默认，启动时调一次
```

| key | 何时 | 函数参数（都有 `path`、`value`） |
|---|---|---|
| `required` / `isTrue` / `email` / `url` / `pattern` | 对应规则 | `pattern` 另有 `pattern` |
| `minLength` / `maxLength` | 字符串长度 | `minLength` / `maxLength`、`length` |
| `min` / `max` | 数字范围 | `min` / `max` |
| `enum` | `enumPolicy: 'error'` 且值不在 `$enum` | `options` |
| `fallback` | validator 抛出没有 message 的错误，或 schema issue 的 `message` 为空 | `error` |
| `superseded` | `submit` 结果 `reason: 'superseded'` 的 `message` | — |
| `treeIntoSelf` / `treeSourceMissing` / `treeTargetMissing` / `treeEmptyPos` | `moveTree` 拒绝时的 `reason` | `from`、`to`（不含 `path`、`value`） |
| `submit` / `reset` / `search` / `refresh` / `expand` / `collapse` | antd 按钮：`Submit` / `Reset`、QueryList、ProQueryTable | — |
| `optional` | `requiredMark: 'optional'` 时非必填项标签后的文字（`（可选）`） | — |
| `add` / `remove` / `removeConfirm` / `moveUp` / `moveDown` / `copy` / `dragSort` | ProArrayTable 行操作 | — |
| `selectionCount` / `selectionClear` / `selectionAll` / `selectionInvert` / `density` / `columnSettings` | ProArrayTable 选择栏、密度、列配置 | `selectionCount`：`count`；`density`：`density` |
| `edit` / `ok` / `cancel` | Shadow 触发按钮、ShadowDrawer 底部 | — |
| `yes` / `no` / `empty` | `PreviewText`（阅读态）的布尔值和空值，`empty` 默认空串 | — |

优先级：规则 `message` > 表单 `messages` > `setDefaultMessages` > 内置中文（`zhCN`）。组件读最近的 `<Form>` 的文案；QueryList / ProQueryTable 读 `table.form` 的，要英文就把 `useForm({ messages: enUS })` 作为 `form` 传给 `useQueryTable`，或者直接 `setDefaultMessages(enUS)`。自定义组件用 `useFormMessage()` 跟随同一套文案：`const t = useFormMessage(); t('submit')`；有实例时也可以 `form.message('submit')`。

## 服务端错误

提交后后端说「用户名已存在」，用 `setErrors` 把错误写到字段上：

```ts
await form.submit(async (values) => {
  const res = await api.register(values)
  if (res.status === 409) form.setErrors({ username: '用户名已存在' })
  // 也可以一次给多条、给表单根：form.setErrors({ email: ['格式不对'], '': '服务器繁忙' })
})
```

- 接受 `{ path: 文案 | 文案[] }` 或 `FieldError[]`；`''` 是表单根；空数组清掉那条。单个字段可以用 `setFieldError(path, msg)`。
- 和规则错误一起出现在 `form.errors`、`field.errors`、`$errors` 里，并让 `canSubmit` 为 `false`。
- 自动清除：这个值（或它的上级、下级）变了，或这个字段重新校验（每次 `submit` 都会校验全表）；也可以 `reset()` / `clearErrors(path?)`。

## 规则写在哪

规则写在哪，决定**组件卸载后还查不查**：

| 规则写在 | `<Field>` 卸载后 |
|---|---|
| JSX：`<Field rules required>`、`useField(name, { rules })` | 不再查（挂载期规则，卸载时释放） |
| `useForm({ fields })`、`registerField`、行模板 `items.*.name` | 仍查 |
| reaction 里的 `$rules` / `$required` | 仍查（并且优先级最高） |

显隐和计算字段也会跳过校验，见 [显隐、pattern 与提交](/guide/concepts#显隐pattern-与提交)。注意 `hidden`（`$hidden = true`）仍然校验：藏起来的必填照样挡住提交；`$visible = false` 是 `none`，不校验。

跨标签页、折叠区、虚拟滚动之外都要校验的业务规则，写在 `fields` 或 reaction 里；只在当前界面有意义的规则才写 JSX。
