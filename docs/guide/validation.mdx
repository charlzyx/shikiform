# 校验

姓名留空，离开输入框，会出现提示。邀请码的输入框可以不在页面上，提交时仍然会查。这两件事不是同一种规则。

默认在离开输入框（`onBlur`）和提交（`onSubmit`）时校验。表单用 `validateTrigger` 配置；当前 React `Field` 不接收 `trigger` 属性。需要逐字段触发配置时，使用引擎的 `registerField(path, { trigger: [...] })`。

规则从哪里来，决定卸掉输入框之后还查不查。

| 规则写在 | 输入框卸掉之后 |
|---|---|
| JSX 的 `rules` / `required` | 不再查。卸掉时清掉，不擦掉下面两行 |
| `useForm({ fields })` 或 `registerField` | 仍查 |
| `reaction` 里的 `$rules` / `$required` | 仍查 |

可以在 [没挂载的字段](/guide/unmounted) 里点：关掉「填写更多」再提交，邀请码仍报「必填」，昵称不再报。

display 再决定查不查得到：

- `visible` 和 `hidden` 都查。藏起来的必填，提交一样会挡住。
- `none` 不查，也不进提交结果。
- 计算字段不查。

数量上限可以写在 `reaction` 里，例如库存变了就改 `$rules` 的 `max`。SKU 选择器就是这样，见 [SKU 选择器](/play/sku-picker)。

跨层规则用 `validator` 的 `ctx`。`ctx.parent` 是上一层记录（跳过数组）。C 级供应商的单价不能超过 1000，写在产品价格上，读的是供应商的 `level`。见 [供应商和产品](/play/merged)。

提交会先等进行中的异步规则。校验过程中值又变了，或者又开始了新的一轮校验，这次提交不写入，提示再交一次。
