# Field、装饰器与组件

一个字段要有标签、控件、错误提示，还要知道自己的值和状态。`<Field>` 把这些收在一处：它拥有一个 path，渲染 `decorator` 包住 `component`，并通过上下文把字段交给二者，所以 `FormItem` 和接好的控件都不需要 `name`。

```tsx
<Field
  name="email"              // 相对当前作用域（ObjectField / 数组行 / 树节点）
  title="邮箱"               // 装饰器标签（FormItem → label）
  description="用于登录"      // 装饰器说明（FormItem → extra）
  required rules={{ format: 'email' }}
  decorator={[FormItem, { tooltip: '工作邮箱' }]}
  component={[Input, { placeholder: 'name@example.com' }]}
/>
```

| 属性 | 作用 |
|---|---|
| `name` | 相对路径。`profile.name`，或在 `<ObjectField name="profile">` 里写 `name` |
| `rules` / `required` | 挂载期规则，组件卸载时释放，见 [规则写在哪](/guide/validation#规则写在哪) |
| `display` / `pattern` / `virtual` | 初始显隐 / 编辑态 / 不进提交；reaction 写的值优先 |
| `title` / `description` | 装饰器的标签 / 说明 |
| `decorator` / `component` | 组件，或 `[组件, props]` |
| `decoratorProps` / `componentProps` | 与元组里的 props 相同，单独写 |
| `children` | 控件元素（`<Input />`）或 render prop `(field) => …`，代替 `component` |

`display` 不是 `visible` 时 `<Field>` 不渲染，字段模型仍在：`hidden`（`$hidden = true`）仍校验、仍提交，`none`（`$visible = false`）跳过校验、不提交；详见 [显隐、pattern 与提交](/guide/concepts#显隐pattern-与提交)。

## 四种写法

```tsx preview
import { Input as AntInput } from 'antd';
import { Field, Form, useForm } from 'shikiform';
import { FormItem, FormLayout, Input } from 'shikiform/antd';

export default function App() {
  const form = useForm({ initialValues: { a: '元组', b: '子元素', c: 'render prop', d: '无装饰器' } });
  return (
    <Form form={form}>
      <FormLayout labelCol={{ span: 6 }} wrapperCol={{ span: 18 }}>
        {/* 1. 槽位：最常用 */}
        <Field name="a" title="decorator + component" decorator={[FormItem]} component={[Input, { allowClear: true }]} />
        {/* 2. 子元素：控件从上下文读字段 */}
        <Field name="b" title="children 元素" decorator={[FormItem]}>
          <Input addonBefore="@" />
        </Field>
        {/* 3. render prop：完全自己接线（这里用原生 antd Input） */}
        <Field name="c" title="render prop" decorator={[FormItem]}>
          {(field) => <AntInput id={field.id} value={field.value} onChange={(event) => field.onChange(event.target.value)} onBlur={field.onBlur} />}
        </Field>
        {/* 4. 不要装饰器：表格单元格常用 */}
        <Field name="d" component={[Input]} />
      </FormLayout>
    </Form>
  );
}
```

## UI 状态三层叠加

`title`、`description`、`componentProps`、`decoratorProps` 存在字段模型上，来源从低到高：

1. `fields` 声明；
2. JSX（`<Field title>`、元组里的 props）；
3. reaction（`$title`、`$componentProps.placeholder = …`）。

`componentProps` / `decoratorProps` 深合并：普通对象逐键递归合并，数组、函数、React 元素、类实例取最高一层的整值。所以「根据别的字段改控件属性」写在 reaction 里，而不是在渲染时算 props：

```tsx preview
import { Field, Form, defineEffects, useForm } from 'shikiform';
import { FormItem, FormLayout, Input, Switch } from 'shikiform/antd';

type Values = { vip: boolean; code: string };

const effects = defineEffects<Values>(({ reaction }) => {
  reaction((d) => {
    const vip = d.vip.$value;
    d.code.$title = vip ? '会员码' : '邀请码';
    d.code.$componentProps.placeholder = vip ? 'VIP-0000' : '选填';
    d.code.$componentProps.disabled = !vip;
    d.code.$decoratorProps.tooltip = vip ? '会员必填' : undefined;
    d.code.$required = vip;
  });
});

export default function App() {
  const form = useForm<Values>({ initialValues: { vip: false, code: '' }, effects: [effects] });
  return (
    <Form form={form}>
      <FormLayout labelCol={{ span: 5 }} wrapperCol={{ span: 19 }}>
        <Field name="vip" title="会员" decorator={[FormItem]} component={[Switch]} />
        {/* JSX 的 allowClear 保留：reaction 只覆盖它写到的键 */}
        <Field name="code" title="（被 reaction 覆盖）" decorator={[FormItem]} component={[Input, { allowClear: true }]} />
      </FormLayout>
    </Form>
  );
}
```

reaction 通过 draft 写入时只改写到的那一处：

| 写法 | 结果 |
|---|---|
| `d.x.$componentProps.placeholder = '…'` | 只改这个键，其他键保留 |
| `d.x.$componentProps.style.color = 'red'` | 只补 `style.color`，下层 `style` 的其他键保留。中间对象不会自动创建，先写 `style ??= {}` |
| `d.x.$componentProps.style ??= {}` | 开一层空补丁，不清空下层的 `style` |
| `d.x.$componentProps.style = { color: 'red' }` | 整键替换：下层的 `style` 不再生效 |
| `delete d.x.$componentProps.style` | 去掉这个键，下层的也不再生效 |
| `d.x.$componentProps = { … }` | 整体替换，`fields` 和 JSX 两层都不再生效 |
| `d.x.$componentProps = undefined` | 撤销 reaction 这一层 |

reaction 里读 `$componentProps` 看到的是「声明 + reaction」两层，JSX 只在渲染时合并。UI 状态是唯一能在同一轮读回刚写的值的 `$` 状态。

## Field 就是 useField

`<Field>` 等于 `useField(name, options)` 加「不是 visible 就返回 null」，再渲染两个槽。不用组件时，纯函数 `mapFormItemProps(field, props)` 和 `mapFieldProps(field, props)` 给出同样的 `Form.Item` 和控件 props。在装饰器或控件内部读当前字段，用 `useCurrentField()`。完整签名见 [useField](/reference/react-hooks#usefield) 和 [适配层参考](/reference/antd-adapter)。
