# path 和提交

昵称在 `profile` 里面。确认密码要校验，但不要进提交 JSON。

```tsx preview
import { useState } from 'react';
import { Form, Field, ObjectField, Submit, useForm } from 'shikiform';
import { FormItem, Input } from 'shikiform/ui';

export default function App() {
  const [payload, setPayload] = useState('');
  const form = useForm({
    initialValues: { profile: { name: 'Ada' }, password: '', confirmPassword: '' },
  });
  return (
    <Form form={form} onSubmit={(values) => setPayload(JSON.stringify(values, null, 2))}>
      <ObjectField name="profile">
        <Field name="name" decorator={<FormItem label="昵称" />}>
          <Input />
        </Field>
      </ObjectField>
      <Field name="password" decorator={<FormItem label="密码" />}>
        <Input type="password" />
      </Field>
      <Field name="confirmPassword" virtual decorator={<FormItem label="确认密码" />}>
        <Input type="password" />
      </Field>
      <Submit>提交</Submit>
      {payload ? <pre className="shiki-code">{payload}</pre> : null}
    </Form>
  );
}
```

`ObjectField` 里面的 `name` 是相对名字。昵称的 path 是 `profile.name`。数组行同理，`items.0.price` 这种下标由行自己带上，不要手写死。

`virtual` 的字段照常联动、照常校验，`getSubmitValues()` 把它拿掉。确认密码、翻页（纯前端时）、勾选、展开的 key，通常都是 `virtual`。

提交结果还会拿掉这些：

- display 是 `none` 的字段。`hidden` 的值留着。
- `reaction` 写了 `$value` 的计算字段。要交上去，把这个字段的 `virtual` 设成 `false`。

查询条件先收成一份 `params`：空字符串去掉，关键词去掉两端空白。表格请求读的是这份结果，不是输入框里的原始字符串。见 [查询表](/play/query)。
