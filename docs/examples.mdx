# 复杂示例

这些示例不是另一套教学实现：它们使用和教程相同的正式库。先操作页面，再对照 `playground/pages/` 下的源码。每个 `/play/...` 地址都有独立构建入口，可以直接打开和刷新；目前完整场景支持操作表单，**不支持在页面内修改源码**。想边改代码边看结果，先用 [教程](/tutorial) 与 [API 页内示例](/api)。

建议先看 **SKU 选择器 → 嵌套订单 → 抽屉行编辑**：分别理解联动、数据结构和编辑提交边界。下面覆盖全部 15 个 Play 页面，不把局部演示称作完整业务系统。

## 数组、嵌套与树

| 示例 | 试着完成的流程 | 设计边界 |
|---|---|---|
| [数组与树拖动](/play/headless) | 移动数组行，再把树节点拖到另一父节点下，观察稳定 ID 与变化后的索引位置 | 使用原生拖动和 headless Hooks；不是带增删、缩进/反缩进按钮的完整树编辑器 |
| [嵌套字段](/play/nested) | 切换父级编辑态，展开订单输入，打开/关闭地址抽屉后继续编辑 | 演示 scope、继承与值保留，不是整套嵌套配置产品 |
| [订单行](/play/orders) | 展开订单子表，改数量和单价，再收起/打开；观察行金额与订单合计，以及已发货行的阅读态 | 直接写正式值，收起不回滚；不是草稿编辑或多行撤销。待处理订单还有依赖父订单状态的数量规则 |
| [供应商和产品](/play/merged) | 在合并列编辑供应商，在子列编辑产品；只看在售后检查 rowSpan；尝试给 C 级供应商填超过 1000 的单价 | 数据保持嵌套，合并只是显示；校验仍使用正确的父记录 |

对应学习：[数组逐行联动](/tutorial/7-array)、[path 和提交](/guide/path)、[数组/树 Hooks](/reference/react-hooks#usearrayfield)。

## SKU 与多维联动

| 示例 | 试着完成的流程 | 设计边界 |
|---|---|---|
| [SKU 选择器](/play/sku-picker) | 任意顺序选三个维度；改一个维度时保留最新选择、清理冲突；观察缺货禁用、价格区间/唯一价和库存数量上限 | 展示选择约束与派生状态，不是服务端库存锁定或下单系统 |
| [SKU 表格](/play/sku-editor) | 用同一份 SKU 数据编辑价格，改合并的颜色，再加渠道列，检查价格仍属于原 `skuId` | 组合结构变化时按稳定 ID 保留值，而不是按旧行号搬运价格 |
| [组合生成行](/play/sku) | 勾选有库存的颜色/尺寸组合生成行，修改价格与数量，再改变组合 | 是较小的数组联动示例；价格覆盖按组合 ID 保存，不等同于上面的完整三维选择交互 |

对应学习：[reaction / watch 分工](/guide/effects)、[逐行 reaction](/tutorial/7-array)。

## 查询与校验

| 示例 | 试着完成的流程 | 设计边界 |
|---|---|---|
| [antd 查询表](/play/query) | 填条件、折叠筛选区域、切列筛选、选择行、翻页后重新查询 | 条件折叠不丢值；关键词 trim、空条件不入参数；新搜索回到第 1 页并清空选择。列筛选和表单共用状态 |
| [原生查询表](/play/query-native) | 使用原生输入、勾选、分页、查询/重置/刷新完成同样的查询流程 | 使用 `shikiform/pro` 的 headless Hook，说明查询逻辑不绑定 antd；请求来自本地数据集 |
| [Schema 校验](/play/schema) | 提交空表，修正邮箱/确认密码/嵌套地址/数组项；隐藏昵称或排除 ghost 后再提交 | 同时使用字段 Zod 与整表 Valibot Standard Schema；hidden 不跳过业务校验，none 才排除 |
| [标签页与规则生命周期](/play/tabs) | 切换基本/附加页后提交，比较表单声明的必填与只在附加页挂载的 JSX 必填 | 跨页业务规则不靠输入框是否渲染；没有额外的 `forceMount` 字段 API |
| [显隐对照](/play/display) | 在 visible、hidden、none 之间切换，再检查错误与提交 JSON | hidden 保留校验和提交；none 排除。显隐不是 virtual，也不是清空字段值 |

查询页展示请求流程，行编辑页展示异步加载；它们**不等于**一个覆盖防抖校验、远程枚举和提交竞态的完整异步表单案例。异步规则、等待期间再编辑的行为，以 [校验指南](/guide/validation) 和 [查询 Hooks](/reference/query-hooks) 的契约为准。

## 抽屉行编辑

[打开行编辑](/play/row-edit)：点一行的「编辑」，等待数据装入抽屉；改值后「取消」，原行不变；重新打开并「确定」，才按稳定 ID 写回这一行。「详情」走阅读态。

这里用一个 `virtual` editor 区域显式装载和确认，加载请求用序号避免旧结果回填。**这是示例自己的单编辑器流程，不是通用 ShadowForm，也不是并发多行事务。** 与 [订单行](/play/orders) 的「输入即写正式值」刻意不同。阅读代码时先决定业务需要哪一种提交边界。

## 大数据与虚拟行

| 示例 | 可以观察什么 | 不应据此推断什么 |
|---|---|---|
| [字段规模与局部联动](/play/large) | 两档分别是 40 行 × 5 字段（200 字段）和 200 行 × 5 字段（1000 字段）；滚动虚拟区，改单行成本，观察建议价与渲染计数 | 不是 2000 行性能结果；没有以此承诺首屏耗时、帧率或所有设备上的吞吐 |
| [虚拟行容器](/play/virtual) | 40 行数据放进有限高度窗口，滚动时只挂载附近行 | 当前 `ArrayTable` 是虚拟行容器，不是 antd Table 的完整列/排序/分页替代品 |

渲染多少行和校验哪些数据是两个问题。离屏仍需校验的规则应通过声明/模板定义，而非依赖每个输入框同时挂载，见 [没挂载的字段](/guide/unmounted)。
