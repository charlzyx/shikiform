---
title: 字段状态
description: $value 与 visible、disabled、readOnly、omit 四个独立布尔的行为规则。
---

字段自身状态以 `$` 开头挂在 handle 上。显隐、编辑与提交由四个独立布尔控制：`$visible`、`$disabled`、`$readOnly`、`$omit`。

`reaction` 写入 `$value` 的字段是计算字段：仍然可编辑，也仍然提交，不计入 dirty。要预览就再写 `readOnly`；不要提交就声明 `omit: true`。

## 四个布尔

| 开关 | 默认 | 界面 | 校验 | 提交 |
|---|---|---|---|---|
| `visible` | `true` | 是否渲染 | `false` 时跳过并清错 | 仍然提交，计入 dirty |
| `disabled` | `false` | 置灰、不可编辑 | 跳过并清错 | 提交 |
| `readOnly` | `false` | 渲染预览。与 `disabled` 同时为真时预览优先 | 跳过并清错 | 提交 |
| `omit` | `false` | 不影响 | 不影响 | 剔除该字段及其子孙，表单级不计入 dirty |

四个布尔都沿字段路径继承。`visible` / `disabled` / `readOnly`：这一层写了 `true` 或 `false` 就用这一层，没写就保持上一层。所以父级 `disabled: true`、子级 `disabled: false` 时，子级可以编辑。`omit`：任一祖先为 `true`，子孙读到的 `$omit` 就是 `true`；子级写 `omit: false` 不能单独提交，因为父级被删掉时整棵子树一起离开提交结果。父级取消 `omit` 后，子级回到自己的值（没写就是提交）。`FormLayout` / `FormTab` 不是字段路径上的父级。赋 `undefined` 丢掉 reaction 层。隐藏后再显示，值还在。关掉校验门会清掉已有错误；再打开时不会自动重跑，要等下一次 blur、`validate` 或 `submit`。`disabled` 的字段照常提交，这和 react-hook-form 相反。

被 omit 的祖先自己的 `$dirty` 仍按深比较计算，值变了时可以为 `true`，但表单级 `dirty` 不计这个字段及其子孙；子孙字段的 `$dirty` 则是 `false`。

```tsx preview
import { useState } from 'react';
import { defineEffects, Form, typed, useForm, Watch, type Draft } from '@shikiform/react';
import { FormItem, Input, Select, Submit } from '@shikiform/antd';

type Mode = 'visible' | 'hidden' | 'omit' | 'readOnly';
type Values = { mode: Mode; nick: string };

const effects = defineEffects<Values>(({ reaction }) => {
  reaction((d) => {
    const mode = d.mode.$value;
    d.nick.$visible = mode !== 'hidden';
    d.nick.$omit = mode === 'omit';
    d.nick.$readOnly = mode === 'readOnly';
  });
});

export default function App() {
  const [result, setResult] = useState('');
  const form = useForm<Values>({ initialValues: { mode: 'visible', nick: 'ada' }, effects: [effects] });
  const F = typed(form);
  return (
    <Form form={form} onSubmit={(values) => setResult(JSON.stringify(values))}>
      <F.Field
        name="mode"
        title="状态"
        enum={['visible', 'hidden', 'omit', 'readOnly']}
        decorator={[FormItem]}
        component={[Select, { style: { width: 160 } }]}
      />
      <F.Field name="nick" title="昵称" required decorator={[FormItem]} component={[Input]} />
      <Watch select={(d: Draft<Values>) => d.nick.$visible}>{(shown) => <p>读 $visible：{String(shown)}</p>}</Watch>
      <Submit>提交</Submit>
      <pre>{result}</pre>
    </Form>
  );
}
```

可以在上面的例子中切换选项观察差异：
- 选 `hidden` 时，输入框消失，也不再校验；提交的 JSON 里仍然有 `nick`。
- 选 `omit` 时，输入框还在、空值会拦住提交，通过之后 JSON 里没有 `nick`。
- 选 `readOnly` 时，输入框换成预览，不校验，值照常提交。

<Aside type="caution" title="隐藏不等于不提交">
`$visible = false` 只是不渲染、不校验。值仍然提交。不进提交结果要再写 `$omit = true`。父级 `omit` 时，子字段的 `$omit` 也是 `true`，不能用 `omit: false` 单独提交。
</Aside>

## 禁用和只读

`disabled` 把控件置灰。`readOnly` 换成预览组件。两个都是 `true` 时渲染预览。

它们和 `visible` 一样沿字段路径继承：这一层写了 `true` 或 `false` 就用这一层，没写就保持上一层。赋 `undefined` 丢掉 reaction 层。详情页：`useForm({ readOnly: true })`，或运行时 `form.batch((d) => { d.$readOnly = true })`。
