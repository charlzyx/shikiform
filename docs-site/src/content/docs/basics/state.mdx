---
title: 字段状态
description: $value 与 visible、disabled、readOnly、omit 四个独立布尔的行为规则。
---

字段自身状态以 `$` 开头挂在 handle 上。显隐、编辑与提交由四个独立布尔控制：`$visible`、`$disabled`、`$readOnly`、`$omit`。

`reaction` 写入 `$value` 的字段是计算字段：仍然可编辑，也仍然提交，不计入 dirty。要预览就再写 `readOnly`；不要提交就声明 `omit: true`。

## 四个布尔

| 开关 | 默认 | 界面 | 校验 | 提交 |
|---|---|---|---|---|
| `visible` | `true` | 是否渲染 | `false` 时跳过并清错 | 仍然提交，计入 dirty |
| `disabled` | `false` | 置灰、不可编辑 | 跳过并清错 | 提交 |
| `readOnly` | `false` | 渲染预览。与 `disabled` 同时为真时预览优先 | 跳过并清错 | 提交 |
| `omit` | `false` | 不影响 | 不影响 | 剔除该字段及其子孙，表单级不计入 dirty |

四个开关的继承和交互规则很简单：
- **显隐、禁用、只读**：父级设置后，子字段默认跟着生效；子字段显式写 `true` 或 `false` 就能覆盖父级（例如父级 `disabled: true`，子字段写 `disabled: false` 依然可以编辑）。纯布局组件不算父字段。
- **不提交（`omit`）**：只要任意一层父字段设了 `omit: true`，整棵子树都会从提交结果中剔除，子字段写 `omit: false` 也无法单独保留；父级取消 `omit` 后，子字段恢复各自的配置。
- **隐藏与跳过校验**：把字段隐藏（`visible: false`）后再显示，原先填的值还在。变成隐藏、禁用或只读时，已有的报错会立刻清空；恢复可编辑后不会自动重跑校验，要等下次失焦、`validate` 或 `submit`。
- **撤销联动覆盖**：在 `reaction` 里赋 `undefined`（如 `d.nick.$disabled = undefined`），就会撤销联动里的设置，恢复成组件或字段默认配的状态。
- **禁用也会提交**：`disabled` 字段照常提交（这与 react-hook-form 相反）；不想提交时再配 `omit: true`。

如果一个父字段自己设了 `omit: true`，改它的值时它自己的 `$dirty` 仍可能为 `true`，但整张表的 `form.dirty` 不会把它和它的子字段算进去（子字段的 `$dirty` 则是 `false`）。

```tsx preview
import { useState } from 'react';
import { defineEffects, Form, Submit, typed, useForm, Watch, type Draft } from '@shikiform/react';
import { Badge, Button, FieldInput, FieldRadioGroup, siteKit } from '@site/ui';

type Mode = 'visible' | 'hidden' | 'omit' | 'readOnly';
type Values = { mode: Mode; nick: string };

const effects = defineEffects<Values>(({ reaction }) => {
  reaction((d) => {
    const mode = d.mode.$value;
    d.nick.$visible = mode !== 'hidden';
    d.nick.$omit = mode === 'omit';
    d.nick.$readOnly = mode === 'readOnly';
  });
});

export default function App() {
  const [result, setResult] = useState('');
  const form = useForm<Values>({ initialValues: { mode: 'visible', nick: 'ada' }, effects: [effects] });
  const F = typed(form);
  return (
    <Form form={form} kit={siteKit} onSubmit={(values) => setResult(JSON.stringify(values))} style={{ maxWidth: 440 }}>
      <F.Field
        name="mode"
        title="状态"
        enum={['visible', 'hidden', 'omit', 'readOnly']}
        component={[FieldRadioGroup, { variant: 'button' }]}
      />
      <F.Field name="nick" title="昵称" required component={FieldInput} />
      <Watch select={(d: Draft<Values>) => d.nick.$visible}>
        {(shown) => (
          <div style={{ display: 'flex', alignItems: 'center', gap: 8 }}>
            <span style={{ fontSize: 13, color: 'var(--sf-ui-fg-muted)' }}>读 $visible</span>
            <Badge variant={shown ? 'success' : 'warning'} dot>{String(shown)}</Badge>
          </div>
        )}
      </Watch>
      <div><Submit asChild><Button variant="primary">提交</Button></Submit></div>
      {result && <pre>{result}</pre>}
    </Form>
  );
}
```

可以在上面的例子中切换选项观察差异：
- 选 `hidden` 时，输入框消失，也不再校验；提交的 JSON 里仍然有 `nick`。
- 选 `omit` 时，输入框还在、空值会拦住提交，通过之后 JSON 里没有 `nick`。
- 选 `readOnly` 时，输入框换成预览，不校验，值照常提交。

<Aside type="caution" title="隐藏不等于不提交">
`$visible = false` 只是不渲染、不校验。值仍然提交。不进提交结果要再写 `$omit = true`。父级 `omit` 时，子字段的 `$omit` 也是 `true`，不能用 `omit: false` 单独提交。
</Aside>

## 禁用和只读

`disabled` 把控件置灰，`readOnly` 换成纯文本预览。两个同时为 `true` 时，以只读预览为准。

它们和 `visible` 一样从父级向下继承，子字段可以单独写 `true` / `false` 覆盖，在 `reaction` 里赋 `undefined` 可撤销联动覆盖。整页详情只读可以写 `useForm({ readOnly: true })`，或者运行时调用 `form.setReadOnly(true)`（等价于 `form.batch((d) => { d.$readOnly = true })`）。
