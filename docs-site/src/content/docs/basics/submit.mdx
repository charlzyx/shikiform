表单内按回车、点击 `<Submit>`（`type="submit"`）或直接调用 `form.submit()` 走同一套校验与提交流程。全部规则通过后才调用 `<Form onSubmit>`，传入的值已剔除 `omit` 字段。`<Form>` 已渲染原生 `<form>` 元素，不要在外部或内部再嵌套 `<form>`。

`form.submit()` 是一个 Promise，和 Formily 一样：

| 结果 | 触发场景 |
|---|---|
| resolve 提交值 | 校验通过。没传 `onValid`，或 `onValid` 返回 `undefined`，resolve 的就是提交值 |
| resolve `onValid` 的返回值 | 传了 `onValid` 且它返回了非 `undefined` 的值（`await` 之后） |
| reject `FieldError[]` | 校验未通过，不会调用 `onValid` |
| reject `onValid` 抛出的那个错误 | `onValid` 或表单级 `validate` 自己抛错，原样 reject |
| reject `SubmitSupersededError` | 这次提交被后一次 `submit()` 取代。`code` 是 `'superseded'`，`message` 来自 `messages.superseded`。不是 `FieldError[]` |
| reject `SubmitUnstableError` | 校验期间值连续 3 轮都没稳定（不是被后一次提交取代）。`code` 是 `'unstable'`，`message` 同样来自 `messages.superseded` |

```ts
try {
  const values = await form.submit()
  save(values)
} catch (error) {
  if (error instanceof SubmitSupersededError) return // 后一次提交会给出结论
  if (error instanceof SubmitUnstableError) return report(error)
  if (isFieldErrors(error)) showErrors(error)
  else report(error)
}

form.submit(async (values) => {
  const saved = await api.save(values)
  return saved.id
}).then((id) => setId(id)).catch((error) => {
  if (isFieldErrors(error)) scrollTo(error[0]?.path)
  else report(error)
})
```

直接调用 `form.submit()` 时要 `await`，或者接上 `.catch`。没有接住的失败会变成未处理的 rejection（unhandled rejection）。

`<Form>` 和 `<Submit>` 会在内部 catch 这次 rejection：校验失败走 `onInvalid(errors)`，`onSubmit` 抛错和 `SubmitUnstableError` 走 `onSubmitError`（不传则 `console.error`），被取代的那次提交被吞掉，不会变成未处理的 rejection。

校验失败时，`<Form>` 按文档顺序自动聚焦第一个出错字段，无需在 `onInvalid` 中手动定位。

## Submit 与 Reset 按钮

`@shikiform/react` 提供无样式的 `Submit` 和 `Reset` 按钮组件（默认渲染原生 `<button>`，也支持 `asChild` 或 render prop 接入任意 UI 库）。

- `Submit`：订阅 `$canSubmit` 与 `$submitting`。存在已暴露的错误或正在提交时禁用并设置 `aria-busy` / `data-loading`；尚未触发校验的空必填项不会在初始渲染时禁用按钮，首次点击仍会执行校验。
- `Reset`：点击调用 `form.reset()` 恢复初始值。`onClick` 在重置前执行，调用 `event.preventDefault()` 可取消重置；`afterReset(values)` 在重置完成后执行，参数为恢复后的表单值。

```tsx preview
import { useState } from 'react';
import { Form, Reset, Submit, typed, useForm } from '@shikiform/react';

type Values = { name: string };

export default function App() {
  const [log, setLog] = useState('');
  const form = useForm<Values>({ initialValues: { name: 'Ada' } });
  const F = typed(form);
  return (
    <Form
      form={form}
      onSubmit={(values) => setLog(`提交 ${JSON.stringify(values)}`)}
      onInvalid={() => setLog('没有通过校验')}
    >
      <F.Field name="name" title="姓名" required>
        {(f) => (
          <p>
            <label htmlFor={f.id}>{f.title}：</label>
            <input
              id={f.id}
              value={f.value ?? ''}
              onChange={(e) => f.onChange(e.target.value)}
              onBlur={f.onBlur}
            />
            {f.errors[0] && <small role="alert" style={{ color: 'crimson' }}> {f.errors[0]}</small>}
          </p>
        )}
      </F.Field>
      <div style={{ display: 'flex', gap: 8 }}>
        <Submit>提交</Submit>
        <Reset afterReset={(values) => setLog(`重置 ${JSON.stringify(values)}`)} />
      </div>
      <pre aria-live="polite">{log}</pre>
    </Form>
  );
}
```

清空姓名后点击提交，页面焦点会自动回到姓名输入框，同时下方显示「没有通过校验」；接着点击重置按钮，姓名会恢复为 `Ada`，日志同步更新为重置后的表单值。

<Aside type="tip" title="保存成功后更新初始基线">
保存成功后若要保留当前值并清掉 `dirty` 标记，调用 `form.setInitialValues(form.values)`；加载另一条记录并替换基线则调用 `form.reset(record)`。
</Aside>

服务端返回字段错误（如用户名冲突）时，调用 `form.setErrors({ username: '已存在' })` 写回对应路径，详见 [服务端错误](/guide/validation#服务端错误)。
