练习代码里有一个「需要联系」开关，目前无论开或关，下方的邮箱输入框始终显示在界面上。

在联动函数中，字段的自身状态统一带有 `$` 前缀（例如 `$value` 读取当前值，`$required` 控制必填），不带 `$` 的属性名则代表子字段。

ShikiForm 用 `display` 区分四种渲染与提交行为：

| 值 | 界面渲染 | 参与校验 | 参与提交 |
|---|---|---|---|
| `visible` | 是 | 是 | 是 |
| `hidden` | 否 | 是 | 是 |
| `virtual` | 是 | 是 | 否 |
| `none` | 否 | 否 | 否 |

其中 `$visible = false` 等价于 `display = 'none'`，而 `$hidden = true` 对应 `display = 'hidden'`。读取 `$visible` 时，只要字段在界面上可见（即 `visible` 或 `virtual`），结果都为 `true`。

另一组常用状态是 `pattern`（包含 `editable`、`disabled`、`readOnly`、`readPretty`），它支持从父级向下继承；如果某个子字段显式设置了自己的 `$pattern`，则会覆盖父级的配置。

**这一步：** 在 `reaction` 中补充 `d.email.$visible = d.contact.$value`。

完成后，关闭开关即可隐藏邮箱。即便先清空邮箱再关闭开关，点击提交依然能够顺利通过，且最终 JSON 中不包含 `email`；同时引擎会保留原先输入的值，重新打开开关时内容依然还在。

如果业务要求「隐藏界面但依然校验并提交数据」，可以改为设置 `d.email.$hidden = !d.contact.$value`。
