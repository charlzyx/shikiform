练习代码里有一个「需要联系」开关，目前无论开或关，下方的邮箱输入框始终显示在界面上。

在联动函数中，字段的自身状态统一带有 `$` 前缀（例如 `$value` 读取当前值，`$required` 控制必填），不带 `$` 的属性名则代表子字段。

ShikiForm 用 `display` 区分四种渲染与提交行为：

| 值 | 界面渲染 | 参与校验 | 参与提交 |
|---|---|---|---|
| `visible` | 是 | 是 | 是 |
| `hidden` | 否 | 是 | 是 |
| `virtual` | 是 | 是 | 否 |
| `none` | 否 | 否 | 否 |

`$visible = false` 不渲染、不校验，值仍然提交。不提交用 `$omit = true`（不继承）。`disabled` 置灰，`readOnly` 渲染预览；两者同时为真时 `readOnly` 优先。`visible` / `disabled` / `readOnly` 按 OR 从父级继承，显式 `false` 可以退出。

校验只在 `visible && !disabled && !readOnly` 时运行。

**这一步：** 在 `reaction` 中补充 `d.email.$visible = d.contact.$value`。

完成后，关闭开关即可隐藏邮箱。即便先清空邮箱再关闭开关，点击提交依然能够顺利通过，且最终 JSON 中不包含 `email`；同时引擎会保留原先输入的值，重新打开开关时内容依然还在。

隐藏后的字段仍然提交。如果这份数据不该进提交结果，再写 `d.email.$omit = true`。
