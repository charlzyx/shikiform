第一段练习中，单价和数量已经填好，但金额不会自动更新，仍然需要手动填写。

派生计算适合用 `reaction`：它会在表单初始化时立即执行一次，并自动收集内部读取的所有 `$` 状态作为依赖；当依赖发生变化时重新计算。如果一个计算结果在当前轮次还要继续使用（比如先算小计再算税费），请先存入局部变量，不要直接读回刚赋值的 `$value`。

凡是被 `reaction` 写入过 `$value` 的字段都是计算字段：它仍然可编辑、也仍然提交。需要预览就写 `$readOnly = true`；不需要提交就声明 `omit: true`。

**这一步：** 用 `defineEffects` 注册一条 `reaction`：

```ts
const amount = (d.price.$value || 0) * (d.qty.$value || 0);
d.amount.$value = amount;
```

将 `effects` 传给 `useForm` 后，修改单价或数量，金额会自动更新且转为只读展示，最终提交的 JSON 里也会包含 `amount`。

第二段练习中，初始省份为「浙江」，原本对应的初始城市是「杭州」，但因为起始代码把清空城市的逻辑错写在了 `reaction` 中，导致表单一打开就把杭州清空了。

「在某个字段变化时执行一次性动作」应该使用 `watch`：它在初始化时不执行，只有当第一个参数中监听的状态发生改变时，才会触发回调。

这段代码同时演示了 `typed(form)` 返回的 `F.Field`：它与普通 `<Field>` 行为一致，只是会在编译期检查字段名是否拼写正确。

**这一步：** 在 `reaction` 中仅保留 `d.city.$disabled = !d.province.$value`，把清空城市改为 `watch`：

```ts
watch(
  (d) => d.province.$value,
  (d) => {
    d.city.$value = '';
  },
);
```

修改后，首次打开时城市会保留「杭州」；只有主动切换省份后，城市才会被清空；如果清空省份，城市选择器也会随之禁用。
