ShikiForm 的核心思路是把所有表单状态（值、显隐、只读、校验规则、错误提示、UI 属性）和联动逻辑收拢到一个与视图框架解耦的引擎中。React 组件和 Ant Design 适配层本身不维护独立状态，它们只负责订阅对应路径的变化并把状态映射为组件属性。

理解这套模型后，日常开发只需掌握以下几个核心概念。

## 术语速览

| 术语 | 说明 |
|---|---|
| **表单实例** | 由 `useForm` 或 `createForm` 返回的 `FormInstance`，统一持有表单数据树与各路径的字段状态 |
| **draft** | `reaction`、`watch` 和 `form.batch` 回调收到的参数 `d`，用来安全地追踪依赖并读写引擎状态 |
| **handle** | draft 上的路径句柄（如 `d.user.name`）。属性访问只用于定位路径，不会直接读取数据 |
| **`$` 状态** | 挂在 handle 上以 `$` 开头的成员（如 `$value`、`$required`、`$visible`），用于读写具体的字段状态 |
| **`decorator` / `component`** | `<Field>` 渲染的两层结构：`decorator`（如 `FormItem`）负责标签和错误展示，`component`（如 `Input`）负责输入交互 |
| **`reaction` / `watch`** | `reaction` 用于派生状态，初始化即运行并自动追踪依赖；`watch` 用于副作用动作，仅在监听源变化后触发 |
| **`each`** | `reaction.each` 与 `watch.each` 只接受两个参数，会为选中数组的每一行建立独立实例，并自动递归进入嵌套对象数组（嵌套在对象上的基本类型数组除外；若直接对基本类型数组本身调用 `each`，则会在 `depth === 0` 触发回调），可在回调内按 `ctx.key` / `ctx.depth` 过滤 |
| **四个布尔** | `visible`、`disabled`、`readOnly`、`omit`。前三个按字段路径继承，`omit` 只决定是否提交 |

## handle 与 value 的区别

在 `reaction`、`watch` 或 `form.batch` 中，初学者最容易混淆「字段句柄（handle）」和「字段值（value）」。记住一条核心原则：**不带 `$` 的访问是在定位路径，带 `$` 的成员才是读写状态**。

```ts
d.user.name.$value            // 读取字段值（在 reaction 中会自动登记为依赖）
d.user.name.$value = 'Ada'    // 更新该字段的值
d.user.name.$required = true  // 修改该字段的必填状态
d.items.$value                // 获取整个数组的值（d.items 本身只是路径句柄，不是数组）
```

实际使用时需要注意三点：
1. **不要直接修改 `$value` 返回的对象**：`$value` 返回的是不可变快照，直接执行 `d.user.$value.name = 'x'` 既不会触发通知，在开发环境下还会直接抛出错误。需要改哪个字段，就赋值给那个字段自己的 `$value`。
2. **不要把 handle 当作数组操作**：诸如 `d.items.map`、`d.items.length` 或 `for…of d.items` 都是无效的。遍历行逻辑请用 [`reaction.each`](/guide/linkage)，读取整组数据请访问 `d.items.$value`。
3. **字段本身叫 `value` 时**：依然遵循同一规则，通过 `d.value.$value` 读写。

### 关于解构

**解构仅用于提前取出子字段的 handle，任何 `$` 状态都必须挂在 handle 上读写：**

```ts
const { name } = d.user // name 依然是指向 d.user.name 的 handle
name.$value = 'Ada'
```

在开发模式下，对象展开（`{ ...d.user }`）、rest 剩余属性、`Object.keys(d.user)` 以及数组解构（`const [first] = d.items`）都会触发 `ShikiUsageError`，错误信息中会提示改用 `d.items[0]` 或 `d.user.$value` 等正确写法。更多案例见 [常见的坑](/practices/pitfalls#解构)。

```tsx preview
import { Button, Space } from 'antd';
import { Field, Form, Watch, useForm, type Draft } from '@shikiform/react';
import { FormItem, Input } from '@shikiform/antd';

type Values = { user: { name: string; email: string } };

export default function App() {
  const form = useForm<Values>({ initialValues: { user: { name: 'Ada', email: '' } } });
  return (
    <Form form={form}>
      <Field name="user.name" title="姓名" decorator={[FormItem]} component={[Input]} />
      <Field name="user.email" title="邮箱" decorator={[FormItem]} component={[Input]} />
      <Space wrap>
        <Button onClick={() => form.batch((d) => { d.user.name.$value = 'Grace'; })}>写 user.name</Button>
        <Button onClick={() => form.batch((d) => { d.user.email.$required = !d.user.email.$required; })}>切换邮箱必填</Button>
        <Button onClick={() => form.batch((d) => { d.user.email.$readOnly = !d.user.email.$readOnly; })}>切换阅读态</Button>
      </Space>
      <Watch select={(d: Draft<Values>) => d.user.$value}>{(user) => <pre>{JSON.stringify(user)}</pre>}</Watch>
    </Form>
  );
}
```

当需要一次修改多个状态时，推荐使用 `form.batch(fn)`，它会在回调结束后统一触发一轮联动与组件重渲染；如果只是更新单个字段的值，也可以直接调用 `form.setValue('user.name', 'Grace')`。

## 常用 `$` 状态一览

| 状态 | 作用说明 |
|---|---|
| `$value` | 字段的值。`reaction` 写入 `$value` 的字段是计算字段：仍然可编辑、仍然提交、不计入 dirty。要预览再写 `readOnly`，不要提交再写 `omit` |
| `$visible` / `$disabled` / `$readOnly` / `$omit` | 四个独立布尔，详见下方 [四个布尔](#四个布尔) |
| `$required` / `$rules` | 控制必填与校验规则；由 `reaction` 写入的规则不受组件卸载影响 |
| `$enum` | 枚举选项（支持静态数组或 `EnumSource.with(params)`），优先级高于 JSX `enum` 与 `fields` 声明；赋 `undefined` 撤销 reaction 层覆盖，赋 `[]` 清空选项 |
| `$title` / `$description` | 字段标题与辅助说明（映射至 `FormItem` 的 `label` 与 `extra`） |
| `$component` / `$decorator` | 动态替换 `<Field>` 渲染的控件或装饰器 |
| `$componentProps` / `$decoratorProps` | 控件与装饰器的透传属性，支持按键打补丁，详见 [UI 状态三层叠加](/guide/field#ui-状态三层叠加) |
| `$errors` / `$warnings` / `$validating` / `$touched` | 只读状态，分别表示错误列表、警告列表、异步校验中状态及失焦触碰标记 |
| `$dirty` / `$edited` | 只读状态。`$dirty` 通过深比较判断当前值是否偏离初始值（改回原值即恢复 `false`；表单根上的 `d.$dirty` 不计入 `omit` 与计算字段；`visible: false` 仍计入）；`$edited` 记录用户是否手动编辑过，直到 `reset` 才重置 |
| `d.$canSubmit` / `d.$submitting` / `d.$submitCount` | 表单级只读状态，只能在根 draft `d` 上读取 |

## 四个布尔

字段状态是四个独立布尔（可交互演示见 [字段状态](/basics/state)）：

| 配置 | 界面 | 校验 | 提交 |
|---|---|---|---|
| 默认 | 渲染 | 校验 | 提交，计入 dirty |
| `visible: false` | 不渲染（仍注册） | 跳过，并清掉已有错误 | **仍然提交**，计入 dirty |
| `disabled: true` | 置灰、不可编辑 | 跳过，并清掉已有错误 | 提交 |
| `readOnly: true` | 渲染预览。和 `disabled` 同时为真时预览优先 | 跳过，并清掉已有错误 | 提交 |
| `omit: true` | 不影响渲染 | 不影响校验 | 剔除该字段。不计入 dirty |
| `reaction` 写过 `$value` | 仍可编辑（要预览就再写 `readOnly`） | 按上面三个开关 | 提交，除非 `omit` |

`visible` / `disabled` / `readOnly` 沿字段路径从根走到自己：这一层写了 `true` 或 `false` 就用这一层，没写就保持上一层。所以父级 `disabled: true`、子级 `disabled: false` 时，子级可以编辑。`omit` 不继承：父级 `omit` 不会把子级的 `$omit` 读成 `true`；删掉一个被 omit 的对象时，嵌套的键会跟着对象一起离开提交结果。

`$flag = undefined` 丢掉 reaction 这一层，回到 JSX / `fields` / 继承。详情页用 `useForm({ readOnly: true })`。

## 用 `fields` 预声明字段

在 `useForm({ fields })` 中声明的字段在表单创建时即已生效，即使对应的 `<Field>` 组件尚未挂载（例如位于未打开的标签页、折叠面板或虚拟列表视口之外），其校验规则和联动依然有效。你也可以把 `title`、`decorator`、`component` 等 UI 配置一并声明在 `fields` 中，JSX 里只需写 `<Field name="city" />` 即可渲染：

```tsx preview play=tabs
import { Field, Form, Watch, useForm, type Draft } from '@shikiform/react';
import { FormItem, Input, Select } from '@shikiform/antd';

type Values = { city: string; note: string; items: { name: string }[] };

export default function App() {
  const form = useForm<Values>({
    initialValues: { city: 'sh', note: '', items: [{ name: '' }, { name: '' }] },
    fields: {
      city: {
        title: '城市', decorator: [FormItem], component: [Select, { style: { width: 160 } }],
        enum: [{ label: '上海', value: 'sh' }, { label: '北京', value: 'bj' }],
      },
      note: { title: '备注', description: '声明在 fields 里的说明', decorator: [FormItem], component: [Input.TextArea] },
      // 行模板：作用于 items 的每一行（包括之后新增的行）
      'items.*.name': { required: true },
    },
  });
  return (
    <Form form={form}>
      <Field name="city" />
      <Field name="note" />
      <button type="button" onClick={() => { void form.validate().catch(() => {}) }}>校验（items 没有渲染）</button>
      <Watch select={(d: Draft<Values>) => d.items.$errors}>{(errors) => <small> 错误：{errors.join('；') || '无'}</small>}</Watch>
    </Form>
  );
}
```

配置中的 `'items.*.name'` 属于行模板规则，会自动应用到 `items` 现有的及后续新增的每一行上。

## 一次用户输入如何流转

当用户在页面上修改某个输入框时，数据会按以下顺序流过引擎：

1. 控件触发 `field.onChange(value)`，将新值写入表单引擎。
2. 引擎标记受影响的状态，并重新执行订阅了这些状态的 `reaction`；如果有下游依赖，会持续传递直到整个状态树收敛。来源发生变化的 `watch` 也会随后触发一次。
3. 订阅了相关字段路径的 React 组件收到通知并完成局部重渲染。
4. 按照触发时机（默认失焦或提交时，可配置为输入时）执行同步及异步校验。
5. 调用提交时，引擎会先等待尚未完成的异步规则并做最终校验，全部通过后去掉 `omit` 的字段（`visible: false` 的值仍在），将最终数据交给 `onSubmit` 回调。
