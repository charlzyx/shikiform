ShikiForm 将表单值、字段状态（显隐、禁用、只读、校验规则、错误提示、UI 属性）和联动逻辑放在一个独立于视图层的引擎中维护。React 组件与任意 UI 适配层都不持有自己的表单状态，仅按路径订阅引擎状态并映射为组件属性。

## 术语速览

| 术语 | 说明 |
|---|---|
| **表单实例** | `useForm` 或 `createForm` 返回的 `FormInstance`，持有表单值树与各路径的字段状态 |
| **draft** | `reaction`、`watch` 和 `form.batch` 回调的参数 `d`，用于追踪依赖与读写状态 |
| **handle** | draft 上的路径代理（如 `d.user.name`）；普通属性访问只定位路径，不读取值 |
| **`$` 状态** | handle 上以 `$` 开头的成员（如 `$value`、`$required`、`$visible`），用于读写具体状态 |
| **`decorator` / `component`** | `<Field>` 渲染的两层结构：`decorator`（如 `FormItem`）展示标签和错误，`component`（如 `Input`）负责输入 |
| **`reaction` / `watch`** | `reaction` 计算派生状态，初始化即运行并自动追踪依赖；`watch` 执行变化后的动作，首次不运行 |
| **`each`** | `reaction.each` 与 `watch.each` 接收 `(select, fn)` 两个参数，为数组每行建立独立实例并递归进入嵌套对象数组（跳过对象上的基本类型数组；直接对基本类型数组本身调用 `each` 时在 `depth === 0` 触发），可在回调内按 `ctx.key` / `ctx.depth` 过滤 |
| **四个布尔** | `visible`、`disabled`、`readOnly`、`omit`，均沿字段路径继承；`omit` 控制是否提交，父级为 `true` 时子级 `false` 不能单独提交 |

## handle 与 value 的区别

在 `reaction`、`watch` 或 `form.batch` 中，不带 `$` 的属性访问只定位字段路径，带 `$` 的成员才读写字段状态：

```ts
d.user.name.$value            // 读取字段值（在 reaction 中会自动登记为依赖）
d.user.name.$value = 'Ada'    // 更新该字段的值
d.user.name.$required = true  // 修改该字段的必填状态
d.items.$value                // 获取整个数组的值（d.items 本身只是路径句柄，不是数组）
```

实际使用时需要注意三点：
1. **在联动或批量写入中修改一个键**。在 `reaction`、`watch` 的动作回调或 `form.batch` 中，`d.user.$value.name = 'Ada'` 和 `d.user.name.$value = 'Ada'` 都写入 `user.name`。在外部用 `form.setValue('user.name', 'Ada')`。
2. **不要把 handle 当作数组操作**：诸如 `d.items.map`、`d.items.length` 或 `for…of d.items` 都是无效的。遍历行逻辑请用 [`reaction.each`](/guide/linkage)，读取整组数据请访问 `d.items.$value`。
3. **字段本身叫 `value` 或带 `$` 前缀时**：字段名是 `value` 时通过 `d.value.$value` 读写；如果数据对象上已存在非保留的 `$` 前缀自有键（例如业务字段 `$values`、`$id`），handle 会优先按字段路径解析（如 `d.$values.$value`），只有对象上不存在该键且拼写近似保留状态名（如 `$valeu`）时，才触发状态名拼写检查。

### 关于解构

**解构仅用于提前取出子字段的 handle，任何 `$` 状态都必须挂在 handle 上读写：**

```ts
const { name } = d.user // name 依然是指向 d.user.name 的 handle
name.$value = 'Ada'
```

在开发模式下，对象展开（`{ ...d.user }`）、rest 剩余属性、`Object.keys(d.user)` 以及数组解构（`const [first] = d.items`）都会触发 `ShikiUsageError`，错误信息中会提示改用 `d.items[0]` 或 `d.user.$value` 等正确写法。更多案例见 [常见的坑](/practices/pitfalls#解构-handle)。

```tsx preview
import { Field, Form, Watch, useField, useForm, type Draft } from '@shikiform/react';

type Values = { user: { name: string; email: string } };

function TextField() {
  const field = useField<string>();
  return (
    <div style={{ marginBottom: 8 }}>
      <label htmlFor={field.id} style={{ display: 'inline-block', width: 64 }}>
        {field.required && <span style={{ color: 'crimson' }}>* </span>}
        {field.title}
      </label>
      {field.readOnly ? (
        <span>{field.value || '-'}</span>
      ) : (
        <input id={field.id} value={field.value ?? ''} disabled={field.disabled}
          onChange={(e) => field.onChange(e.target.value)} onBlur={field.onBlur} />
      )}
    </div>
  );
}

export default function App() {
  const form = useForm<Values>({ initialValues: { user: { name: 'Ada', email: '' } } });
  return (
    <Form form={form}>
      <Field name="user.name" title="姓名" component={[TextField]} />
      <Field name="user.email" title="邮箱" component={[TextField]} />
      <div style={{ display: 'flex', gap: 8, flexWrap: 'wrap', marginTop: 8 }}>
        <button type="button" onClick={() => form.batch((d) => { d.user.name.$value = 'Grace'; })}>写 user.name</button>
        <button type="button" onClick={() => form.batch((d) => { d.user.email.$required = !d.user.email.$required; })}>切换邮箱必填</button>
        <button type="button" onClick={() => form.batch((d) => { d.user.email.$readOnly = !d.user.email.$readOnly; })}>切换阅读态</button>
      </div>
      <Watch select={(d: Draft<Values>) => d.user.$value}>{(user) => <pre>{JSON.stringify(user)}</pre>}</Watch>
    </Form>
  );
}
```

当需要一次修改多个状态时，推荐使用 `form.batch(fn)`，它会在回调结束后统一触发一轮联动与组件重渲染；如果只是更新单个字段的值，也可以直接调用 `form.setValue('user.name', 'Grace')`。

## 常用 `$` 状态一览

| 状态 | 作用说明 |
|---|---|
| `$value` | 字段的值。`reaction` 写入 `$value` 的字段是计算字段：仍然可编辑、仍然提交、不计入 dirty。要预览再写 `readOnly`，不要提交再写 `omit` |
| `$visible` / `$disabled` / `$readOnly` / `$omit` | 四个独立布尔，详见下方 [四个布尔](#四个布尔) |
| `$required` / `$rules` | 控制必填与校验规则；由 `reaction` 写入的规则不受组件卸载影响 |
| `$enum` | 枚举选项（支持静态数组或 `EnumSource.with(params)`），优先级高于 JSX `enum` 与 `fields` 声明；赋 `undefined` 撤销 reaction 层覆盖，赋 `[]` 清空选项 |
| `$title` / `$description` | 字段标题与辅助说明（映射至 `FormItem` 的 `label` 与 `extra`） |
| `$component` / `$decorator` | 动态替换 `<Field>` 渲染的控件或装饰器 |
| `$componentProps` / `$decoratorProps` | 控件与装饰器的透传属性，支持按键打补丁，详见 [UI 状态三层叠加](/guide/field#ui-状态三层叠加) |
| `$errors` / `$warnings` / `$validating` / `$touched` | 只读状态，分别表示错误列表、警告列表、异步校验中状态及失焦触碰标记 |
| `$dirty` / `$edited` | 只读状态。`$dirty` 通过深比较判断当前值是否偏离初始值（改回原值即恢复 `false`；表单根上的 `d.$dirty` 不计入 `omit`（含被祖先 omit 的子孙）与计算字段；`visible: false` 仍计入）。被 omit 的字段自身在没有更上层 omit 时仍可能为 `true`。`$edited` 记录用户是否手动编辑过，直到 `reset` 才重置 |
| `d.$canSubmit` / `d.$submitting` / `d.$submitCount` | 表单级只读状态，只能在根 draft `d` 上读取 |

## 四个布尔

字段状态是四个独立布尔（可交互演示见 [字段状态](/basics/state)）：

| 配置 | 界面 | 校验 | 提交 |
|---|---|---|---|
| 默认 | 渲染 | 校验 | 提交，计入 dirty |
| `visible: false` | 不渲染（仍注册） | 跳过，并清掉已有错误 | **仍然提交**，计入 dirty |
| `disabled: true` | 置灰、不可编辑 | 跳过，并清掉已有错误 | 提交 |
| `readOnly: true` | 渲染预览。和 `disabled` 同时为真时预览优先 | 跳过，并清掉已有错误 | 提交 |
| `omit: true` | 不影响渲染 | 不影响校验 | 剔除该字段及其子孙。表单级不计入 dirty |
| `reaction` 写过 `$value` | 仍可编辑（要预览就再写 `readOnly`） | 按上面三个开关 | 提交，除非 `omit` |

四个布尔都沿字段路径继承。`visible` / `disabled` / `readOnly` 从根走到自己：这一层写了 `true` 或 `false` 就用这一层，没写就保持上一层。所以父级 `disabled: true`、子级 `disabled: false` 时，子级可以编辑。`omit` 是任一祖先为 `true` 则子孙为 `true`（`$omit` 和 binding 上的 `omit` 都一样）。子级写 `omit: false` 不能把自己捞回来：提交时被 omit 的对象整棵删掉，嵌套的键跟着离开，子字段没有可以单独提交的值。父级 `omit` 取消后，子级回到自己的值（没写就是 `false`）。

被 omit 的祖先自己的 `$dirty` 仍按深比较计算，值变了时可以为 `true`，但表单级 `dirty` 不计这个字段及其子孙；子孙字段的 `$dirty` 则是 `false`。在根层设置 `d.$omit = true` 时，整表提交返回 `{}` 且表单级 `dirty` 为 `false`（显式调用 `form.validate(path)` 仍可校验并取回该路径的值）。

`$flag = undefined` 丢掉 reaction 这一层，回到 JSX / `fields` / 继承。详情页用 `useForm({ readOnly: true })`。

## 用 `fields` 预声明字段

在 `useForm({ fields })` 中声明的字段在表单创建时即已生效，即使对应的 `<Field>` 组件尚未挂载（例如位于未打开的标签页、折叠面板或虚拟列表视口之外），其校验规则和联动依然有效。你也可以把 `title`、`decorator`、`component` 等 UI 配置一并声明在 `fields` 中，JSX 里只需写 `<Field name="city" />` 即可渲染：

```tsx preview play=tabs
import type { ReactNode } from 'react';
import { Field, Form, Watch, useField, useFieldDecorator, useForm, type Draft } from '@shikiform/react';

type Values = { city: string; note: string; items: { name: string }[] };

function FieldItem({ children }: { children?: ReactNode }) {
  const d = useFieldDecorator();
  return (
    <div style={{ marginBottom: 8 }}>
      <label {...d.labelProps} style={{ display: 'inline-block', width: 56 }}>{d.label}</label>
      {children}
      {d.descriptionProps && <small {...d.descriptionProps} style={{ marginLeft: 8, opacity: 0.7 }}>{d.description}</small>}
    </div>
  );
}

function SelectInput() {
  const field = useField<string>();
  return (
    <select id={field.id} value={field.value ?? ''} onChange={(e) => field.onChange(e.target.value)}>
      {field.options.map((o) => <option key={String(o.value)} value={String(o.value)}>{o.label}</option>)}
    </select>
  );
}

function TextArea() {
  const field = useField<string>();
  return <textarea id={field.id} rows={2} value={field.value ?? ''} onChange={(e) => field.onChange(e.target.value)} onBlur={field.onBlur} />;
}

export default function App() {
  const form = useForm<Values>({
    initialValues: { city: 'sh', note: '', items: [{ name: '' }, { name: '' }] },
    fields: {
      city: {
        title: '城市', decorator: [FieldItem], component: [SelectInput],
        enum: [{ label: '上海', value: 'sh' }, { label: '北京', value: 'bj' }],
      },
      note: { title: '备注', description: '声明在 fields 里的说明', decorator: [FieldItem], component: [TextArea] },
      // 行模板：作用于 items 的每一行（包括之后新增的行）
      'items.*.name': { required: true },
    },
  });
  return (
    <Form form={form}>
      <Field name="city" />
      <Field name="note" />
      <button type="button" onClick={() => { void form.validate().catch(() => {}) }}>校验（items 没有渲染）</button>
      <Watch select={(d: Draft<Values>) => d.items.$errors}>{(errors) => <small> 错误：{errors.join('；') || '无'}</small>}</Watch>
    </Form>
  );
}
```

配置中的 `'items.*.name'` 属于行模板规则，会自动应用到 `items` 现有的及后续新增的每一行上。按钮上的 `void` 只表示这次不使用返回值：`form.validate()` 通过时仍 resolve 去掉 `omit` 后的提交值，失败 reject `FieldError[]`，错误从 `d.items.$errors` 读。

## 一次用户输入如何流转

输入框变更后的执行顺序：

1. 控件调用 `field.onChange(value)` 将新值写入引擎。
2. 引擎标记脏状态，重跑依赖这些状态的 `reaction` 直至收敛；监听源发生变化的 `watch` 随后执行一次。
3. 订阅了变更路径的 React 组件收到通知并局部重渲染。
4. 按 `validateTrigger`（默认 `onBlur` 与 `onSubmit`，可加入 `onChange`）执行同步与异步校验。
5. 提交时等待在途异步规则并执行全表校验，通过后剔除 `omit` 字段（`visible: false` 的值仍保留），将结果传给 `onSubmit`。
