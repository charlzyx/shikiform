从安装到一张会校验、会提交的表单。字段只有一种写法：`<Field>`，装饰器包住控件。

## 准备

这四个包还没有发布到 npm。在仓库里执行 `npm run release` 只做 `npm publish --dry-run`。

### 从 npm 安装

发布到 npm 之后，用下面任一命令。`@shikiform/react` 会带上引擎 `@shikiform/core`。

```bash
npm i @shikiform/react
pnpm add @shikiform/react
yarn add @shikiform/react
```

用 Ant Design 时，在 `@shikiform/react` 之外再装 `@shikiform/antd`。`Form`、`useForm`、`typed` 从 `@shikiform/react` 引入，`@shikiform/antd` 不重新导出它们。pnpm 只允许 import 写在依赖里的包，所以两个都要装。

```bash
npm i @shikiform/react @shikiform/antd
pnpm add @shikiform/react @shikiform/antd
yarn add @shikiform/react @shikiform/antd
```

查询列表、影子表单再把 `@shikiform/hooks` 加进同一条命令。只要引擎、不要 React 时单独装 `@shikiform/core`。

| peer 依赖 | 版本 | 哪些包 |
|---|---|---|
| `react` / `react-dom` | `^18 \|\| ^19` | `@shikiform/react`、`@shikiform/hooks`、`@shikiform/antd` |
| `antd` / `dayjs` | `^5.18` / `^1` | 只有 `@shikiform/antd`（`FormLayout layout="vertical"` 需要 antd 5.18 起的 `Form.Item layout`） |

### 本地 tarball

包还不在 npm 上时，在 shikiform 仓库根目录先构建再打包。每个包的 `files` 只有 `dist/`，不构建就没有可运行的文件。`@shikiform/react` 依赖 `@shikiform/core@0.1.0`（版本以该包的 `package.json` 为准）。这个版本不在注册表里，只打包或只安装 react 会 404。core 和 react 都要打包，并在同一次安装里装上。

```bash
npm ci
npm run build:lib
npm pack -w @shikiform/core --pack-destination packages/core
npm pack -w @shikiform/react --pack-destination packages/react
```

tarball 在包目录下。文件名是包名去掉 `@`、把 `/` 换成 `-`，再加上版本：`packages/core/shikiform-core-0.1.0.tgz`、`packages/react/shikiform-react-0.1.0.tgz`。

下面假定项目和 shikiform 仓库是同级目录。路径按实际位置改。

npm 可以在命令行一次装上两个 tarball：

```bash
npm i ../shikiform/packages/core/shikiform-core-0.1.0.tgz ../shikiform/packages/react/shikiform-react-0.1.0.tgz
```

写进 `package.json` 再安装，是同一件事。pnpm 和 Yarn 不能靠「同一次装上两个 tarball」对上依赖：它们仍按 `@shikiform/core@0.1.0` 去注册表查找。pnpm 用 `pnpm.overrides` 指回 core 的 tarball，Yarn 1 用 `resolutions`。Yarn 1 不自动安装 peer，把 `react` 和 `react-dom` 写进 `dependencies`。

```json
{
  "dependencies": {
    "@shikiform/core": "file:../shikiform/packages/core/shikiform-core-0.1.0.tgz",
    "@shikiform/react": "file:../shikiform/packages/react/shikiform-react-0.1.0.tgz",
    "react": "^19.0.0",
    "react-dom": "^19.0.0"
  },
  "pnpm": {
    "overrides": {
      "@shikiform/core": "file:../shikiform/packages/core/shikiform-core-0.1.0.tgz"
    }
  },
  "resolutions": {
    "@shikiform/core": "file:../shikiform/packages/core/shikiform-core-0.1.0.tgz"
  }
}
```

然后 `npm i`、`pnpm install` 或 `yarn install`。`npm` 会忽略 `pnpm` 和 `resolutions`。

要用 `@shikiform/antd`，四个包都打包（antd 依赖 core、react、hooks）。在仓库根目录：

```bash
npm pack -w @shikiform/core --pack-destination packages/core
npm pack -w @shikiform/react --pack-destination packages/react
npm pack -w @shikiform/hooks --pack-destination packages/hooks
npm pack -w @shikiform/antd --pack-destination packages/antd
```

在项目里一次装上：

```bash
npm i ../shikiform/packages/core/shikiform-core-0.1.0.tgz ../shikiform/packages/react/shikiform-react-0.1.0.tgz ../shikiform/packages/hooks/shikiform-hooks-0.1.0.tgz ../shikiform/packages/antd/shikiform-antd-0.1.0.tgz
```

`dependencies` 里为每个 tarball 写一条 `file:`，并加上 peer `antd`（`^5.18.0`）和 `dayjs`（`^1`）。`pnpm.overrides` 与 `resolutions` 里为 `@shikiform/core`、`@shikiform/react`、`@shikiform/hooks` 各写一条，指向同一个 tarball。Yarn 1 安装这组依赖时，antd 的间接依赖 `scroll-into-view-if-needed@3.2.0` 要求 Node `>=26`。Node 更低时改跑 `yarn install --ignore-engines`。只要 `@shikiform/hooks`、不要 antd 时，打包并安装 core、react、hooks 三个 tarball 即可。

### workspace

先在 shikiform 仓库执行上面的 `npm ci` 和 `npm run build:lib`。把仓库放进 workspace（目录名按克隆来）。

pnpm：根目录 `.npmrc` 写 `link-workspace-packages=true`，`pnpm-workspace.yaml`：

```yaml
packages:
  - 'app'
  - 'shikiform/packages/*'
```

应用的依赖写 `"@shikiform/react": "workspace:*"`。`.npmrc` 里的 `link-workspace-packages=true` 让 pnpm 把 `@shikiform/core@0.1.0` 接到 workspace 里的 core。用 antd 时再加 `"@shikiform/antd": "workspace:*"`。

Yarn 4（Berry）用同一套目录。根 `package.json` 的 `workspaces` 包含 `app` 和 `shikiform/packages/*`，应用里同样是 `"@shikiform/react": "workspace:*"`。`.yarnrc.yml`：

```yaml
nodeLinker: node-modules
```

Yarn 4 默认的 PnP 下，Node 直接 import 找不到这些包。Yarn 1 没有 `workspace:*`，用上面的 tarball 和 `resolutions`。

## 第一张表单

`useForm` 创建引擎，`<Form>` 把它交给字段并渲染原生 `<form>`。`<Field>` 拥有一个路径：`decorator={[FormItem]}` 显示标签、星号和错误，`component={[Input]}` 是 connect 过的 antd 控件，二者都从字段上下文读字段，不再写 `name`。`typed(form)` 返回同一组组件，只是 `name` 按表单值类型检查。

```tsx preview
import { useState } from 'react';
import { Form, typed, useForm } from '@shikiform/react';
import { FormButtonGroup, FormItem, FormLayout, Input, InputNumber, Reset, Submit } from '@shikiform/antd';

type Values = { name: string; email: string; age: number | null };

export default function App() {
  const [result, setResult] = useState('还没有提交');
  const form = useForm<Values>({ initialValues: { name: '', email: '', age: 18 } });
  const F = typed(form);
  return (
    <Form form={form} onSubmit={(values) => setResult(JSON.stringify(values))}>
      <FormLayout labelCol={{ span: 4 }} wrapperCol={{ span: 20 }}>
        <F.Field name="name" title="姓名" required decorator={[FormItem]} component={[Input, { placeholder: 'Ada' }]} />
        <F.Field name="email" title="邮箱" required rules={{ format: 'email', message: '邮箱格式不对' }}
          decorator={[FormItem]} component={[Input]} />
        <F.Field name="age" title="年龄" rules={{ min: 0, max: 150 }} decorator={[FormItem]} component={[InputNumber]} />
        <FormButtonGroup.FormItem>
          <Submit>提交</Submit>
          <Reset />
        </FormButtonGroup.FormItem>
      </FormLayout>
      <pre aria-live="polite">{result}</pre>
    </Form>
  );
}
```

直接点提交，必填项报错；失焦时也会校验。全部通过后 `onSubmit` 才收到值。

- `title`、`required`、`rules` 写在 `Field` 上；`component` / `decorator` 的第二项是传给控件 / 装饰器的属性。
- `<Submit>` 在已经有错误、或正在提交时不可点（`$canSubmit` 为 false）。还没校验过的空必填项不挡住它，第一次点击仍会跑校验。`<Reset>` 回到初始值。
- `FormButtonGroup.FormItem` 让按钮跟随 `FormLayout` 对齐到控件列，不用再写一遍偏移。
- `<Form>` 自己就是 `<form>`，不要再套一层。组件外创建引擎用 `createForm`，选项和 `useForm` 相同。

## 不用 antd

自己的输入组件用不带参数的 `useField()` 读当前字段，放进 `component`（或作为 `<Field>` 的子元素）。完整的一页在 [不用 UI 库](/start/native)。

```tsx preview
import { useState } from 'react';
import { Field, Form, useField, useForm } from '@shikiform/react';

function TextInput({ label }: { label: string }) {
  const field = useField<string>();
  return (
    <p>
      <label htmlFor={field.id}>{label} </label>
      <input id={field.id} value={field.value ?? ''} onChange={(event) => field.onChange(event.target.value)} onBlur={field.onBlur} />
      {field.errors[0] && <small role="alert" style={{ color: 'crimson' }}> {field.errors[0]}</small>}
    </p>
  );
}

export default function App() {
  const [result, setResult] = useState('还没有提交');
  const form = useForm({ initialValues: { username: '' } });
  return (
    <Form form={form} onSubmit={(values) => setResult(JSON.stringify(values))}>
      <Field name="username" required component={[TextInput, { label: '姓名' }]} />
      <button type="submit">提交</button>
      <pre aria-live="polite">{result}</pre>
    </Form>
  );
}
```

不带参数的 `useField()` 必须写在 `<Field>` 的 `component` / `decorator` / 子元素里，否则抛错并提示修法。输入组件自己把 `value` / `onChange` / `onBlur` 接到控件上；要套用同一套映射，用 [`connect`](/reference/antd-adapter#connect)（从 `@shikiform/react` 导入，不必装 antd）。标签、错误和提交按钮见 [接自己的组件库](/guide/headless#接自己的组件库)。

## 复用一段字段

片段就是普通组件：名字相对外层 `<ObjectField>` / 行作用域解析，`typed<Address>()` 按片段自己的值类型检查。

```tsx preview
import { Form, ObjectField, typed, useForm } from '@shikiform/react';
import { FormItem, Input } from '@shikiform/antd';

type Address = { city: string; street: string };
const A = typed<Address>();

function AddressFields() {
  return (
    <>
      <A.Field name="city" title="城市" decorator={[FormItem]} component={[Input]} />
      <A.Field name="street" title="街道" decorator={[FormItem]} component={[Input]} />
    </>
  );
}

export default function App() {
  const form = useForm({ initialValues: { home: { city: '杭州', street: '' }, office: { city: '上海', street: '' } } });
  return (
    <Form form={form}>
      <ObjectField name="home"><AddressFields /></ObjectField>
      <ObjectField name="office"><AddressFields /></ObjectField>
    </Form>
  );
}
```

装饰器和控件的四种写法、UI 属性分层见 [Field、装饰器与组件](/guide/field)。只要绑定、不要组件时用 `useField`，见 [Headless Hooks](/guide/headless)。
