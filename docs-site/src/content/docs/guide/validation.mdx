## 规则配置

字段的 `rules` 接受单条内置规则、实现 [Standard Schema](https://standardschema.dev) 的校验器（Zod、Valibot、ArkType），或它们的数组：

| 内置规则 | 说明 |
|---|---|
| `required` | 必填校验，空值报错（也可以直接在 `<Field>` 上写 `required` 属性） |
| `min` / `max` | 数值上下限校验（含边界值）；配置了 `min` 或 `max` 时，`NaN` 会触发范围错误 |
| `minLength` / `maxLength` | 字符串长度限制 |
| `pattern` | 正则表达式匹配；带 `g` / `y` 标志的正则每次都从索引 `0` 匹配，并保留调用方正则的 `lastIndex` |
| `format: 'email' \| 'url'` | 内置格式校验 |
| `isTrue` | 值必须为 `true`（常用于勾选同意协议） |
| `validator(value, ctx)` | 自定义校验函数（同步与异步采用同一运行时返回值契约）：非空字符串或字符串数组 `string[]` → 错误文案；`false` → 失败并使用规则 `message` 或默认 `fallback` 文案；`true` / `null` / `undefined` / `''` → 通过；返回其它值时开发环境抛 `ShikiUsageError`，生产环境按失败处理并使用默认文案。`ctx.record` 在路径含数组下标时是最后一个下标对应的那一行，否则是包住该字段的对象；`parent` 跳过数组层的上级对象；另有 `root`、`get(path)` 与 `signal`（读到的是本轮校验开始时的快照）。函数抛错或 reject 时，异常的 `message` 会作为报错文案 |
| `message` | 自定义该条规则的错误提示文案 |
| `level: 'warning'` | 设为警告级别：提示信息写入 `$warnings` / `field.warnings` 并以警告色展示，但**不会阻止提交**，也不会影响 `canSubmit`（异步警告可在提交完成后发布；显式调用 `form.validate()` 仍等待警告结果），适合「密码强度偏弱」等软提醒 |

与 Ant Design 和 Formily 一致，ShikiForm 的内置规则中，空值（`''`、`null`、`undefined`）统一只由 `required` 判定；`minLength`、`pattern`、`min`、`format` 等规则遇到空值会直接放行。这样既能保证选填项留空时不报错，也能避免必填项在留空时同时冒出多条错误。对于 Zod 等外部 Schema，空值是否放行取决于 Schema 自身定义（例如 `z.string().min(3)` 会拦截空串，若字段可留空需写 `.optional()` 或 `.or(z.literal(''))`）。

```tsx preview play=schema
import { useState, type ReactNode } from 'react';
import { z } from 'zod';
import { Checkbox, CheckboxIndicator } from '@ui-sdk/react/checkbox';
import { Field, Form, Watch, useField, useFieldDecorator, useForm, type Draft } from '@shikiform/react';

type Values = { username: string; email: string; password: string; confirm: string; agree: boolean };
const TAKEN = ['admin', 'root'];

function FieldItem({ children }: { children?: ReactNode }) {
  const d = useFieldDecorator();
  return (
    <div style={{ marginBottom: 8 }}>
      {d.label && (
        <label {...d.labelProps} style={{ display: 'inline-block', width: 72 }}>
          {d.required && <span style={{ color: 'crimson' }}>* </span>}
          {d.label}
        </label>
      )}
      {children}
      {d.errorProps && <small {...d.errorProps} style={{ color: 'crimson', marginLeft: 8 }}>{d.errors[0]}</small>}
      {!d.errorProps && d.warningProps && <small {...d.warningProps} style={{ color: '#b45309', marginLeft: 8 }}>{d.warnings[0]}</small>}
    </div>
  );
}

function TextInput({ type = 'text' }: { type?: string }) {
  const field = useField<string>();
  return (
    <input id={field.id} type={type} value={field.value ?? ''}
      onChange={(e) => field.onChange(e.target.value)} onBlur={field.onBlur} />
  );
}

function AgreeCheckbox({ children }: { children?: ReactNode }) {
  const field = useField<boolean>();
  return (
    <label style={{ display: 'inline-flex', alignItems: 'center', gap: 6, cursor: 'pointer' }}>
      <Checkbox id={field.id} checked={Boolean(field.value)} onCheckedChange={(checked) => field.onChange(checked === true)}>
        <CheckboxIndicator>✓</CheckboxIndicator>
      </Checkbox>
      {children}
    </label>
  );
}

export default function App() {
  const [result, setResult] = useState('');
  const form = useForm<Values>({
    initialValues: { username: '', email: '', password: '', confirm: '', agree: false },
    fields: {
      username: { asyncDebounceMs: 300 }, // 停止输入 300ms 后才跑异步规则
      confirm: { omit: true }, // 参与校验，不进提交结果
    },
    // 跨字段：返回 path → 文案
    validate: (values) => (values.confirm && values.confirm !== values.password ? { confirm: '两次密码不一致' } : undefined),
  });
  return (
    <Form form={form} onSubmit={(values) => setResult(JSON.stringify(values))}>
      <Field name="username" title="用户名" required decorator={[FieldItem]} component={[TextInput]}
        rules={[
          { minLength: 3, message: '至少 3 个字符' },
          { validator: (value, { signal }) => new Promise<string | null>((resolve) => {
            const timer = setTimeout(() => resolve(TAKEN.includes(String(value)) ? '用户名已被占用' : null), 400);
            signal?.addEventListener('abort', () => clearTimeout(timer));
          }) },
        ]} />
      <Field name="email" title="邮箱" required rules={z.string().email('邮箱格式不对').or(z.literal(''))} decorator={[FieldItem]} component={[TextInput]} />
      <Field name="password" title="密码" required decorator={[FieldItem]} component={[TextInput, { type: 'password' }]}
        rules={[
          { minLength: 6, message: '至少 6 位' },
          // 警告：提示但不挡提交
          { validator: (value) => (/\d/.test(String(value)) && /[a-z]/i.test(String(value)) ? null : '建议同时包含字母和数字'), level: 'warning' },
        ]} />
      <Field name="confirm" title="确认密码" required decorator={[FieldItem]} component={[TextInput, { type: 'password' }]} />
      <Field name="agree" rules={{ isTrue: true, message: '请先同意条款' }} decorator={[FieldItem]}>
        <AgreeCheckbox>我已阅读并同意条款</AgreeCheckbox>
      </Field>
      <Watch select={(d: Draft<Values>) => d.$submitting}>
        {(submitting) => <button type="submit" disabled={submitting}>{submitting ? '提交中…' : '注册'}</button>}
      </Watch>
      <pre aria-live="polite">{result}</pre>
    </Form>
  );
}
```

尝试只输入纯数字密码时，字段会展示黄色警告提示，但依然可以正常提交；在用户名中输入 `admin`，异步校验会在停顿 300ms 后发起，如果在这期间继续输入，引擎会通过 `signal` 中止前一次请求并丢弃过期结果，被中止的请求也不会阻塞后续提交。

除了字段级规则，你还可以直接给 `useForm({ validate: z.object({ … }) })` 传入整表 Schema，报错路径（如 `['items', 0, 'name']`）会自动映射到对应的字段（`items.0.name`）；若将 Schema 写在具体字段的 `rules` 上，报错路径则会相对于该字段解析。表单级校验与字段 Schema 错误（含在途异步返回）会跟随存活的行或树节点迁移，行或节点被删除或替换时自动丢弃。

## 校验时机与竞态处理

- 默认在失焦（`onBlur`）和提交（`onSubmit`）时触发校验，可通过 `validateTrigger: ['onChange', 'onBlur', 'onSubmit']` 调整。已报错的字段在后续每次值变更时都会立即重验，合法后即时消除错误。
- `await form.validate()` 校验全表，传入路径前缀（如 `form.validate('items')`）或路径数组则只校验对应范围（运行时统一规范化方括号与点号路径）。通过时 resolve 调用结束时的当前值：无 path 是 `getSubmitValues()`（`TSubmit`，根层 `$omit: true` 时为 `{}`）；一个 path 是该处的值（`PathValue`；path 自身即使 `omit` 或处于根层 `omit` 下也仍校验并返回，只因它而被 omit 的子孙仍在，子孙自己的 `omit` 才去掉）；路径数组是只含这些 path 的嵌套对象（`ValidatePick`）。这份值是副本：普通对象、数组、`Date`、`Map`、`Set` 会复制，类实例、函数和 React 元素仍是原来的引用，原地修改不会写回表单。规则读的是开跑时的快照；这段时间里值又变了，`validate()` 不会重跑。失败时 reject `FieldError[]`（`{ path, messages }[]`）；表单级 `validate` 抛错原样 reject。局部 `validate(path)` / `validate(paths)` 在途期间若受检行移动，校验失败时按受检行的当前坐标 reject，全部通过时按调用传入的路径读取当前值返回；跨父移出的带键树节点仍属于原局部校验范围。
- `submit()` 会等待在途异步规则完成后再做最终判定（不等待异步 `warning` 规则）。若校验期间表单值变化，或 `enumPolicy: 'error'` 下影响校验的**启用选项值集合**发生变化（仅重排顺序或修改 `label` 不触发重试），引擎会重跑校验（最多 3 轮），通过后 resolve 的是刚校验过的那份提交值。新的 `submit()` 会立即拒绝仍在等待校验的旧调用（reject `SubmitSupersededError`），只有最新一次触发 `onValid`；已经进入 `onValid` 的调用继续计入 `submitting`。防止重复点击可根据 `$submitting` 禁用按钮。
- 局部 `reset(path)` 只取消该子树范围内排队的防抖校验，并只使范围相交的在途校验失效（无关子树的 `reset` 不会中断或跳过表单级校验）；全表 `reset` 前发起的表单级校验仍会向原调用返回判定，但不再把旧结果写回重置后的表单状态；等待异步 `warning` 期间若发生 `reset`，有键行的原调用判定映射到恢复后的坐标，无法匹配的克隆匿名行错误丢弃；被 `reset` 中止的校验视为无结论，即使重置到相同值，下一次 `submit()` 也会重跑校验。整体替换父对象时，仅重跑值确实变化且有待处理校验的子字段。
- 在 `reaction` / `batch` 中写 `$rules` 时需传入规则对象数组（清空用 `[]`）；传入非数组或非规则对象时，开发环境抛 `ShikiUsageError`，生产环境忽略该次写入并保留原有规则。

```ts
const values = await form.validate()
const user = await form.validate('user')
const picked = await form.validate(['name', 'user.city'])
```

## 提交返回值处理

`form.submit()` 通过时 resolve，失败时 reject：

| 结果 | 说明 |
|---|---|
| resolve 提交值 | 校验通过。没传 `onValid`，或它返回 `undefined` |
| resolve `onValid` 的返回值 | `await onValid(values)` 得到了非 `undefined` 的值 |
| reject `FieldError[]` | 校验未通过，`onValid` 不会被调用 |
| reject 原错误 | `onValid` 或表单级 `validate` 自己抛出的异常 |
| reject `SubmitSupersededError` | 被后一次 `submit()` 取代（`code: 'superseded'`，`message` 为 `messages.superseded`） |
| reject `SubmitUnstableError` | 值连续 3 轮未稳定，不是被取代（`code: 'unstable'`，`message` 同样为 `messages.superseded`）。`<Form>` / `<Submit>` 把它交给 `onSubmitError` |

```ts
try {
  const values = await form.submit(async (draft) => {
    await api.save(draft)
  })
  form.setInitialValues(form.values)
} catch (error) {
  if (isFieldErrors(error)) console.log(error[0]?.path)
}
```

对于 `<Form>` 的提交类型推断：不传泛型（`useForm({ fields })`）或使用 `typed<Values>().useForm({ fields })` 时，在 `fields` 中声明了 `omit: true` 或 `visible: false, omit: true` 的路径会自动推导为可选字段；如果直接写 `useForm<Values>({ fields })`，提交类型则固定为 `Values`；对于只在 JSX 或 `reaction` 里动态 `omit` 的字段，可以通过第二个泛型参数 `SubmitValues<Values, 'confirm'>` 手动剔除。`useForm()` 不传参或传 `undefined` 等价于传入 `{}`。

`<Form>` 支持通过属性直接绑定这几个回调（`<Submit onSubmit>` 也支持相同用法）：

```tsx
<Form
  form={form}
  id="profile"
  onSubmit={save}                                   // 校验通过后执行，支持 async 函数
  onInvalid={(errors) => scrollToField(errors[0].path)}
  onSubmitError={(error) => message.error(String(error))}  // 处理 save 抛出的异常，不传时默认 console.error
>
  …
</Form>
<button type="submit" form="profile">保存</button>   {/* 其余原生属性会透传至 <form> */}
```

## 内置文案与国际化

内置校验提示、引擎错误信息以及 `<Submit>` / `<Reset>` 等组件的默认文案均为简体中文。你可以通过 `messages` 按需覆盖单张表单的文案，或用 `setDefaultMessages` 全局修改：

```ts
import { createForm, enUS, setDefaultMessages } from '@shikiform/react'

createForm({ messages: enUS })                       // 单张表单切换为英文
createForm({
  messages: {
    required: 'Required',
    minLength: ({ minLength }) => `At least ${minLength} characters`,  // 函数形式可接收上下文参数
    enum: ({ value }) => `${value} is not an option`,
  },
})
setDefaultMessages(enUS)                              // 全局默认配置，通常在应用入口调用一次
```

| 文案 key | 使用场景 | 回调参数（默认均含 `path`、`value`） |
|---|---|---|
| `required` / `isTrue` / `email` / `url` / `pattern` | 对应内置校验规则 | `pattern` 额外提供 `pattern` |
| `minLength` / `maxLength` | 字符串长度校验 | `minLength` / `maxLength`、`length` |
| `min` / `max` | 数值范围校验 | `min` / `max` |
| `enum` | `enumPolicy: 'error'` 且值不在 `$enum` 选项中时 | `options` |
| `fallback` | `validator` 抛出的错误缺少 `message`，或 schema issue 文案为空时 | `error` |
| `superseded` | `SubmitSupersededError` 与 `SubmitUnstableError` 的 `message` | — |
| `treeIntoSelf` / `treeSourceMissing` / `treeTargetMissing` / `treeEmptyPos` | 树句柄 `move` 被拒绝时的原因说明 | `from`、`to`（不含 `path` 与 `value`） |
| `submit` / `reset` / `search` / `refresh` / `expand` / `collapse` | `Submit` / `Reset` 及 `QueryList` 等按钮文案 | — |
| `optional` | `requiredMark: 'optional'` 时非必填项标签后缀（默认 `（可选）`） | — |
| `add` / `remove` / `removeConfirm` / `moveUp` / `moveDown` / `copy` / `dragSort` | `ArrayItems`、`ArrayCards`、`ArrayTable` 行操作按钮文案（`copy` 仅用于 `ArrayTable`） | — |
| `selectionCount` / `selectionClear` / `selectionAll` / `selectionInvert` / `density` / `columnSettings` | `ArrayTable` 多选栏、表格密度与列设置 | `selectionCount` 含 `count`；`density` 含 `density` |
| `edit` / `ok` / `cancel` | 草稿表单触发按钮及抽屉底部按钮 | — |
| `yes` / `no` / `empty` | `PreviewText.*` 阅读态组件的布尔值与空值占位符（`empty` 默认为 `-`） | — |

文案覆盖优先级从高到低为：规则自身的 `message` > 组件自身的属性（如 `title`、`okText`） > 表单 `messages` > `setDefaultMessages` > 内置中文（`zhCN`）。`QueryList` 会读取 `table.form` 的 `messages` 配置。在自定义组件中，用 `form.message('submit')`（或 `useFormContext().message('submit')`）读取当前表单的文案。

## 服务端错误

当提交接口返回业务校验错误（例如「用户名已存在」）时，可以调用 `form.setErrors` 将错误挂载回指定字段：

```ts
await form.submit(async (values) => {
  const res = await api.register(values)
  if (res.status === 409) form.setErrors({ username: '用户名已存在' })
  // 也支持一次传入多个字段及表单根错误（键为 ''）：
  // form.setErrors({ email: ['格式不对'], '': '服务器繁忙' })
})
```

`setErrors` 接收 `{ path: 文案 | 文案[] }` 或 `FieldError[]`，传入 `null` 或空数组可清除单条错误。挂载后的服务端错误会与规则错误一同显示，并使 `canSubmit` 变为 `false`；只要对应字段（或其祖先/子孙字段）的值发生变更、触发重新校验，或调用 `reset()` / `clearErrors(path?)`，服务端错误会自动清除。在 `batch` / `watch` 内调用 `setErrors` / `clearErrors` 时，按调用顺序和当时工作树坐标定位字段（移行后命中当前位于该坐标的行），内层 `batch` 抛错时回滚；批内读取 `form.errors` / `$errors` 仍返回已提交状态，批结束时统一落地。

## 规则写在哪决定「卸载后是否还校验」

ShikiForm 支持在三个地方定义校验规则，它们在 `<Field>` 卸载后的生命周期各不相同：

| 规则定义位置 | `<Field>` 卸载后是否继续校验 |
|---|---|
| JSX 属性：`<Field rules required>` 或 `useField(name, { rules })` | 不再校验（随组件卸载自动释放） |
| 引擎配置：`useForm({ fields })`、`registerField`、行模板 `items.*.name` | 依然校验 |
| 联动规则：`reaction` 中的 `$rules` / `$required` | 依然校验，且优先级最高 |

如果需要在切换标签页、收起折叠面板或虚拟滚动列表场景下依然校验隐藏起来的字段，请将业务规则写在 `fields` 或 `reaction` 中；仅与当前界面渲染强相关的临时校验才适合写在 JSX 上。

校验只在 `visible && !disabled && !readOnly` 时运行，否则清掉已有错误。计算字段不会因此跳过校验。门重新打开后不会自动重跑，要等下一次 blur、`validate` 或 `submit`。完整对照见 [四个布尔](/guide/concepts#四个布尔)。

### 练一练：未挂载字段的校验

下方练习中，关闭「填写更多」后昵称与邀请码都会从 DOM 卸载，此时点击提交不会报错。按下面两步修改：

1. 在 `defineEffects` 中写入 `d.code.$rules = [{ required: true, message: '邀请码必填' }]`，并将 `effects` 传给 `useForm`；
2. 去掉邀请码 `<Field>` 上的 `rules` 属性，保留昵称的 JSX 规则。

再次关闭开关并提交：邀请码虽然未挂载仍会拦截提交，而昵称的 JSX 规则已随卸载释放。点击 **看答案** 可对照参考写法。
