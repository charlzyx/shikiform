---
title: 命名 UI：同一字段多控件与无数据 UI
description: 为同一个字段挂载多个独立控件（如输入框 + 滑块/回显），或在表单中通过 reaction 控制提示横幅与分组框等无数据节点。
---

以下两类需求适合使用命名 UI 节点，而非普通 `<Field>`：

- 同一字段挂载多个独立控件：例如输入框旁加一个字数超限时变红的回显，或预算金额同时绑定数字框和滑块且只禁用滑块。若直接渲染两个不带 `ui` 的 `<Field name="amount">`，两者会共用同一份 `$componentProps`、`$disabled`、`$readOnly` 并生成重复的 DOM `id`；开发环境会在重复挂载时输出一次告警，提示给第二个 `<Field>` 加上 `ui` 名称。
- 不绑定数据的 UI 节点：例如「报销金额 ≥ 50000 需主管审批」的提示条，或包裹一组字段的卡片容器。这类节点随表单状态显隐或改属性，但不进入表单值和校验。

两种节点的写法与联动入口：

| 界面写法 | 联动访问方式 | 含义 |
|---|---|---|
| `<Field name="x" ui="echo" component={[Echo]} />` | `d.x.$ui('echo')` | 字段 `x` 的附加 UI 实例：共享值、错误和校验规则，但拥有独立的 UI 状态 |
| `<UI name="tip" component={[Alert, props]} />` | `d.$ui('tip')` | 无数据的纯 UI 节点（在数组行或 `<ObjectField>` 内可通过作用域句柄 `row.$ui('tip')` 访问） |

命名 UI 节点只有界面状态（`$visible`、`$disabled`、`$readOnly`、`$title`、`$description`、`$componentProps`、`$decoratorProps`），优先级同样是 `reaction > JSX > 默认继承值`。在 `reaction` 中读取它们时也会自动订阅变化；整体赋值 `$componentProps` / `$decoratorProps` 时只接受普通对象或 `undefined`（开发环境抛 `ShikiUsageError`，生产环境忽略）。

## 同一字段的独立 UI 实例

```tsx preview
import type { CSSProperties } from 'react';
import { defineEffects, Form, typed, useField, useForm } from '@shikiform/react';
import { FieldInput, FormItem, siteKit } from '@site/ui';

type Values = { nickname: string };

// 显示组件从无参 useField() 拿值：在 <Field ui> 里它是共享的字段 + 这个实例的 UI 状态
function Echo({ style }: { style?: CSSProperties }) {
  const field = useField<string>();
  return <span id={field.id} data-echo="" className="sf-ui-readonly" style={style}>{field.value || '（空）'}</span>;
}

export default function App() {
  const form = useForm<Values>({
    initialValues: { nickname: '' },
    effects: [
      defineEffects<Values>(({ reaction }) => {
        reaction((d) => {
          d.nickname.$ui('echo').$componentProps.style =
            d.nickname.$value.length > 8 ? { color: 'red' } : undefined;
        });
      }),
    ],
  });
  const F = typed(form);
  return (
    <Form form={form} kit={siteKit} id="echo" data-ui-echo-demo="" style={{ maxWidth: 420 }}>
      <F.Field name="nickname" title="昵称" decorator={[FormItem, { layout: 'horizontal' }]} component={[FieldInput, { placeholder: '超过 8 个字回显变红' }]} />
      <F.Field name="nickname" ui="echo" title="回显" decorator={[FormItem, { layout: 'horizontal' }]} component={Echo} />
    </Form>
  );
}
```

- 在这个例子中，主输入框的 DOM `id` 为 `echo-nickname`，回显节点的 `id` 自动生成为 `echo-nickname--echo`，两者的 `label` 互不冲突（若 `<Form>` 未传 `id`，React 18+ 会自动用 `useId()` 生成水合安全的唯一前缀；React 16.8 / 17 的 SSR 应用请显式传入 `<Form id="…">` 以避免水合不一致）。
- `$componentProps` 和 `$decoratorProps` 仅作用于当前实例本身；而 `title` 和 `description` 若未单独指定，则会自动回退继承主字段的标题与说明。
- 不带 `ui` 属性的主 `<Field>` 依然对应字段自身（通过 `d.nickname.$componentProps` 控制）。

## 共享数据但独立控制交互形态

```tsx preview
import { defineEffects, Form, typed, useForm } from '@shikiform/react';
import { FieldNumber, FieldSlider, FieldSwitch, FormItem, siteKit } from '@site/ui';

type Values = { budget: number; locked: boolean };

export default function App() {
  const form = useForm<Values>({
    initialValues: { budget: 30, locked: false },
    effects: [
      defineEffects<Values>(({ reaction }) => {
        reaction((d) => {
          d.budget.$ui('slider').$disabled = d.locked.$value ? true : undefined;
        });
      }),
    ],
  });
  const F = typed(form);
  return (
    <Form form={form} kit={siteKit} data-ui-slider-demo="" style={{ maxWidth: 420 }}>
      <F.Field name="locked" title="锁定滑块" decorator={[FormItem, { layout: 'horizontal' }]} component={FieldSwitch} />
      <F.Field name="budget" title="预算" required decorator={[FormItem, { layout: 'horizontal' }]} component={[FieldNumber, { min: 0, max: 100 }]} />
      <F.Field name="budget" ui="slider" title="滑块调节" decorator={[FormItem, { layout: 'horizontal' }]} component={[FieldSlider, { min: 0, max: 100 }]} />
    </Form>
  );
}
```

- 数字输入框与滑块共享同一份值和校验状态，拖动滑块或输入数字都会实时同步。
- `$ui('slider').$disabled = undefined` 丢掉这一层，滑块回到主字段的 `disabled`（整表 `readOnly` 时滑块也跟着预览）。
- `rules`、`required`、`enum` 和 `omit` 写在不带 `ui` 的主 `<Field>` 上。

## 无数据的提示节点：`<UI>`

```tsx preview
import { useState } from 'react';
import { defineEffects, Form, Submit, typed, UI, useField, useForm } from '@shikiform/react';
import { Alert, Button, Input, siteKit } from '@site/ui';

type Values = { amount: number | null };

function AmountInput() {
  const field = useField<number | null>();
  return (
    <Input
      id={field.id}
      type="number"
      prefix="¥"
      placeholder="输入 50000 以上试试"
      value={field.value ?? ''}
      onChange={(e) => field.onChange(e.target.value === '' ? null : Number(e.target.value))}
      onBlur={field.onBlur}
    />
  );
}

export default function App() {
  const form = useForm<Values>({
    initialValues: { amount: null },
    effects: [
      defineEffects<Values>(({ reaction }) => {
        reaction((d) => {
          d.$ui('approvalTip').$visible = (d.amount.$value ?? 0) >= 50000;
        });
      }),
    ],
  });
  const F = typed(form);
  const [saved, setSaved] = useState<Values>();
  return (
    <Form form={form} kit={siteKit} onSubmit={setSaved} data-ui-alert-demo="" style={{ maxWidth: 420 }}>
      <F.Field name="amount" title="报销金额" component={AmountInput} />
      <UI name="approvalTip" component={[Alert, { variant: 'warning', children: '金额 ≥ 50000，提交后需要主管审批' }]} />
      <div><Submit asChild><Button variant="primary">提交</Button></Submit></div>
      {saved && <pre>{JSON.stringify(saved)}</pre>}
    </Form>
  );
}
```

`<UI>` 节点不会出现在表单值或校验列表中，但同样支持通过 `decorator`、`title`、`description` 融入表单排版，并允许在 `reaction` 中动态更新 `$componentProps.message` 等属性。它也支持传入子元素或 render prop `(ui) => …`。

## 隐藏 `<UI>` 不会自动隐藏内部字段

用 `<UI>` 包裹一组字段只是视觉上的分组。隐藏 `<UI>` 只会让这层容器从页面上卸载，不会改动里面字段的数据状态：字段要不要校验看它自己（或父字段）的 `$visible`，提不提交看它自己（或父字段）的 `$omit`。因为 `<UI>` 不在数据路径里，只藏起 `<UI>` 并不会把里面的字段从提交结果里去掉。

```tsx preview
import { useState } from 'react';
import { defineEffects, Form, Submit, typed, UI, useForm } from '@shikiform/react';
import { Button, Card, FieldInput, FieldSwitch, siteKit } from '@site/ui';

type Values = { needInvoice: boolean; invoiceTitle: string; remark: string };

export default function App() {
  const form = useForm<Values>({
    initialValues: { needInvoice: false, invoiceTitle: '', remark: '保留' },
    effects: [
      defineEffects<Values>(({ reaction }) => {
        reaction((d) => {
          const need = d.needInvoice.$value;
          d.$ui('invoiceBox').$visible = need;   // 只控制卡片 UI 是否渲染
          d.invoiceTitle.$visible = need;        // 隐藏并跳过校验；visible=false 仍会提交
          d.invoiceTitle.$omit = !need;          // 不需要发票时，从提交结果里去掉抬头
        });
      }),
    ],
  });
  const F = typed(form);
  const [saved, setSaved] = useState<Values>();
  return (
    <Form form={form} kit={siteKit} onSubmit={setSaved} data-ui-box-demo="" style={{ maxWidth: 420 }}>
      <F.Field name="needInvoice" title="开发票" component={FieldSwitch} />
      <UI name="invoiceBox" component={[Card, { title: '发票信息', padding: 'sm' }]}>
        <div style={{ display: 'grid', gap: 12 }}>
          <F.Field name="invoiceTitle" title="抬头" required component={FieldInput} />
          <F.Field name="remark" title="备注" component={FieldInput} />
        </div>
      </UI>
      <div><Submit asChild><Button variant="primary">提交</Button></Submit></div>
      {saved && <pre>{JSON.stringify(saved)}</pre>}
    </Form>
  );
}
```

在这个示例里，关闭「开发票」后提交：`invoiceTitle` 同时设了 `$visible = false` 和 `$omit = true`，所以不渲染、不校验，也不会出现在提交结果中。`remark` 没有改这两个开关，卡片被隐藏后提交 JSON 里依然包含 `"remark": "保留"`。`$visible = false` 本身仍会提交。这两个字段都在根上，没有共同的对象父级，所以要各自设置 `$omit`。如果它们在同一个对象里，给这个对象设置 `$omit` 即可：子字段读到的 `$omit` 也是 `true`，写 `omit: false` 不能单独提交。

## 回退规则一览

| UI 状态 | 未显式赋值时（无 reaction / JSX）的默认值 |
|---|---|
| `$visible` / `$disabled` / `$readOnly` | 没写时，字段附加实例回退到主字段的有效值；`<UI>` 回退到所在作用域（根部 `visible` 默认 true）。显式 `false` 退出 |
| `$title` / `$description` | 字段附加实例回退到主字段的标题与说明；`<UI>` 默认为空 |
| `$componentProps` / `$decoratorProps` | 仅取当前节点自身的 JSX 与 `reaction` 配置，不从主字段继承 |

另外，附加实例的显隐优先于主字段。`d.x.$visible = false; d.x.$ui('summary').$visible = true` 可以藏起主输入、留下摘要。字段自己的 `$visible = false` 会跳过校验，值仍然提交。

## 为 UI 名称启用类型检查

`ui`、`<UI name>` 与 `$ui()` 默认接受任意字符串。若 `reaction` 写入了一个从未挂载的 UI 名称，开发环境下会在首次挂载稳定后输出警告并列出该路径下已挂载的名称。

需要在编译期校验 UI 名称拼写时，可通过模块扩展声明 `UiNames`：

```ts
// src/shikiform.d.ts
import '@shikiform/core'
declare module '@shikiform/core' {
  interface UiNames { echo: true; slider: true; approvalTip: true }
}
```

声明后，`ui="ecko"` 或 `d.$ui('aprovalTip')` 会在编译期报错。
