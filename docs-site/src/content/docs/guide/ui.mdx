---
title: 命名 UI：同一字段多控件与无数据 UI
description: 为同一个字段挂载多个独立控件（如输入框 + 滑块/回显），或在表单中通过 reaction 控制提示横幅与分组框等无数据节点。
---

在日常表单开发中，有两类界面需求很难直接通过普通 `<Field>` 优雅表达：

- **同一字段对应多个控件**：例如在输入框旁放一个实时回显，超过一定字数时仅让回显变红；或者让预算金额同时绑定数字框和滑块，锁定开关开启时只禁用滑块。如果直接写两个 `<Field name="amount">`，两者会共享同一份 `$componentProps`、`$disabled` 和 `$readOnly`，不仅无法单独控制，还会产生重复的 `id`。
- **不绑定数据的纯 UI 节点**：例如「报销金额 ≥ 5 万需要主管审批」的提示横幅，或者一个用来包裹分组的卡片容器。它们需要跟随表单值变化动态显隐或修改属性，但不应该进入提交结果或参与校验。

ShikiForm 通过「命名 UI 节点」来解决这两类场景：

| 界面写法 | 联动访问方式 | 含义 |
|---|---|---|
| `<Field name="x" ui="echo" component={[Echo]} />` | `d.x.$ui('echo')` | 字段 `x` 的附加 UI 实例：共享值、错误和校验规则，但拥有独立的 UI 状态 |
| `<UI name="tip" component={[Alert, props]} />` | `d.$ui('tip')` | 无数据的纯 UI 节点（在数组行或 `<ObjectField>` 内可通过作用域句柄 `row.$ui('tip')` 访问） |

命名 UI 节点只有界面状态（`$visible`、`$disabled`、`$readOnly`、`$title`、`$description`、`$componentProps`、`$decoratorProps`），优先级是 `reaction > JSX > 回退值`。在 `reaction` 中读取它们时也会收集依赖。

## 同一字段的独立 UI 实例

```tsx preview
import type { CSSProperties } from 'react';
import { defineEffects, Form, typed, useField, useForm } from '@shikiform/react';
import { FormItem, FormLayout, Input } from '@shikiform/antd';

type Values = { nickname: string };

// 显示组件从无参 useField() 拿值：在 <Field ui> 里它是共享的字段 + 这个实例的 UI 状态
function Echo({ style }: { style?: CSSProperties }) {
  const field = useField<string>();
  return <span id={field.id} data-echo="" style={style}>{field.value || '（空）'}</span>;
}

export default function App() {
  const form = useForm<Values>({
    initialValues: { nickname: '' },
    effects: [
      defineEffects<Values>(({ reaction }) => {
        reaction((d) => {
          d.nickname.$ui('echo').$componentProps.style =
            d.nickname.$value.length > 8 ? { color: 'red' } : undefined;
        });
      }),
    ],
  });
  const F = typed(form);
  return (
    <Form form={form} id="echo" data-ui-echo-demo="">
      <FormLayout labelCol={{ span: 4 }} wrapperCol={{ span: 16 }}>
        <F.Field name="nickname" title="昵称" decorator={[FormItem]} component={[Input, { placeholder: '超过 8 个字回显变红' }]} />
        <F.Field name="nickname" ui="echo" title="回显" decorator={[FormItem]} component={[Echo]} />
      </FormLayout>
    </Form>
  );
}
```

- 在这个例子中，主输入框的 DOM `id` 为 `echo-nickname`，回显节点的 `id` 自动生成为 `echo-nickname--echo`，两者的 `label` 互不冲突（若 `<Form>` 未传 `id`，引擎会自动使用 React `useId()` 生成唯一前缀以隔离同页面多张表单）。
- `$componentProps` 和 `$decoratorProps` 仅作用于当前实例本身；而 `title` 和 `description` 若未单独指定，则会自动回退继承主字段的标题与说明。
- 不带 `ui` 属性的主 `<Field>` 依然对应字段自身（通过 `d.nickname.$componentProps` 控制）。

## 共享数据但独立控制交互形态

```tsx preview
import { defineEffects, Form, typed, useForm } from '@shikiform/react';
import { FormItem, FormLayout, InputNumber, Slider, Switch } from '@shikiform/antd';

type Values = { budget: number; locked: boolean };

export default function App() {
  const form = useForm<Values>({
    initialValues: { budget: 30, locked: false },
    effects: [
      defineEffects<Values>(({ reaction }) => {
        reaction((d) => {
          d.budget.$ui('slider').$disabled = d.locked.$value ? true : undefined;
        });
      }),
    ],
  });
  const F = typed(form);
  return (
    <Form form={form} data-ui-slider-demo="">
      <FormLayout labelCol={{ span: 4 }} wrapperCol={{ span: 16 }}>
        <F.Field name="locked" title="锁定滑块" decorator={[FormItem]} component={[Switch]} />
        <F.Field name="budget" title="预算" required decorator={[FormItem]} component={[InputNumber, { min: 0, max: 100 }]} />
        <F.Field name="budget" ui="slider" decorator={[FormItem, { label: ' ', colon: false }]} component={[Slider]} />
      </FormLayout>
    </Form>
  );
}
```

- 数字输入框与滑块共享同一份值和校验状态，拖动滑块或输入数字都会实时同步。
- `$ui('slider').$disabled = undefined` 丢掉这一层，滑块回到主字段的 `disabled`（整表 `readOnly` 时滑块也跟着预览）。
- `rules`、`required`、`enum` 和 `omit` 写在不带 `ui` 的主 `<Field>` 上。

## 无数据的提示节点：`<UI>`

```tsx preview
import { Alert } from 'antd';
import { useState } from 'react';
import { defineEffects, Form, typed, UI, useForm } from '@shikiform/react';
import { FormButtonGroup, FormItem, FormLayout, InputNumber, Submit } from '@shikiform/antd';

type Values = { amount: number | null };

export default function App() {
  const form = useForm<Values>({
    initialValues: { amount: null },
    effects: [
      defineEffects<Values>(({ reaction }) => {
        reaction((d) => {
          d.$ui('approvalTip').$visible = (d.amount.$value ?? 0) >= 50000;
        });
      }),
    ],
  });
  const F = typed(form);
  const [saved, setSaved] = useState<Values>();
  return (
    <Form form={form} onSubmit={setSaved} data-ui-alert-demo="">
      <FormLayout labelCol={{ span: 4 }} wrapperCol={{ span: 16 }}>
        <F.Field name="amount" title="报销金额" decorator={[FormItem]} component={[InputNumber, { style: { width: 200 } }]} />
        <UI name="approvalTip" decorator={[FormItem, { label: ' ', colon: false }]}
          component={[Alert, { type: 'warning', showIcon: true, message: '金额 ≥ 50000，提交后需要主管审批' }]} />
        <FormButtonGroup.FormItem>
          <Submit />
        </FormButtonGroup.FormItem>
      </FormLayout>
      {saved && <pre>{JSON.stringify(saved)}</pre>}
    </Form>
  );
}
```

`<UI>` 节点不会出现在表单值或校验列表中，但同样支持通过 `decorator`、`title`、`description` 融入表单排版，并允许在 `reaction` 中动态更新 `$componentProps.message` 等属性。它也支持传入子元素或 render prop `(ui) => …`。

## 隐藏 `<UI>` 不会自动隐藏内部字段

用 `<UI>` 包裹一组字段作为视觉分组时，把 `<UI>` 隐藏仅仅是卸载了这层容器界面；里面的字段是否渲染、是否校验看它自己的 `$visible`，是否提交看它自己的 `$omit`。

```tsx preview
import { Card } from 'antd';
import { useState } from 'react';
import { defineEffects, Form, typed, UI, useForm } from '@shikiform/react';
import { FormButtonGroup, FormItem, FormLayout, Input, Submit, Switch } from '@shikiform/antd';

type Values = { needInvoice: boolean; invoiceTitle: string; remark: string };

export default function App() {
  const form = useForm<Values>({
    initialValues: { needInvoice: false, invoiceTitle: '', remark: '保留' },
    effects: [
      defineEffects<Values>(({ reaction }) => {
        reaction((d) => {
          const need = d.needInvoice.$value;
          d.$ui('invoiceBox').$visible = need;   // 只控制卡片 UI 是否渲染
          d.invoiceTitle.$visible = need;        // 隐藏并跳过校验；visible=false 仍会提交
          d.invoiceTitle.$omit = !need;          // 不需要发票时，从提交结果里去掉抬头
        });
      }),
    ],
  });
  const F = typed(form);
  const [saved, setSaved] = useState<Values>();
  return (
    <Form form={form} onSubmit={setSaved} data-ui-box-demo="">
      <FormLayout labelCol={{ span: 4 }} wrapperCol={{ span: 16 }}>
        <F.Field name="needInvoice" title="开发票" decorator={[FormItem]} component={[Switch]} />
        <UI name="invoiceBox" component={[Card, { size: 'small', title: '发票信息', style: { marginBottom: 16 } }]}>
          <F.Field name="invoiceTitle" title="抬头" required decorator={[FormItem]} component={[Input]} />
          <F.Field name="remark" title="备注" decorator={[FormItem]} component={[Input]} />
        </UI>
        <FormButtonGroup.FormItem>
          <Submit />
        </FormButtonGroup.FormItem>
      </FormLayout>
      {saved && <pre>{JSON.stringify(saved)}</pre>}
    </Form>
  );
}
```

在这个示例里，关闭「开发票」后提交：`invoiceTitle` 同时设了 `$visible = false` 和 `$omit = true`，所以不渲染、不校验，也不会出现在提交结果中。`remark` 没有改这两个开关，卡片被隐藏后提交 JSON 里依然包含 `"remark": "保留"`。`$visible = false` 本身仍会提交；要整组数据都不提交，需要给里面的字段各自设置 `$omit`。

## 回退规则一览

| UI 状态 | 未显式赋值时（无 reaction / JSX）的默认值 |
|---|---|
| `$visible` / `$disabled` / `$readOnly` | 没写时，字段附加实例回退到主字段的有效值；`<UI>` 回退到所在作用域（根部 `visible` 默认 true）。显式 `false` 退出 |
| `$title` / `$description` | 字段附加实例回退到主字段的标题与说明；`<UI>` 默认为空 |
| `$componentProps` / `$decoratorProps` | 仅取当前节点自身的 JSX 与 `reaction` 配置，不从主字段继承 |

另外，附加实例的显隐优先于主字段。`d.x.$visible = false; d.x.$ui('summary').$visible = true` 可以藏起主输入、留下摘要。字段自己的 `$visible = false` 会跳过校验，值仍然提交。

## 为 UI 名称启用类型检查

默认情况下，`ui`、`<UI name>` 和 `$ui()` 接受任意字符串；如果在 `reaction` 中写入了一个从未挂载的 UI 名称，开发环境下会在渲染稳定后发出警告并列出当前路径下已挂载的名称。

如果希望在编译期就拦截拼写错误，可以在全局类型声明中扩展 `UiNames` 接口：

```ts
// src/shikiform.d.ts
import '@shikiform/core'
declare module '@shikiform/core' {
  interface UiNames { echo: true; slider: true; approvalTip: true }
}
```

声明完成后，像 `ui="ecko"` 或 `d.$ui('aprovalTip')` 这样的拼写错误会直接触发 TypeScript 编译报错。
