---

在 ShikiForm 中，`<Field>` 是单个表单项的唯一入口。它会绑定数据路径并渲染两层结构：外层的 `decorator` 负责展示标签、必填星号和校验报错，内层的 `component` 负责实际的数据输入。由于 `<Field>` 会把当前字段上下文向下传递，因此 `FormItem` 和接入后的控件都可以直接读取字段状态，无需再次传入 `name`。

```tsx
<Field
  name="email"              // 相对当前作用域（ObjectField / 数组行 / 树节点）
  title="邮箱"               // 装饰器标签（FormItem → label）
  description="用于登录"      // 装饰器说明（FormItem → extra）
  required rules={{ format: 'email' }}
  decorator={[FormItem, { tooltip: '工作邮箱' }]}
  component={[Input, { placeholder: 'name@example.com' }]}
/>
```

| 属性 | 说明 |
|---|---|
| `name` | 字段路径，相对于外层的 `<ObjectField>` 或数组行解析 |
| `rules` / `required` | 挂载期校验规则，组件卸载时自动移除；持久化规则请写在 `fields` 或 `reaction` 中，详见 [规则写在哪](/guide/validation#规则写在哪) |
| `enum` | 静态选项（如 `[{ label, value }]`、`['a', 'b']`）或异步数据源 `SomeEnum.with(params)`，详见 [选项写在 JSX 里](#选项写在-jsx-里) |
| `display` / `pattern` | 组件层声明的显隐（`visible` / `hidden` / `virtual` / `none`）和交互模式；若 `reaction` 中也写了对应状态，则以 `reaction` 为准 |
| `title` / `description` | 传递给装饰器的标题与补充说明 |
| `decorator` / `component` | 接收组件本身或 `[Component, props]` 元组。元组中的 `props` 会与组件的完整属性类型进行严格校验；使用 `FieldKit` 注册后，也可以直接传注册名字符串（如 `"Input"` 或 `["Input", props]`），见 [登记一次](/guide/headless#登记一次) |
| `children` | 直接传入控件元素（如 `<Input />`）或 render prop `(field) => …`，用来替代 `component` |

当 `display` 为 `hidden` 或 `none` 时，`<Field>` 会跳过渲染并返回 `null`；处于 `virtual` 时仍正常渲染。显隐状态对校验与提交的影响见 [显隐、pattern 与提交](/guide/concepts#显隐pattern-与提交)。

## 四种常用写法

```tsx preview
import { Input as AntInput } from 'antd';
import { Field, Form, useForm } from '@shikiform/react';
import { FormItem, FormLayout, Input } from '@shikiform/antd';

export default function App() {
  const form = useForm({ initialValues: { a: '元组', b: '子元素', c: 'render prop', d: '无装饰器' } });
  return (
    <Form form={form}>
      <FormLayout labelCol={{ span: 6 }} wrapperCol={{ span: 18 }}>
        {/* 1. 槽位：最常用 */}
        <Field name="a" title="decorator + component" decorator={[FormItem]} component={[Input, { allowClear: true }]} />
        {/* 2. 子元素：控件从上下文读字段 */}
        <Field name="b" title="children 元素" decorator={[FormItem]}>
          <Input addonBefore="@" />
        </Field>
        {/* 3. render prop：完全自己接线（这里用原生 antd Input） */}
        <Field name="c" title="render prop" decorator={[FormItem]}>
          {(field) => <AntInput id={field.id} value={field.value} onChange={(event) => field.onChange(event.target.value)} onBlur={field.onBlur} />}
        </Field>
        {/* 4. 不要装饰器：表格单元格常用 */}
        <Field name="d" component={[Input]} />
      </FormLayout>
    </Form>
  );
}
```

当使用 `component={[MyInput, { placeholder: '…' }]}` 时，引擎会把合并后的 `componentProps` 直接作为 props 传给 `MyInput`（`decoratorProps` 同理）。注意这包属性中不包含 `value` 和 `onChange`，字段的数据绑定依然通过 `connect` 或在组件内调用 `useField()` 完成。

## UI 状态三层叠加

字段的 `title`、`description`、`componentProps` 和 `decoratorProps` 支持三个配置层级，优先级从低到高依次为：

1. 创建表单时传入的 `fields` 声明；
2. JSX 中 `<Field>` 上的属性及元组里的 `props`；
3. 联动函数 `reaction` 中写入的 `$title`、`$componentProps` 等状态。

其中 `componentProps` 和 `decoratorProps` 采用对象深合并策略：普通对象会递归合并各自的键，而数组、函数、React 元素或类实例则整体取最高层级的值。因此，如果需要根据其他字段动态调整控件属性，应当写在 `reaction` 中，而不是在 JSX 渲染期间计算后传入：

```tsx preview
import { Field, Form, defineEffects, useForm } from '@shikiform/react';
import { FormItem, FormLayout, Input, Switch } from '@shikiform/antd';

type Values = { vip: boolean; code: string };

const effects = defineEffects<Values>(({ reaction }) => {
  reaction((d) => {
    const vip = d.vip.$value;
    d.code.$title = vip ? '会员码' : '邀请码';
    d.code.$componentProps.placeholder = vip ? 'VIP-0000' : '选填';
    d.code.$componentProps.disabled = !vip;
    d.code.$decoratorProps.tooltip = vip ? '会员必填' : undefined;
    d.code.$required = vip;
  });
});

export default function App() {
  const form = useForm<Values>({ initialValues: { vip: false, code: '' }, effects: [effects] });
  return (
    <Form form={form}>
      <FormLayout labelCol={{ span: 5 }} wrapperCol={{ span: 19 }}>
        <Field name="vip" title="会员" decorator={[FormItem]} component={[Switch]} />
        {/* JSX 的 allowClear 保留：reaction 只覆盖它写到的键 */}
        <Field name="code" title="（被 reaction 覆盖）" decorator={[FormItem]} component={[Input, { allowClear: true }]} />
      </FormLayout>
    </Form>
  );
}
```

在 `reaction` 中操作 `$componentProps` / `$decoratorProps` 时，不同写法的合并效果如下：

| 写法 | 合并效果 |
|---|---|
| `d.x.$componentProps.placeholder = '…'` | 仅覆盖 `placeholder`，其余来自下层的属性继续保留 |
| `d.x.$componentProps.style.color = 'red'` | 仅补充 `style.color`，保留下层 `style` 中的其他样式；由于中间层对象不会自动初始化，需先写 `style ??= {}` |
| `d.x.$componentProps.style ??= {}` | 初始化一个空补丁层，不会清空下层已有的 `style` |
| `d.x.$componentProps.style = { color: 'red' }` | 整键替换：下层的 `style` 不再生效 |
| `delete d.x.$componentProps.style` | 移除该键，下层的 `style` 同样不再生效 |
| `d.x.$componentProps = { … }` | 整体替换掉整个对象，`fields` 和 JSX 两层的 props 全部失效 |
| `d.x.$componentProps = undefined` | 撤销 `reaction` 这一层的覆盖，恢复下层属性 |

在 `reaction` 内部读取 `$componentProps` 时，只能读到「`fields` 声明 + `reaction`」两层合并后的结果，JSX 层属性仅在渲染阶段合并。在所有 `$` 状态中，只有 UI 状态支持在同一轮次内读回刚刚写入的值。

## 选项写在 JSX 里

下拉框、单选框、多选框组等选择类字段，可以直接在 `<Field>` 上通过 `enum` 传入选项数据，无需提前在 `fields` 中声明。适配后的 `Select`、`Radio`、`Checkbox.Group` 会自动将其作为 `options`，阅读态下也会自动将其反显为对应的标签文案。

```tsx preview
import { Switch } from 'antd';
import { Form, typed, useForm } from '@shikiform/react';
import { Checkbox, FormItem, FormLayout, Radio, Select } from '@shikiform/antd';

type Values = { level: 'gold' | 'silver'; tags: string[]; size: number };

export default function App() {
  const form = useForm<Values>({ initialValues: { level: 'gold', tags: ['math'], size: 2 } });
  const F = typed(form);
  return (
    <Form form={form}>
      <FormLayout labelCol={{ span: 5 }} wrapperCol={{ span: 19 }}>
        <FormItem label="阅读态">
          <Switch onChange={(on) => form.batch((d) => { d.$pattern = on ? 'readPretty' : undefined; })} />
        </FormItem>
        {/* value 按字段类型检查：写 'bronze' 编译不过 */}
        <F.Field name="level" title="等级" enum={[{ label: '黄金', value: 'gold' }, { label: '白银', value: 'silver' }]}
          decorator={[FormItem]} component={[Select, { style: { width: 160 } }]} />
        {/* 数组字段按元素类型检查 */}
        <F.Field name="tags" title="兴趣" enum={[{ label: '数学', value: 'math' }, { label: '诗歌', value: 'poetry' }]}
          decorator={[FormItem]} component={[Checkbox.Group]} />
        {/* 原始值：标签就是 String(value) */}
        <F.Field name="size" title="尺码" enum={[1, 2, 3]} decorator={[FormItem]} component={[Radio]} />
      </FormLayout>
    </Form>
  );
}
```

关于 JSX `enum` 的使用细节：
- **覆盖优先级**：`reaction` 中的 `$enum` > JSX `enum` > `fields.x.enum` > 行模板（`rows.*.x`）。JSX 传入的选项仅在组件挂载期间生效，卸载或改为 `undefined` 后会自动回退到声明层。
- **撤销与清空**：在 `reaction` 中设置 `$enum = undefined` 会撤掉联动层的选项并回退到下层（同时中止未完成的异步枚举加载并复位 `loading`）；如果要彻底清空选项，请赋值 `$enum = []`。
- **变动更新策略**：引擎会对 JSX `enum` 做深比较，因此每次渲染传入新的数组字面量不会引起无效重置；选项变更后按 `enumPolicy` 处理（如 `'clear'` 会自动清掉不再合法的旧值，首次挂载则保持原值）。
- **异步数据源**：可直接传入 `enum={Cities.with(province)}`；但如果选项依赖其他字段变化，推荐写在 `reaction` 中（`d.city.$enum = …`）。
- **类型校验**：配合 `typed(form)` 或 `row.Field` 使用时，选项中的 `value` 类型会与字段值类型（数组字段为其元素类型）进行严格比对。

## Field 与底层 Hooks 的对应关系

`<Field>` 本质上是对 `useField(name, options)` 的一层轻量封装：当字段 `display` 为 `hidden` 或 `none` 时返回 `null`（`virtual` 状态正常渲染），其余情况依次渲染 `decorator` 和 `component`。

如果你不希望通过 `<Field>` 包裹，可以直接调用 `useField(name)` 并使用 `mapFormItemProps(field, props)` 和 `mapFieldProps(field, props)` 计算对应的属性；而在自定义控件或装饰器内部，调用无参数的 `useField()` 即可拿到当前字段的绑定对象。完整签名请参考 [useField](/reference/react-hooks#usefield) 和 [Ant Design 适配层](/reference/antd-adapter)。

## 字段名的类型检查

普通的 `<Field>` 通过 React 上下文获取表单实例，无法静态得知表单值的类型结构，因此 `name` 默认接受任意字符串（这也保留了动态路径的灵活性）。如果希望在编译期捕获字段名拼写错误，使用 `typed(form)` 获取强类型版本即可：

```tsx
const F = typed(form)
<F.Field name="email" decorator={[FormItem]} component={[Input]} />   // name="emial" 会触发 TS 编译错误
<F.ArrayField name="items">{(row) => <row.Field name="name" component={[Input]} />}</F.ArrayField>
```

生成的组件依然遵守相对路径作用域规则，`row.Field` 会自动按单行数据类型进行字段名检查。详见 [typed](/reference/react-hooks#typed)。
