---

`<Field>` 绑定一条数据路径并渲染两层结构：外层 `decorator` 展示标签、必填标记和错误信息，内层 `component` 处理输入交互。`<Field>` 通过上下文向下传递字段绑定，`FormItem` 与已适配控件直接从中读取状态，无需再传 `name`。

```tsx
<Field
  name="email"              // 相对当前作用域（ObjectField / 数组行 / 树节点）
  title="邮箱"               // 装饰器标签（FormItem → label）
  description="用于登录"      // 装饰器说明（FormItem → extra）
  required rules={{ format: 'email' }}
  decorator={[FormItem, { tooltip: '工作邮箱' }]}
  component={[Input, { placeholder: 'name@example.com' }]}
/>
```

| 属性 | 说明 |
|---|---|
| `name` | 字段路径，相对于外层的 `<ObjectField>` 或数组行解析 |
| `rules` / `required` | 挂载期校验规则，组件卸载时自动移除；持久化规则请写在 `fields` 或 `reaction` 中，详见 [规则写在哪决定「卸载后是否还校验」](/guide/validation#规则写在哪决定卸载后是否还校验) |
| `enum` | 静态选项（如 `[{ label, value }]`、`['a', 'b']`）或异步数据源 `SomeEnum.with(params)`，详见 [选项写在 JSX 里](#选项写在-jsx-里) |
| `visible` / `disabled` / `readOnly` / `omit` | 四个布尔。`reaction` 写入的同名 `$` 状态优先于 JSX |
| `title` / `description` | 传递给装饰器的标题与补充说明 |
| `decorator` / `component` | 接收组件本身或 `[Component, props]` 元组。元组中的 `props` 会与组件的完整属性类型进行严格校验；使用 `FieldKit` 注册后，也可以直接传注册名字符串（如 `"Input"` 或 `["Input", props]`），见 [登记一次](/guide/headless#登记一次) |
| `children` | 直接传入控件元素（如 `<Input />`）或 render prop `(field) => …`，用来替代 `component` |

`visible` 为 false 时，`<Field>` 返回 `null`。`omit` 不影响渲染。校验与提交见 [四个布尔](/guide/concepts#四个布尔)。

## 四种常用写法

```tsx preview
import { Field, Form, useForm } from '@shikiform/react';
import { FieldInput, FormItem, Input } from '@site/ui';

export default function App() {
  const form = useForm({ initialValues: { a: '元组', b: '子元素', c: 'render prop', d: '无装饰器' } });
  return (
    <Form form={form} style={{ maxWidth: 420 }}>
      {/* 1. 槽位：最常用 */}
      <Field name="a" title="decorator + component" decorator={[FormItem]} component={[FieldInput, { placeholder: '输入内容' }]} />
      {/* 2. 子元素：控件从上下文读字段 */}
      <Field name="b" title="children 元素" decorator={[FormItem]}>
        <FieldInput prefix="@" />
      </Field>
      {/* 3. render prop：完全自己接线 */}
      <Field name="c" title="render prop" decorator={[FormItem]}>
        {(field) => (
          <Input
            id={field.id}
            value={field.value}
            onChange={(event) => field.onChange(event.target.value)}
            onBlur={field.onBlur}
          />
        )}
      </Field>
      {/* 4. 不要装饰器：表格单元格常用 */}
      <Field name="d" component={[FieldInput]} />
    </Form>
  );
}
```

当使用 `component={[MyInput, { placeholder: '…' }]}` 时，引擎会把合并后的 `componentProps` 直接作为 props 传给 `MyInput`（`decoratorProps` 同理）。注意这包属性中不包含 `value` 和 `onChange`，字段的数据绑定依然通过 `connect` 或在组件内调用 `useField()` 完成。

## UI 状态三层叠加

字段的 `title`、`description`、`componentProps` 和 `decoratorProps` 支持三个配置层级，优先级从低到高依次为：

1. 创建表单时传入的 `fields` 声明；
2. JSX 中 `<Field>` 上的属性及元组里的 `props`；
3. 联动函数 `reaction` 中写入的 `$title`、`$componentProps` 等状态。

其中 `componentProps` 和 `decoratorProps` 会按属性名逐层合并：普通对象合并各自的键，数组、函数、React 元素或类实例则直接取优先级最高的那一份。所以要根据其他字段动态改控件属性时，写在 `reaction` 里即可，不要在 JSX 渲染期间临时计算后传入：

```tsx preview
import { Field, Form, defineEffects, useForm } from '@shikiform/react';
import { FieldInput, FieldSwitch, siteKit } from '@site/ui';

type Values = { vip: boolean; code: string };

const effects = defineEffects<Values>(({ reaction }) => {
  reaction((d) => {
    const vip = d.vip.$value;
    d.code.$title = vip ? '会员码' : '邀请码';
    d.code.$componentProps.placeholder = vip ? 'VIP-0000' : '选填';
    d.code.$componentProps.disabled = !vip;
    d.code.$decoratorProps.extra = vip ? '会员必填' : undefined;
    d.code.$required = vip;
  });
});

export default function App() {
  const form = useForm<Values>({ initialValues: { vip: false, code: '' }, effects: [effects] });
  return (
    <Form form={form} kit={siteKit} style={{ maxWidth: 420 }}>
      <Field name="vip" title="会员" component={FieldSwitch} />
      {/* JSX 的 maxLength 保留：reaction 只覆盖它写到的键 */}
      <Field name="code" title="（被 reaction 覆盖）" component={[FieldInput, { maxLength: 16 }]} />
    </Form>
  );
}
```

在 `reaction` 中操作 `$componentProps` / `$decoratorProps` 时，不同写法的合并效果如下：

| 写法 | 合并效果 |
|---|---|
| `d.x.$componentProps.placeholder = '…'` | 只覆盖 `placeholder`，JSX 和 `fields` 里配的其他属性继续保留 |
| `d.x.$componentProps.style.color = 'red'` | 只补充 `style.color`，保留下层 `style` 里的其他样式；如果 `style` 还没初始化，先写 `style ??= {}` |
| `d.x.$componentProps.style ??= {}` | 准备一个空的 `style` 补丁对象，不会清掉下层已有的 `style` |
| `d.x.$componentProps.style = { color: 'red' }` | 直接替换整个 `style`，下层的 `style` 不再生效 |
| `delete d.x.$componentProps.style` | 删除 `style`，下层的 `style` 同样不再生效 |
| `delete` 数组 draft 的下标（`$componentProps` 里的数组，或 `$value`） | 跟 JavaScript 一样在该下标留空位，`length` 不变。要删除并让后面的元素前移，用 `splice`；表单行用 `useArrayField().remove` |
| `d.x.$componentProps = { … }` | 整体替换整个 props 对象，`fields` 和 JSX 两层配的属性全部失效（只接受普通对象或 `undefined`，传 `null`、数组或原始值在开发环境抛 `ShikiUsageError`，生产环境忽略） |
| `d.x.$componentProps = undefined` | 撤销 `reaction` 这一层的覆盖，恢复成 JSX 和 `fields` 的配置 |

在 `reaction` 内部读取 `$componentProps` 时，只能读到「`fields` 声明 + `reaction`」两层合并后的结果，JSX 层属性仅在渲染阶段合并。UI 状态、`$value`、`$enum` 和 `$rules` 都能在同一轮读回刚写的值。

## 选项写在 JSX 里

下拉框、单选框、多选框组等选择类字段，可以直接在 `<Field>` 上通过 `enum` 传入选项数据，无需提前在 `fields` 中声明。使用 `connect` 或 `useField()` 适配的选择控件会通过 `field.options` 读取这些选项，阅读态下也可据此反显为对应的标签文案。

```tsx preview
import { Form, typed, useField, useForm } from '@shikiform/react';
import { Checkbox, FieldCheckboxGroup, FieldRadioGroup, FormItem, ReadOnlyEnum } from '@site/ui';

type Values = { level: 'gold' | 'silver'; tags: string[]; size: number };

function NativeSelect() {
  const field = useField<string>();
  if (field.readOnly) return <ReadOnlyEnum value={field.value} options={field.options} />;
  return (
    <select id={field.id} value={field.value ?? ''} onChange={(e) => field.onChange(e.target.value)} onBlur={field.onBlur}>
      {field.options.map((o) => <option key={String(o.value)} value={String(o.value)}>{o.label}</option>)}
    </select>
  );
}

export default function App() {
  const form = useForm<Values>({ initialValues: { level: 'gold', tags: ['math'], size: 2 } });
  const F = typed(form);
  return (
    <Form form={form} style={{ maxWidth: 440 }}>
      <div>
        <Checkbox onCheckedChange={(checked) => form.batch((d) => { d.$readOnly = checked ? true : undefined; })}>
          阅读态
        </Checkbox>
      </div>
      {/* value 按字段类型检查：写 'bronze' 编译不过 */}
      <F.Field
        name="level"
        title="等级"
        enum={[{ label: '黄金', value: 'gold' }, { label: '白银', value: 'silver' }]}
        decorator={[FormItem, { layout: 'horizontal' }]}
        component={NativeSelect}
      />
      {/* 数组字段按元素类型检查 */}
      <F.Field
        name="tags"
        title="兴趣"
        enum={[{ label: '数学', value: 'math' }, { label: '诗歌', value: 'poetry' }]}
        decorator={[FormItem, { layout: 'horizontal' }]}
        component={FieldCheckboxGroup}
      />
      {/* 原始值：标签就是 String(value) */}
      <F.Field
        name="size"
        title="尺码"
        enum={[1, 2, 3]}
        decorator={[FormItem, { layout: 'horizontal' }]}
        component={FieldRadioGroup}
      />
    </Form>
  );
}
```

JSX `enum` 的行为规则：

- 优先级：`reaction` 的 `$enum` > JSX `enum` > `fields.x.enum` > 行模板（`rows.*.x`）。JSX `enum` 只在组件挂载期间有效，卸载或改成 `undefined` 后恢复成 `fields` / 行模板里的配置。
- 在 `reaction` 里写 `$enum = undefined` 会撤销联动设置的选项，恢复成组件或字段默认配的选项（同时取消还没返回的异步请求并重置 `loading`）；要显式清空选项请写 `$enum = []`。
- JSX `enum` 按深比较判断变化，渲染期间传入内联数组字面量不会重复触发更新；选项变更后按 `enumPolicy` 处理当前值（例如 `'clear'` 清掉不在新选项中的旧值，首次挂载保留初始值）。
- 支持直接传入异步源 `enum={Cities.with(province)}`；若参数依赖其他字段，放在 `reaction` 中写 `d.city.$enum = …`。
- 在 `typed(form)` 或 `row.Field` 上，选项的 `value` 类型按字段值类型校验（数组字段按元素类型校验）。

## Field 与底层 Hooks 的对应关系

`<Field>` 内部调用 `useField(name, options)`：`visible` 为 `false` 时返回 `null`，否则渲染 `decorator` 包裹的 `component`。

不使用 `<Field>` 时，可直接调用 `useField(name)` 读取 `value`、`onChange`、`onBlur`、`disabled` 等状态，配合 [`useFieldDecorator()`](/reference/react-hooks#usefielddecorator) 渲染标签与错误；在自定义控件或装饰器内部调用无参 `useField()` 则读取外层 `<Field>` 的绑定对象。完整签名见 [useField](/reference/react-hooks#usefield) 与 [接入组件库](/guide/headless#接自己的组件库)。

## 字段名的类型检查

普通 `<Field>` 从 React 上下文获取表单实例，编译期不知道表单值类型，`name` 接受任意字符串（可用于动态路径）。需要在编译期检查字段路径时，调用 `typed(form)`：

```tsx
const F = typed(form)
<F.Field name="email" decorator={[FormItem]} component={[Input]} />   // name="emial" 会触发 TS 编译错误
<F.ArrayField name="items">{(row) => <row.Field name="name" component={[Input]} />}</F.ArrayField>
```

生成的组件依然遵守相对路径作用域规则，`row.Field` 会自动按单行数据类型进行字段名检查。详见 [typed](/reference/react-hooks#typed)。
