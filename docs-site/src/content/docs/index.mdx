title: ShikiForm
description: 面向 TypeScript 的无 UI 表单引擎，集中管理状态与联动，通过 Field + FormItem 接入 Ant Design 等组件库。
---

表单业务复杂起来之后，最容易失控的往往是散落在组件各处的条件判断：某个字段什么时候必填、什么时候隐藏、隐藏后是否还要参与校验和提交。ShikiForm 把表单值、字段状态、校验规则和联动逻辑统一收拢到表单引擎中管理。你可以用 `reaction` 直接给字段状态赋值，React 组件只负责声明界面结构。

```tsx preview
import { useEffect, useRef, useState } from 'react';
import { defineEffects, Form, typed, useForm, useWatch, type Draft } from '@shikiform/react';
import { FormButtonGroup, FormItem, FormLayout, Input, Radio, Submit } from '@shikiform/antd';

type Values = { kind: 'personal' | 'work'; email: string; company: string };

const effects = defineEffects<Values>(({ reaction }) => {
  reaction((d) => {
    const work = d.kind.$value === 'work';
    d.email.$required = work;
    d.email.$componentProps.placeholder = work ? 'name@company.com' : 'name@example.com';
    d.company.$visible = work;
  });
});

function ForgetResult({ clear }: { clear: () => void }) {
  const kind = useWatch((d: Draft<Values>) => d.kind.$value);
  const clearRef = useRef(clear);
  clearRef.current = clear;
  const ready = useRef(false);
  useEffect(() => {
    if (!ready.current) {
      ready.current = true;
      return;
    }
    clearRef.current();
  }, [kind]);
  return null;
}

export default function App() {
  const [result, setResult] = useState('');
  const form = useForm<Values>({
    initialValues: { kind: 'personal', email: '', company: '' },
    effects: [effects],
  });
  const F = typed(form);
  return (
    <Form form={form} onSubmit={(values) => setResult(JSON.stringify(values))} onInvalid={() => setResult('')}>
      <ForgetResult clear={() => setResult('')} />
      <FormLayout labelCol={{ span: 5 }} wrapperCol={{ span: 19 }}>
        <F.Field name="kind" title="账号类型" enum={[{ label: '个人', value: 'personal' }, { label: '工作', value: 'work' }]}
          decorator={[FormItem]} component={[Radio]} />
        <F.Field name="email" title="邮箱" rules={{ format: 'email' }} decorator={[FormItem]} component={[Input]} />
        <F.Field name="company" title="公司" required decorator={[FormItem]} component={[Input]} />
        <FormButtonGroup.FormItem>
          <Submit>提交</Submit>
        </FormButtonGroup.FormItem>
      </FormLayout>
      <pre aria-live="polite">{result}</pre>
    </Form>
  );
}
```

在这段示例里，账号类型为「个人」时，邮箱可以留空提交；切换到「工作」后，`reaction` 会自动将邮箱设为必填、更新提示文本，并显示「公司」字段。切回「个人」时，「公司」字段隐藏，同时跳过校验且不会出现在最终提交数据中。所有联动规则都集中在 `effects` 里，JSX 中不需要掺杂条件分支。

在视图层，`typed(form)` 返回带类型约束的 `Field` 组件，用于绑定数据路径；`decorator`（如 `FormItem`）负责展示标签和报错信息，`component`（如 `Input`）负责具体的输入交互。关于这种写法的细节，请参考 [表单与字段](/guide/field) 和 [核心概念](/guide/concepts)。

## 与常见表单方案的差异

| 维度 | ShikiForm | react-hook-form | Formily |
|---|---|---|---|
| 状态与联动 | 集中在一个引擎内，在 `reaction` 中通过 `$` 状态直接赋值 | 多在组件内调用 `watch` / `setValue` | 依赖 `reactions`，常与 Schema 耦合 |
| UI 绑定 | 引擎本身无 UI，`@shikiform/antd` 作为独立适配层按需引入 | 无 UI，需配合 `Controller` 手动桥接 | 自带整套 Ant Design 适配组件 |
| 显隐与提交 | `visible` 决定是否渲染（`false` 跳过校验，值仍提交）；是否提交只看 `omit`。`disabled` 置灰但仍提交 | 由组件是否挂载决定；`disabled` 默认不提交 | `hidden` 默认跳过校验 |

## 安装与模块划分

日常使用推荐安装 React 绑定包，如需配合 Ant Design 或使用查询列表、草稿表单等高阶能力，再按需安装对应包：

```bash
npm i @shikiform/react
# 如需使用 Ant Design 组件
npm i @shikiform/antd
# 如需查询列表、草稿表单等高阶 Hooks
npm i @shikiform/hooks
```

| 包名 | 职责 |
|---|---|
| `@shikiform/core` | 纯 TypeScript 表单引擎，提供状态管理、draft、`reaction` 和校验，不依赖 React |
| `@shikiform/react` | 提供 `Form`、`Field`、`useField`、`connect` 等 React 绑定，并完整重导出了 `@shikiform/core` |
| `@shikiform/hooks` | 提供 `useQueryTable`、`useShadowForm` 等无 UI 的高阶业务 Hooks |
| `@shikiform/antd` | Ant Design 适配层，提供开箱即用的表单控件、布局容器与 Pro 组件（需安装 `antd` 与 `dayjs`） |

完整的导出清单见 [API 总览](/api)。如果你正在借助 AI 工具编写表单代码，可以把 [/llms.txt](/llms.txt) 提供给它作为上下文。
