表单一复杂，「这个字段什么时候必填、什么时候隐藏、隐藏了还交不交」就散落在组件的 `if` 里。ShikiForm 把值、字段状态、校验和联动都放进一个引擎：联动用 `reaction` 写成对字段状态的赋值，组件只负责渲染。

```tsx preview
import { useState } from 'react';
import { defineEffects, Form, typed, useForm } from '@shikiform/react';
import { FormButtonGroup, FormItem, FormLayout, Input, Radio, Submit } from '@shikiform/antd';

type Values = { kind: 'personal' | 'work'; email: string; company: string };

const effects = defineEffects<Values>(({ reaction }) => {
  reaction((d) => {
    const work = d.kind.$value === 'work';
    d.email.$required = work;
    d.email.$componentProps.placeholder = work ? 'name@company.com' : 'name@example.com';
    d.company.$visible = work;
  });
});

export default function App() {
  const [result, setResult] = useState('');
  const form = useForm<Values>({
    initialValues: { kind: 'personal', email: '', company: '' },
    effects: [effects],
  });
  const F = typed(form);
  return (
    <Form form={form} onSubmit={(values) => setResult(JSON.stringify(values))}>
      <FormLayout labelCol={{ span: 5 }} wrapperCol={{ span: 19 }}>
        <F.Field name="kind" title="账号类型" enum={[{ label: '个人', value: 'personal' }, { label: '工作', value: 'work' }]}
          decorator={[FormItem]} component={[Radio]} />
        <F.Field name="email" title="邮箱" rules={{ format: 'email' }} decorator={[FormItem]} component={[Input]} />
        <F.Field name="company" title="公司" required decorator={[FormItem]} component={[Input]} />
        <FormButtonGroup.FormItem>
          <Submit>提交</Submit>
        </FormButtonGroup.FormItem>
      </FormLayout>
      <pre aria-live="polite">{result}</pre>
    </Form>
  );
}
```

切到「工作」：邮箱变成必填、占位符换掉、公司出现；切回「个人」，公司既不显示、也不校验、不进提交结果。规则都在 `reaction` 里，组件里没有分支。字段用 `typed(form)` 的 `Field`：它拥有路径，`FormItem` 显示标签和错误，`component` 是控件。写法见 [快速上手](/guide/quick-start)。`d.email.$required` 在 [核心概念](/guide/concepts) 里解释。

## 和另外两种写法

| | ShikiForm | react-hook-form | Formily |
|---|---|---|---|
| 状态放哪 | 一个引擎。联动是对 `$` 状态的赋值 | 多在组件里 `watch` / `setValue` | `reactions`，常写在 schema 上 |
| UI | 不带 UI。`@shikiform/antd` 是适配层 | 不带 UI | 自带一套 antd 组件 |
| 藏起字段 | 四种 `display`。`hidden` 仍校验、仍提交 | 由你决定挂不挂载 | `hidden` 不校验 |

## 四个包

这四个包还没有发布到 npm，`npm run release` 只做 `npm publish --dry-run`。发布之后用 `npm i @shikiform/react`、`pnpm add @shikiform/react` 或 `yarn add @shikiform/react`。用 Ant Design 再装 `@shikiform/antd`，查询列表再装 `@shikiform/hooks`。还没发布时，在仓库里构建并 `npm pack`，用 `file:` 安装 tarball，或放进 pnpm / Yarn 的 workspace。命令见 [快速开始](/guide/quick-start#准备)。

| 包 | 里面有什么 |
|---|---|
| `@shikiform/core` | 引擎、draft、校验、`reaction`。不依赖 React |
| `@shikiform/react` | `Form`、`Field`、`connect`、`useField`。同时重新导出 core |
| `@shikiform/hooks` | `useQueryTable` 等无 UI 的 hook |
| `@shikiform/antd` | Ant Design 控件和布局。`antd`、`dayjs` 是 peer |

导出列表见 [API](/api)。用 AI 写代码时，把 [/llms.txt](/llms.txt) 交给它。
