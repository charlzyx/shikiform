## 创建表单

```ts
useForm<T, TSubmit = T>(options?: UseFormOptions<T>): FormInstance<T, TSubmit>  // 组件里，实例稳定；省略 options 等同 {}
createForm<T, TSubmit = T>(options?: FormOptions<T>): FormInstance<T, TSubmit>  // 组件外；省略 options 等同 {}
```

返回的 `FormInstance` 只有下面列出的成员（状态、读写、提交、订阅）；引擎内部的绑定、租约、版本号不在上面，数组和树的增删移动也不在上面。选项只在创建时读取，之后改值用写入 API 或 `reset`。`TSubmit` 是提交值的类型，见下面的 [提交值类型](#提交值类型)。

| 选项 | 默认 | 作用 |
|---|---|---|
| `initialValues` | `{}` | 初始值，`reset` 的目标；写全形状以便推断 `T` |
| `effects` | — | `defineEffects` 模块数组，按顺序安装 |
| `fields` | — | `{ [path]: FieldSpec }`：不依赖挂载的字段模型（规则、`required`、`enum`、`visible`、`disabled`、`readOnly`、`omit`、`title`、`decorator`、`component`、`componentProps` …）。`items.*.name` 跟着每一行；`items.0.name` 留在路径上，见 [数组](/guide/structures) |
| `validate` | — | 整表 Standard Schema，或返回 path → 文案的（异步）函数（接外部校验库时也写在这里） |
| `validateTrigger` | `['onBlur', 'onSubmit']` | 可加 `'onChange'` |
| `asyncDebounceMs` | `0` | 异步规则的防抖，字段可单独设置 |
| `enumPolicy` | `'none'` | 值不在 `$enum` 里时：`'clear'` 清掉，`'error'` 报错 |
| `readOnly` / `disabled` | — | 整张表的初始只读 / 禁用（根上的 `$readOnly` / `$disabled`）。子字段沿路径继承：这一层写了 `true` 或 `false` 就用这一层，没写就保持上一层。之后用 `d.$readOnly = …` 改，`undefined` 丢掉 reaction 层，根回到可编辑 |
| `trees` | — | `{ [path]: { childrenKey?, rowKey? } }`：让联动在挂载前就认识树根 |
| `messages` | 中文 | 覆盖内置文案（校验、提交重试、树移动拒绝、默认按钮文案），可部分覆盖，值可以是函数，见 [内置文案](/guide/validation#内置文案) |

### 读写和提交

| 方法 | 说明 |
|---|---|
| `getValue(path)` / `setValue(path, value)` | 读 / 写一个有类型的 path，`a.b.c` 与 `a.b[0].c` 都可以。开发环境读到的对象、数组、`Map`、`Set`、`Date` 是只读视图，原地修改抛 `ShikiUsageError`（错误里有路径）；同一底层对象多次读取是同一个引用，但视图和存储对象 `===` 不相等（生产环境相等）。`rows.indexOf(rawRow)` / `includes` 仍能找到。写入用 `setValue` / `patchValues`，联动里写 `d.x.$value = …`，数组在组件里用 `useArrayField().push`。不要把视图交给会 `push` / `sort` 的控件。`structuredClone` / `postMessage` / IndexedDB 用 `snapshot(value)`（`@shikiform/core`）；只要提交值用 `getSubmitValues()`。`toRaw(value)` 是存储对象本身。生产环境返回存储的原值 |
| `batch((d) => { … })` | 用一个 draft 做多次写入，一轮联动、一次通知 |
| 数组 / 树增删移动 | 不在表单上。见下面的 [数组与树句柄](#数组与树句柄) |
| `validate()` / `validate(path)` / `validate([paths])` | 校验全表、一棵子树，或一组路径（一次校验，`FormStep` 的「下一步」就是路径数组）。通过时 resolve 克隆后的值：无 path 为 `getSubmitValues()`（`TSubmit`，被 `omit` 的字段不在里面）；一个 path 为该处的值（类型 `PathValue`；这个 path 自己即使 `omit` 也返回，只因它而被 `omit` 的子孙仍在，子孙自己的 `omit` 才去掉）；路径数组为只含这些 path 的嵌套对象（类型 `ValidatePick`，同样去掉被 `omit` 的子孙）。字面量 path 保留各自的值；运行时下标是数字键（`{ rows: { 0: { name } } }`）。返回的数组是稠密的，没选中的下标是 `undefined`，`result.rows[0]` 读到的就是该处。失败 reject `FieldError[]`；表单级 `validate` 抛错原样 reject |
| `submit(onValid?)` | 等异步规则、校验，通过才调用 `onValid`。resolve 提交值；`onValid` 返回非 `undefined` 时 resolve 那个返回值。失败 reject `FieldError[]`。`onValid` 抛错原样 reject。被后一次 `submit` 取代 reject `SubmitSupersededError`（`code: 'superseded'`）。值连续 3 轮没稳定 reject `SubmitUnstableError`（`code: 'unstable'`） |
| `getSubmitValues()` | 去掉 `omit: true` 和 `visible: false, omit: true` 后的值。reaction 写过的字段默认留下 |
| `reset(path?)` | 恢复初始值（全表或子树），计算字段重新算；touched、edited、错误清空 |
| `reset(values)` | 编辑页回填：`values` 同时成为新的初始值，之后 `reset()` 回到它，`dirty` 以它为基线 |
| `setInitialValues(values)` | 只换基线、不改当前值。保存成功后 `form.setInitialValues(form.values)` |
| `setErrors(errors)` | 回填外部（服务端）错误：`setErrors({ username: '已存在' })`，`null` 清掉那条，见 [校验 · 服务端错误](/guide/validation#服务端错误) |
| `clearErrors(path?)` | 清掉全表或子树上的所有错误（规则、schema、外部），值不变 |
| `subscribeValidateFailed((errors) => …)` | `submit()` 或 `validate()` reject `FieldError[]` 时调用，参数是这次的错误；change / blur 触发的校验不调用。返回取消订阅。`FormTab` / `FormCollapse` / `FormStep` 切到有错的面板、`<Form>` 聚焦第一个错误字段都靠它 |
| `message(key, params?)` | 按本表单的 `messages` → `setDefaultMessages` → `zhCN` 解析一条内置文案 |
| `subscribePath(path, fn)` / `subscribeStructure(path, fn)` / `subscribeMeta(fn)` | 不用 React 时订阅：某个 path 的值或字段状态变化 / 数组或树的长度、顺序变化 / `canSubmit`、`submitting`、`submitCount`、`dirty`、`validating` 变化。返回取消订阅。React 里用 `useWatch` / `useField` |

实例属性（`values`、`initial`、`errors`、`canSubmit`、`submitting`、`validating`、`submitCount`、`dirty`、`edited`）都是**只读**的，赋值是 TS 错误、运行时抛 `TypeError`；写值走上面的方法。开发环境里 `values` 还是只读视图，`form.values.user.name = 'x'` 会抛 `ShikiUsageError`。它们不会触发渲染；在 React 里用 `useWatch((d) => d.$canSubmit)` 之类订阅。

### 数组与树句柄

行和节点的结构操作在句柄上，不在 `form.pushArray` / `form.moveTree` 上。句柄来自上下文（最近一层，不需要 name）或按名字取。字段状态跟着 `rowKey`（没有 id 时是稳定的对象身份）走。

```ts
useArrayField<TRow = unknown>(): ArrayHandle<TRow>
useArrayField(name, opts?: { rowKey?: string }): ArrayHandle<行类型>
useTreeField<TNode = unknown>(): TreeNodeHandle<TNode>   // 必须在节点里。path 是当前节点
useTreeField(name, opts?: { childrenKey?: string; rowKey?: string }): TreeHandle<unknown>   // path 和 treePath 都是树根

interface ArrayHandle<TRow> {
  path: string
  keys: { key: string; index: number }[]
  push(row: TRow): void
  insert(index: number, row: TRow): void
  remove(index: number): void
  move(from: number, to: number): void   // to 是最终下标
  swap(indexA: number, indexB: number): void
  replace(index: number, row: TRow): void
  dragProps(index: number): DragProps
}

interface TreeHandle<TNode> {
  path: string            // 句柄指向的路径：树根句柄是树根，节点句柄是当前节点
  treePath: string        // 永远是树根。树根句柄上和 path 相同
  errors: readonly string[]     // 这一层自己的消息，不含子孙字段
  warnings: readonly string[]
  value: TNode[]
  push(node: TNode, parentPos?: Pos): void  // 追加到根，或作为 parentPos 的最后一个孩子
  insert(pos: Pos, node: TNode): void
  remove(pos: Pos): void
  replace(pos: Pos, node: TNode): void
  move(from: Pos, to: Pos): MoveResult   // 最终坐标；拒绝移入自身子孙，reason 说明原因
  dragProps(pos: Pos): DragProps
}
```

`useArrayField()` 必须渲染在 `<ArrayField>` 里（行，或 `component` 容器，工具栏也算）。不在里面时，开发构建抛 `ShikiUsageError`。嵌套时取最近的一层。当前行下标是 `useIndex()`（树节点里是兄弟下标），当前行或节点的值是 `useRecord()`。句柄的 `path` 永远是它指向的东西：`useTreeField(name)` 的 `path` 和 `treePath` 都是树根；`useTreeField()` 必须在 `<TreeField>` 的节点里，`path` 是当前节点，`treePath` 是树根，并带上 `pos`、`index`、`record` 和这棵树的 `value`、`push`、`insert`、`remove`、`replace`、`move`、`dragProps`（`dragProps()` 不传坐标指向当前节点）。两种句柄的 `errors` / `warnings` 都只算自己这一层。移动一个节点时，位置和子树都没变的兄弟、以及其他子树，不会重新渲染。

联动里改数组是赋一个新数组（`d.items.$value = [...d.items.$value, row]`），不要原地 `push`。组件里追加、删除、排序用上面的句柄。签名和例子在 [useArrayField](/reference/react-hooks#usearrayfield)、[useTreeField](/reference/react-hooks#usetreefield)。

- `dirty`：当前值和初始值**不同**（深比较），改回原值就变回 `false`；表单级不算 `omit`（含被祖先 omit 的子孙）和计算字段（`visible: false` 仍算）。适合「没改动时禁用保存」「离开前提示未保存」。
- `edited`：粘滞标记，用户编辑过（`setValue` / 控件 `onChange`）就为 `true`，直到 `reset`。reaction 写值不算。

### 编辑页回填

```ts
const form = useForm<Values>({ values: query.data })            // 记录到达 / 重新加载 → reset(记录)
const dirty = useWatch((d: Draft<Values>) => d.$dirty)          // 改回原值也会变回 false

<Button disabled={!dirty} onClick={() => form.submit(save)}>保存</Button>
```

`initialValues` 只在创建时读取；`values` 是外部拥有的数据：第一次渲染当作初始值，之后换成**内容不同**的新对象时自动调用 `reset(values)`（成为新基线、丢弃未保存的编辑、`dirty` 回到 `false`）。内容相同的新对象（每次渲染新建的字面量）什么也不做。没有 React 时直接调用 `form.reset(record)`；不要用 `key` 重挂整个表单。

### 提交值类型

`submit` / `getSubmitValues` / `<Form onSubmit>` 的值类型：

- 不写泛型，或 `typed<V>().createForm({ fields })` / `typed<V>().useForm({ fields })`：`fields` 里 `omit: true` 变成可选。`visible: false` 仍提交，类型上仍在，除非同时 `omit: true`。
- `createForm<V>({ fields })` / `useForm<V>({ fields })`：提交类型就是 `V`，不看 `fields`。`createForm()` / `useForm()` / `useForm(undefined)` 返回表单，等同 `{}`。
- 第二个类型参数照写（下面的例子）。JSX 的 `omit` 和 reaction 里的 `$omit` 类型上看不到，只能自己列出路径。

```ts
import { createForm, type SubmitValues } from '@shikiform/react'

type V = { a: string; tmp: string; b: string; rows: { qty: number; total: number }[] }
const form = createForm<V, SubmitValues<V, 'tmp' | 'b' | 'rows.*.total'>>({
  initialValues: { a: '1', tmp: 'x', b: '', rows: [] },
  fields: { tmp: { omit: true }, 'rows.*.total': { omit: true } },
})
await form.submit((values) => {
  values.tmp   // string | undefined
  values.rows[0]?.total // number | undefined
})
```

路径写法与 `fields` 相同：`rows.*.total` 对每一行生效，数字下标也会让每一行的该字段变成可选。不传路径时 `SubmitValues<T>` 就是 `T`。提交类型与后端 DTO 完全不同时，直接写 `createForm<V, SaveDto>()`，`onSubmit` 里自己转换。

## React 组件

| 组件 | 说明 |
|---|---|
| `<Form form onSubmit onInvalid onSubmitError …>` | 提供引擎，渲染原生 `<form>`，提交时调用 `form.submit(onSubmit)`；校验失败调 `onInvalid(errors)`，`onSubmit` 抛错调 `onSubmitError(error)`（不传则 `console.error`）；提交或 `form.validate()` 失败时聚焦表单里第一个有错的字段（按文档顺序）。控件 `id` 是 `<前缀>-<净化路径>`（`user.name` → `<前缀>-user-name`；前缀是 `<Form id>`，没传则是 React `useId()`）。`<form>` 自身的 `id` 只在传入 `id` 时设置。其余属性（`className`、`noValidate`、`aria-*`）透传给 `<form>` |
| `<Field name …>` | 拥有一个 path，渲染 decorator + component，属性见 [Field](/guide/field) |
| `<ObjectField name visible? disabled? readOnly? omit?>` | 对象作用域。`visible` / `disabled` / `readOnly` 传给里面的字段（子级 `false` 可退出）。`omit` 整棵对象不进提交，里面的字段读到的 `omit` 也是 `true`，`omit: false` 不能单独提交 |
| `<ArrayField name rowKey? component? virtualScroll?>{({ index, key }) => …}` | 每行一个作用域；父组件只订阅结构。`component` 是包住各行的自定义容器（见 [动态数组与表格](/guide/arrays)）；`virtualScroll={{ height }}` 只挂载可见的普通行，不和 `component` 同用 |
| `<TreeField name childrenKey? rowKey?>{(node) => …}` | 注册树根并递归渲染节点：`node` 为 `{ path, pos, index, key, depth, children }`（叶子节点的 `children` 为 `null`）。节点里 `useTreeField()` 读当前节点的 `path` / `pos` / `index` / `record`，并带上这棵树的增删、`move` 和 `dragProps()`。节点外拿整棵树用 `useTreeField(name)` |
| `<Field name ui="echo">` / `<UI name component decorator …>` | 同一字段的第二个 UI（`d.x.$ui('echo')`）/ 不带值的 UI 节点（`d.$ui(name)`），见 [命名 UI 节点](/guide/ui) |
| `<Watch select>{(value) => …}` | `useWatch` 的渲染形式 |

`<Field>`、`<ObjectField>`、`<ArrayField>`、`useField` 不写泛型时接受任意字符串（动态路径的出口）。要按表单类型检查名字，用 [`typed(form)`](/reference/react-hooks#typed) 拿到同一组组件的有类型版本：`<F.Field name="emial">` 编译不过，`ArrayField` 的每一行再给一组按行类型检查的 `row.Field`。可复用的字段片段是普通组件，放在 `<ObjectField>` 里，用 `typed<Address>()` 按片段自己的类型检查。名字在运行时始终相对当前作用域。

## 联动

```ts
const effects = defineEffects<Values>(({ reaction, watch, query }) => {
  reaction((d) => { … })
  reaction.each((d) => d.items, (row, ctx) => { … }) // 两个参数；对象数组会继续往下走
  watch((d) => d.a.$value, (d) => { … })
  watch.each((d) => d.items, (row, ctx) => { … })
})
```

| API | 触发 | 说明 |
|---|---|---|
| `reaction(effect)` | 立即运行；之后读到的 `$` 状态变化时 | 同步派生；写 `$value` 的字段成为计算字段，默认仍提交 |
| `reaction.each(select, effect)` | 每个元素一个实例，并进入嵌套的对象数组 | 只有两个参数。嵌套的基本类型数组不进；对基本类型数组本身调用时，`depth === 0` 仍会访问。用 `ctx.key` / `ctx.depth` 过滤 |
| `watch(source, effect)` | `source` 读到的状态变化后；首次不运行 | 多个来源返回数组 |
| `watch.each(select, effect)` | 与 `reaction.each` 同一层遍历；回调里读到的状态就是来源 | 某个元素变化只触发它自己 |
| `query(path)` | — | 精确 path 的底层 handle（动态路径用），平时写 `d.a.b` |

行级回调都是 `(row, ctx)`，`ctx` 含 `d`、`key`、`index`、`depth`、`parent`、`path`、`pos`。详见 [联动](/guide/linkage)；`$` 状态与显隐见 [核心概念](/guide/concepts)，规则见 [校验](/guide/validation)。

## 引擎工具（`@shikiform/core`）

联动、组件都用不到它们；写自己的树组件或做组合选择时才需要。全部是纯函数，不依赖 React。

```ts
// 树坐标：pos 是下标路径（[0, 2] = 第 1 个节点的第 3 个子节点）
pathOf(root: string, pos: Pos, childrenKey = 'children'): string          // pathOf('menus', [0, 2]) → 'menus.0.children.2'
posOf(root: string, path: string, childrenKey = 'children'): Pos | undefined
moveNode(nodes: any[], from: Pos, to: Pos, childrenKey?, canMove?, messages?): TreeMoveResult  // 不改原数组；to 是移动后的坐标

// 组合选择
comboMatch(table, selection): boolean                                     // 组合表里是否有一行满足所有已选维度
comboOptions(table, selection, dim, { disabledWhen? }?): ComboOption[]    // 其余维度已选时，dim 还能选哪些值
```

`moveNode` 的拒绝原因（移到自己的子树里、坐标不存在）走表单 `messages`（`treeIntoSelf` …）。树句柄 `useTreeField(name).move` 和节点上的 `useTreeField().move` 返回的 `reason` 用的就是它。组合表的完整例子在 [示例 · 联动](/examples/linkage)。外部校验库直接传给 `rules` / `validate`（Standard Schema），不需要额外的工具函数。

## 错误类与文案

```ts
class ShikiUsageError extends Error      // 开发期写法错误：改 $value 对象、同一轮读回刚写的值、把 handle 当数组、拼错 $ 状态、
                                         // 未知规则键（minLenght）、component={[undefined]}、<ArrayField> 用在非数组上…；消息里写了正确写法
class ShikiCycleError extends Error      // reaction / watch 10 轮仍未收敛；cycle: readonly string[] 是互相触发的链
class ShikiConflictError extends Error   // 开发期：两个 reaction 写了同一个 $ 状态；state、first、second 指出是谁
class SubmitSupersededError extends Error // submit 被后一次 submit 取代；code = 'superseded'
class SubmitUnstableError extends Error   // 值连续 3 轮没稳定，不是被取代；code = 'unstable'
function isFieldErrors(value): value is FieldError[]  // validate / submit 失败时 reject 的就是这个数组

zhCN / enUS: FormMessages                // 内置文案（默认 zhCN）
setDefaultMessages(messages: Partial<FormMessages>): void   // 全应用默认，部分覆盖
getDefaultMessages(): FormMessages       // 当前的全应用默认（setDefaultMessages 之后的结果）
```

`ShikiCycleError`、`ShikiUsageError`、`ShikiConflictError`、`SubmitSupersededError`、`SubmitUnstableError` 和 `isFieldErrors` 都从 `@shikiform/react` 和 `@shikiform/core` 导出。错误类可以 `instanceof` 判断。`SubmitSupersededError`（`code: 'superseded'`）是被后一次提交取代。`SubmitUnstableError`（`code: 'unstable'`）是值连续 3 轮没稳定，不是被取代；`<Form>` / `<Submit>` 把它交给 `onSubmitError`。两者都不要和 `FieldError[]` 混在一起，用 `isFieldErrors` 区分校验失败。`ShikiCycleError` 在生产构建里也会抛（联动循环触发）；`ShikiUsageError` 和 `ShikiConflictError` 只在开发构建检查。开发构建里，冲突和循环的消息逐个列出涉及的 reaction：声明位置（`文件:行:列`）、它读了哪些状态、写了哪些状态。两个写者的冲突改成一个写者，或把动作移到 `watch`。文案的优先级是规则自己的 `message` > 表单 `messages` > `setDefaultMessages` > `zhCN`，见 [内置文案](/guide/validation#内置文案)。
