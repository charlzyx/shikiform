## 模块入口

| 入口 | 主要导出 |
|---|---|
| `@shikiform/react` | 零 UI 库依赖的完整 React 入口：`useForm`、`useFormContext`、`typed`、`createForm`、`defineEffects`；`Form`、`Field`、`FieldKit`、`ObjectField`、`ArrayField`、`TreeField`、`UI`、`Watch`；`connect` / `mapProps`；headless `Submit` / `Reset`；上表的 React、查询与 Pro Hooks（含 `enumItems` / `ENUM_COLORS`）；`EnumSource`、`ShikiUsageError` 等错误类、`zhCN` / `enUS` / `setDefaultMessages` / `getDefaultMessages`；类型 `Draft`、`FieldBinding`、`FieldProps`、`FormOptions`、`Pos`、`MoveResult`、`FieldEnum` … |

## 创建表单

```ts
useForm<T, TSubmit = T>(options?: UseFormOptions<T>): FormInstance<T, TSubmit>  // 组件里，实例稳定；省略 options 等同 {}
createForm<T, TSubmit = T>(options?: FormOptions<T>): FormInstance<T, TSubmit>  // 组件外；省略 options 等同 {}
```

返回的 `FormInstance` 只公开下面这些状态、读写、提交和订阅接口（数组和树的增删移动放在 `useArrayField` / `useTreeField` 上）。选项只在创建时读取，后续改值用写入方法或 `reset`。`TSubmit` 是提交值的类型，见下面的 [提交值类型](#提交值类型)。

| 选项 | 默认 | 作用 |
|---|---|---|
| `initialValues` | `{}` | 初始值，`reset` 的目标；写全形状以便推断 `T` |
| `effects` | — | `defineEffects` 模块数组，按顺序安装 |
| `fields` | — | `{ [path]: FieldSpec }`：不依赖挂载的字段模型（规则、`required`、`enum`、`visible`、`disabled`、`readOnly`、`omit`、`title`、`decorator`、`component`、`componentProps` …）。`items.*.name` 跟着每一行；`items.0.name` 留在路径上，见 [数组](/guide/structures) |
| `validate` | — | 整表 Standard Schema，或返回 path → 文案的（异步）函数（接外部校验库时也写在这里） |
| `validateTrigger` | `['onBlur', 'onSubmit']` | 可加 `'onChange'` |
| `asyncDebounceMs` | `0` | 异步规则的防抖，字段可单独设置 |
| `enumPolicy` | `'none'` | 值不在 `$enum` 里时：`'clear'` 清掉，`'error'` 报错 |
| `readOnly` / `disabled` | — | 整张表的初始只读 / 禁用（根上的 `$readOnly` / `$disabled`）。子字段沿路径继承：这一层写了 `true` 或 `false` 就用这一层，没写就保持上一层。之后用 `d.$readOnly = …` 改，`undefined` 丢掉 reaction 层，根回到可编辑 |
| `trees` | — | `{ [path]: { childrenKey?, rowKey? } }`：让联动在挂载前就认识树根 |
| `messages` | 中文 | 覆盖内置文案（校验、提交重试、树移动拒绝、默认按钮文案），可部分覆盖，值可以是函数，见 [内置文案与国际化](/guide/validation#内置文案与国际化) |

### 读写和提交

| 方法 | 说明 |
|---|---|
| `getValue(path)` / `setValue(path, value)` | 按路径读 / 写值，点号（`a.b.0.c`）和方括号（`a.b[0].c`）等价。在 `reaction` / `watch` / `batch` 里调用时，写入和 draft 一起提交或回滚，读也能立刻看到刚改的值。路径里引号键不能含 `.`、`[`、`]`（需要时直接替换父对象）；数组下标必须是非负整数（开发环境抛 `ShikiUsageError`，生产忽略）。开发环境读到的对象、数组、`Map`、`Set`、`Date` 是只读视图（原地修改会抛 `ShikiUsageError`；需要传给 `structuredClone` / `postMessage` / IndexedDB 时用 `snapshot(value)`，要底层原对象用 `toRaw(value)`）；生产环境返回原值 |
| `patchValues(partial)` | 一次刷新里递归合并局部普通对象（未传入的兄弟字段不变，数组与原始值整体替换）；在 `reaction` / `watch` / `batch` 里调用时，和 draft 一起提交或回滚 |
| `setReadOnly(readOnly?)` / `setDisabled(disabled?)` | 一次性设置或清除（传 `undefined`）整张表的根级 `$readOnly` / `$disabled` |
| `batch((d) => { … })` | 在一次批处理里做多次修改，只跑一轮联动、触发一次更新。批里调用 `setValue` / `patchValues` / `getValue` 会立刻看到刚做的修改；嵌套 `batch` 成功时并入外层，抛错时只撤销内层自己的修改（值、行操作、初始值和错误），不影响外层 |
| 数组 / 树增删移动 | 不在表单实例上，见下面的 [数组与树操作](#数组与树句柄) |
| `validate()` / `validate(path)` / `validate([paths])` | 校验全表、单个子树或一组路径（分步表单的「下一步」就是传路径数组；点号和方括号等价）。通过时返回克隆后的值：无参数返回 `getSubmitValues()`（`TSubmit`，去掉 `omit`，根 `$omit: true` 时为 `{}`）；单路径返回该路径的值（即使它本身设了 `omit` 也会校验并返回，但子字段自己的 `omit` 会去掉）；路径数组返回只含这些路径的嵌套对象（`ValidatePick`，未选中的数组下标为 `undefined`）。失败 reject `FieldError[]`，表单级 `validate` 抛错原样 reject |
| `submit(onValid?)` | 等异步规则跑完并校验，通过后才调用 `onValid`。成功时 resolve `onValid` 的非 `undefined` 返回值（否则 resolve 提交值）；失败 reject `FieldError[]`；`onValid` 抛错原样 reject。如果又发起了新一次 `submit`，还在校验中的旧调用会立刻 reject `SubmitSupersededError`（已在执行的 `onValid` 仍算在 `submitting` 里）。如果值连续 3 轮都没稳定，reject `SubmitUnstableError` |
| `getSubmitValues()` | 返回去掉 `omit: true` 字段后的提交数据（根层 `$omit: true` 时返回 `{}`）。`visible: false` 和联动写入的字段默认保留 |
| `reset(path?)` | 恢复全表或某个子树的初始值（点号和方括号等价），重算计算字段，清空 `touched`、`edited` 和错误，并取消这个子树上还没跑完的校验。在 `batch` / `watch` 里和 `reset(values)` / `setInitialValues` 连续调用时按顺序生效，嵌套 `batch` 抛错会一起回滚 |
| `reset(values)` | 编辑页回填：`values` 同时变成新的初始值，之后 `reset()` 回到它，`dirty` 也以它为准。在 `batch` / `watch` 里按顺序生效，嵌套 `batch` 抛错会一起回滚 |
| `setInitialValues(values)` | 只更新初始值，不改当前已填的值（比如保存成功后调 `form.setInitialValues(form.values)` 清掉 `dirty`）。在 `batch` / `watch` 里与 `reset` 按顺序生效，嵌套 `batch` 抛错会一起回滚 |
| `setErrors(errors)` | 回填外部（如服务端）错误：`setErrors({ username: '已存在' })`，传 `null` 清除该条，点号和方括号等价。在 `batch` / `watch` 里按当时的最新行位置写入（移动行后会落到移动后该位置的行），批结束时统一生效，嵌套 `batch` 抛错会回滚。详见 [校验 · 服务端错误](/guide/validation#服务端错误) |
| `clearErrors(path?)` | 清掉全表或某个子树上的所有错误（规则、Schema、外部错误），点号和方括号等价，不改值。在 `batch` / `watch` 里的行为与 `setErrors` 相同 |
| `subscribeValidateFailed((errors) => …)` | `submit()` 或 `validate()` 校验失败时触发（输入/失焦触发的校验不调用），返回取消订阅函数。标签页/折叠面板/分步容器自动切到出错页、`<Form>` 自动聚焦第一个出错字段都靠它 |
| `message(key, params?)` | 按「当前表单 `messages` → `setDefaultMessages` → `zhCN`」的顺序解析内置文案 |
| `subscribePath(path, fn)` / `subscribeStructure(path, fn)` / `subscribeMeta(fn)` | 非 React 环境下手动订阅：某字段的值或状态变化 / 数组或树增删排序（点号与方括号等价） / `canSubmit`、`submitting`、`submitCount`、`dirty`、`validating` 变化，均返回取消订阅函数。React 里直接用 `useWatch` / `useField` |

`validate` 有三个重载，通过时 resolve 的类型跟参数走：

```ts
validate(): Promise<TSubmit>
validate<P extends FieldPath<T>>(path: P): Promise<PathValue<T, P>>
validate<const Paths extends readonly FieldPath<T>[]>(paths: Paths): Promise<ValidatePick<T, Paths>>
```

关于 `validate` 的几个常见细节：
- **返回独立副本**：普通对象、数组、`Date`、`Map`、`Set` 会拷贝一份（类实例、函数、React 元素保持原引用），你可以直接改返回值，不会影响表单。路径不存在时返回 `undefined`。
- **与 `submit()` 的区别**：`validate()` 只校验开始那一刻的值，期间值变了不会重跑；`submit()` 会等到值稳定后再把校验过的那份数据交出去。
- **异步校验遇到行移动/删除**：异步校验还没返回时，如果对应的数组行或树节点被移动了，结果会自动跟到新位置；如果行被删除或整行替换了，旧错误会自动丢弃，不会错报到别的行上。局部 `validate(path)` / `validate([paths])` 同样如此：校验失败时按行移动后的新位置报错，全部通过时按你传入的路径返回当前值。

```ts
const values = await form.validate()
const city = await form.validate('user.city')
const picked = await form.validate(['name', 'user.city'])
values.name = 'Grace' // 只改副本
```

实例属性（`values`、`initial`、`errors`、`canSubmit`、`submitting`、`validating`、`submitCount`、`dirty`、`edited`、`readOnly`、`disabled`）都是**只读**的，赋值是 TS 错误、运行时抛 `TypeError`；写值走上面的方法。开发环境里 `values` 还是只读视图，`form.values.user.name = 'x'` 会抛 `ShikiUsageError`。它们不会触发渲染；在 React 里用 `useWatch((d) => d.$canSubmit)` 之类订阅。

### 数组与树句柄

行和节点的结构操作在句柄上，不在 `form.pushArray` / `form.moveTree` 上。句柄来自上下文（最近一层，不需要 name）或按名字取。字段状态跟着 `rowKey`（没有 id 时是稳定的对象身份）走。

```ts
useArrayField<TRow = unknown>(): ArrayHandle<TRow>
useArrayField(name, opts?: { rowKey?: string }): ArrayHandle<行类型>
useTreeField<TNode = unknown>(): TreeNodeHandle<TNode>   // 必须在节点里。path 是当前节点
useTreeField(name, opts?: { childrenKey?: string; rowKey?: string }): TreeHandle<unknown>   // path 和 treePath 都是树根

interface ArrayHandle<TRow> {
  path: string
  keys: { key: string; index: number }[]
  errors: readonly string[]     // 这一层数组自己的消息，不含子字段
  warnings: readonly string[]
  push(row: TRow): void
  insert(index: number, row: TRow): void
  remove(index: number): void
  move(from: number, to: number): void   // to 是最终下标
  swap(indexA: number, indexB: number): void
  replace(index: number, row: TRow): void
  dragProps(index: number): DragProps
}

interface TreeHandle<TNode> {
  path: string            // 句柄指向的路径：树根句柄是树根，节点句柄是当前节点
  treePath: string        // 永远是树根。树根句柄上和 path 相同
  errors: readonly string[]     // 这一层自己的消息，不含子孙字段
  warnings: readonly string[]
  value: TNode[]
  push(node: TNode, parentPos?: Pos): void  // 追加到根，或作为 parentPos 的最后一个孩子
  insert(pos: Pos, node: TNode): void
  remove(pos: Pos): void
  replace(pos: Pos, node: TNode): void
  move(from: Pos, to: Pos): MoveResult   // 最终坐标；拒绝移入自身子孙，reason 说明原因
  dragProps(pos: Pos): DragProps
}
```

`useArrayField()` 必须渲染在 `<ArrayField>` 里（行，或 `component` 容器，工具栏也算）。不在里面时，开发构建抛 `ShikiUsageError`。嵌套时取最近的一层。当前行下标是 `useIndex()`（树节点里是兄弟下标），当前行或节点的值是 `useRecord()`。句柄的 `path` 永远是它指向的东西：`useTreeField(name)` 的 `path` 和 `treePath` 都是树根；`useTreeField()` 必须在 `<TreeField>` 的节点里，`path` 是当前节点，`treePath` 是树根，并带上 `pos`、`index`、`record` 和这棵树的 `value`、`push`、`insert`、`remove`、`replace`、`move`、`dragProps`（`dragProps()` 不传坐标指向当前节点）。两种句柄的 `errors` / `warnings` 都只算自己这一层。移动一个节点时，位置和子树都没变的兄弟、以及其他子树，不会重新渲染。

联动里 `d.items.$value.push(row)` 和组件里的 `useArrayField().push(row)` 是同一套行操作（在同一批内，数组/树句柄与 draft 数组方法按调用顺序生效，已编辑的单元格值以及规则、枚举和 UI 状态随行或节点移动，删除的行不会复活）；也可以整表替换 `d.items.$value = [...]`。已注册的树用 `useTreeField()`，不要对 `$value` 调用 `push`。签名和例子在 [useArrayField](/reference/react-hooks#usearrayfield)、[useTreeField](/reference/react-hooks#usetreefield)。

- `dirty`：当前值和初始值**不同**（深比较），改回原值就变回 `false`；表单级不算 `omit`（含根层 `$omit: true` 及父级 `omit` 下的子字段）和计算字段（`visible: false` 仍算）。适合「没改动时禁用保存」「离开前提示未保存」。
- `edited`：只要用户手动改过值（`setValue` 或控件 `onChange`）就会保持 `true`，直到调用 `reset`（哪怕改回原值也仍是 `true`）。联动写入不算。

### 编辑页回填

```ts
const form = useForm<Values>({ values: query.data })            // 记录到达 / 重新加载 → reset(记录)
const dirty = useWatch((d: Draft<Values>) => d.$dirty)          // 改回原值也会变回 false

<Button disabled={!dirty} onClick={() => form.submit(save)}>保存</Button>
```

`initialValues` 只在创建时读取；`values` 是外部拥有的数据：第一次渲染当作初始值，之后换成**内容不同**的新对象时自动调用 `reset(values)`（成为新基线、丢弃未保存的编辑、`dirty` 回到 `false`）。内容相同的新对象（每次渲染新建的字面量）什么也不做。没有 React 时直接调用 `form.reset(record)`；不要用 `key` 重挂整个表单。

### 提交值类型

`submit` / `getSubmitValues` / `<Form onSubmit>` 的值类型：

- 不写泛型，或 `typed<V>().createForm({ fields })` / `typed<V>().useForm({ fields })`：`fields` 里 `omit: true` 变成可选。`visible: false` 仍提交，类型上仍在，除非同时 `omit: true`。
- `createForm<V>({ fields })` / `useForm<V>({ fields })`：提交类型就是 `V`，不看 `fields`。`createForm()` / `useForm()` / `useForm(undefined)` 返回表单，等同 `{}`。
- 第二个类型参数照写（下面的例子）。JSX 的 `omit` 和 reaction 里的 `$omit` 类型上看不到，只能自己列出路径。

```ts
import { createForm, type SubmitValues } from '@shikiform/react'

type V = { a: string; tmp: string; b: string; rows: { qty: number; total: number }[] }
const form = createForm<V, SubmitValues<V, 'tmp' | 'b' | 'rows.*.total'>>({
  initialValues: { a: '1', tmp: 'x', b: '', rows: [] },
  fields: { tmp: { omit: true }, 'rows.*.total': { omit: true } },
})
await form.submit((values) => {
  values.tmp   // string | undefined
  values.rows[0]?.total // number | undefined
})
```

路径写法与 `fields` 相同：`rows.*.total` 对每一行生效，数字下标也会让每一行的该字段变成可选。不传路径时 `SubmitValues<T>` 就是 `T`。提交类型与后端 DTO 完全不同时，直接写 `createForm<V, SaveDto>()`，`onSubmit` 里自己转换。

## React 组件

| 组件 | 说明 |
|---|---|
| `<Form form onSubmit onInvalid onSubmitError …>` | 提供引擎，渲染原生 `<form>`，提交时调用 `form.submit(onSubmit)`；校验失败调 `onInvalid(errors)`，`onSubmit` 抛错调 `onSubmitError(error)`（不传则 `console.error`）；提交或 `form.validate()` 失败时聚焦表单里第一个有错的字段（按文档顺序）。控件 `id` 是 `<前缀>-<净化路径>`（`user.name` → `<前缀>-user-name`；前缀是 `<Form id>`，没传时 React 18+ 自动用 `useId()` 生成可水合前缀，React 16.8/17 在 SSR 下请显式传入 `<Form id="…">` 以避免水合不一致）。`<form>` 自身的 `id` 只在传入 `id` 时设置。其余属性（`className`、`noValidate`、`aria-*`）透传给 `<form>` |
| `<Field name …>` | 拥有一个 path，渲染 decorator + component，属性见 [Field](/guide/field) |
| `<ObjectField name visible? disabled? readOnly? omit?>` | 对象作用域。`visible` / `disabled` / `readOnly` 传给里面的字段（子级 `false` 可退出）。`omit` 整棵对象不进提交，里面的字段读到的 `omit` 也是 `true`，`omit: false` 不能单独提交 |
| `<ArrayField name rowKey? component? virtualScroll?>{({ index, key }) => …}` | 每行一个作用域；父组件只订阅结构。`component` 是包住各行的自定义容器（见 [动态数组与表格](/guide/arrays)）；`virtualScroll={{ height }}` 只挂载可见的普通行，不和 `component` 同用 |
| `<TreeField name childrenKey? rowKey?>{(node) => …}` | 注册树根并递归渲染节点：`node` 为 `{ path, pos, index, key, depth, children }`（叶子节点的 `children` 为 `null`）。节点里 `useTreeField()` 读当前节点的 `path` / `pos` / `index` / `record`，并带上这棵树的增删、`move` 和 `dragProps()`。节点外拿整棵树用 `useTreeField(name)` |
| `<Field name ui="echo">` / `<UI name component decorator …>` | 同一字段的第二个 UI（`d.x.$ui('echo')`）/ 不带值的 UI 节点（`d.$ui(name)`），见 [命名 UI 节点](/guide/ui) |
| `<Watch select>{(value) => …}` | `useWatch` 的渲染形式 |

`<Field>`、`<ObjectField>`、`<ArrayField>`、`useField` 不写泛型时接受任意字符串（动态路径的出口）。要按表单类型检查名字，用 [`typed(form)`](/reference/react-hooks#typed) 拿到同一组组件的有类型版本：`<F.Field name="emial">` 编译不过，`ArrayField` 的每一行再给一组按行类型检查的 `row.Field`。可复用的字段片段是普通组件，放在 `<ObjectField>` 里，用 `typed<Address>()` 按片段自己的类型检查。名字在运行时始终相对当前作用域。

## 联动

```ts
const effects = defineEffects<Values>(({ reaction, watch, draft, query }) => {
  reaction((d) => { … })
  reaction.each(draft.items, (row, ctx) => { … }) // 路径 handle；selector (d) => d.items 仍可用
  watch(draft.city, (d) => { … })                 // 监听 city.$value
  watch([draft.a, draft.b], (d) => { … })         // 多个 $value
  watch.each(draft.items, (row, ctx) => { … })
  query(pathOf('menus', pos)).$disabled = true    // 路径是字符串时
})
```

| API | 触发 | 说明 |
|---|---|---|
| `reaction(effect)` | 立即运行；之后读到的 `$` 状态变化时 | 同步派生；写 `$value` 的字段成为计算字段，默认仍提交 |
| `reaction.each(draft.items, effect)` | 普通对象按自有可枚举字符串键逐个建立实例；数组按元素建立实例，并进入嵌套的对象数组 | 路径在注册时取一次。selector `(d) => …` 仍可用，每轮重读，用来跟随会变的键。只有两个参数。用 `ctx.key` / `ctx.depth` 过滤 |
| `watch(draft.city, effect)` / `watch(fn, effect)` | 监听目标读取的 `$` 状态变化后执行；首次不运行 | `watch(draft.city, …)` 与 `watch((d) => d.city.$value, …)` 相同，`watch([draft.a, draft.b], …)` 监听任一 `$value`。函数 `fn` 在内部读取的**任意 `$` 状态变化时触发（不按 `fn` 返回值去重比较**，例如 `d.amount.$value > 100` 在 `amount` 从 `10` 变 `20` 时仍触发），每次触发还会重新追踪 `fn` 的读取，因此能跟随动态键（`d.extra[d.activeKey.$value].$value`） |
| `watch.each(draft.rows, effect)` | 遍历数组元素与嵌套对象数组；回调里读到的状态就是来源 | 某个元素变化只触发它自己。selector 形式仍可用 |
| `query(path)` | — | 路径已经是字符串时的无类型 handle（`pathOf`、配置、props，如 `rowsPath`）。能写在 draft 上的路径用 `d.a.b`、`d.items[i]`、`d.extra[key]` |

行级回调都是 `(row, ctx)`，`ctx` 含 `d`、`key`、`index`、`depth`、`parent`、`path`、`pos`。详见 [联动](/guide/linkage)；`$` 状态与显隐见 [核心概念](/guide/concepts)，规则见 [校验](/guide/validation)。

## 引擎工具（`@shikiform/core`）

联动、组件都用不到它们；写自己的树组件或做组合选择时才需要。全部是纯函数，不依赖 React。

```ts
// 树坐标：pos 是下标路径（[0, 2] = 第 1 个节点的第 3 个子节点）
pathOf(root: string, pos: Pos, childrenKey = 'children'): string          // pathOf('menus', [0, 2]) → 'menus.0.children.2'
posOf(root: string, path: string, childrenKey = 'children'): Pos | undefined
moveNode(nodes: any[], from: Pos, to: Pos, childrenKey?, canMove?, messages?): TreeMoveResult  // 不改原数组；to 是移动后的坐标

// 组合选择
comboMatch(table, selection): boolean                                     // 组合表里是否有一行满足所有已选维度
comboOptions(table, selection, dim, { disabledWhen? }?): ComboOption[]    // 其余维度已选时，dim 还能选哪些值
```

`moveNode` 的拒绝原因（移到自己的子树里、坐标不存在）走表单 `messages`（`treeIntoSelf` …）。树句柄 `useTreeField(name).move` 和节点上的 `useTreeField().move` 返回的 `reason` 用的就是它。组合表的完整例子在 [示例 · 联动](/examples/linkage)。外部校验库直接传给 `rules` / `validate`（Standard Schema），不需要额外的工具函数。

## 错误类与文案

```ts
class ShikiUsageError extends Error      // 开发期写法错误：修改 getValue 的只读视图、同一轮读回刚写的旗标、把 handle 当数组、拼错 $ 状态、
                                         // 未知规则键（minLenght）、component={[undefined]}、<ArrayField> 用在非数组上…；消息里写了正确写法
class ShikiCycleError extends Error      // reaction / watch 10 轮仍未收敛；cycle: readonly string[] 是互相触发的链
class ShikiConflictError extends Error   // 开发期：两个 reaction 写了同一个 $ 状态；state、first、second 指出是谁
class SubmitSupersededError extends Error // submit 被后一次 submit 取代；code = 'superseded'
class SubmitUnstableError extends Error   // 值连续 3 轮没稳定，不是被取代；code = 'unstable'
function isFieldErrors(value): value is FieldError[]  // validate / submit 失败时 reject 的就是这个数组

zhCN / enUS: FormMessages                // 内置文案（默认 zhCN）
setDefaultMessages(messages: Partial<FormMessages>): void   // 全应用默认，部分覆盖
getDefaultMessages(): FormMessages       // 当前的全应用默认（setDefaultMessages 之后的结果）
```

`ShikiCycleError`、`ShikiUsageError`、`ShikiConflictError`、`SubmitSupersededError`、`SubmitUnstableError` 和 `isFieldErrors` 都从 `@shikiform/react` 和 `@shikiform/core` 导出。错误类可以 `instanceof` 判断。`SubmitSupersededError`（`code: 'superseded'`）是被后一次提交取代。`SubmitUnstableError`（`code: 'unstable'`）是值连续 3 轮没稳定，不是被取代；`<Form>` / `<Submit>` 把它交给 `onSubmitError`。两者都不要和 `FieldError[]` 混在一起，用 `isFieldErrors` 区分校验失败。`ShikiCycleError` 在生产构建里也会抛（联动循环触发）；`ShikiUsageError` 和 `ShikiConflictError` 只在开发构建检查。开发构建里，冲突和循环的消息逐个列出涉及的 reaction：声明位置（`文件:行:列`）、它读了哪些状态、写了哪些状态。两个写者的冲突改成一个写者，或把动作移到 `watch`。文案的优先级是规则自己的 `message` > 表单 `messages` > `setDefaultMessages` > `zhCN`，见 [内置文案与国际化](/guide/validation#内置文案与国际化)。
