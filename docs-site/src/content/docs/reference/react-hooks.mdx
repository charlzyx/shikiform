从 `@shikiform/react` 导入，不依赖 antd。用法见 [Headless Hooks](/guide/headless)。

| 要做什么 | Hook | 是否订阅 |
|---|---|---|
| 创建并保留表单 | [`useForm`](#useform) | 不自动订阅值 |
| 按表单类型检查字段名 | [`typed`](#typed) | 不订阅（返回有类型的组件和 Hooks） |
| 取得上层表单 | [`useFormContext`](#useformcontext) | 不自动订阅值 |
| 跟随表单语言的内置文案 | `form.message(key)` / [`useFormContext`](#useformcontext) | 不订阅 |
| 绑定一个输入；无参时读当前字段（自定义控件、装饰器、单元格） | [`useField`](#usefield) | `useField(name)` 订阅该路径；`useField()` 不另订阅（随外层 Field 渲染） |
| 标签、必填、描述、错误（自己的 UI 库） | [`useFieldDecorator`](#usefielddecorator) | 不另订阅（随外层 Field，或随传入的 binding） |
| 提交 / 重置按钮 | headless [`<Submit>`](#submit) / [`<Reset>`](#reset) | 只订阅 `$canSubmit` / `$submitting`（Reset 不订阅值） |
| 读取选中的值或状态 | [`useWatch`](#usewatch) | selector 实际读取的 `$` 依赖 |
| 数组行增删、排序和拖动（`dragProps`）；可传 name，也可取最近一层 | [`useArrayField`](#usearrayfield) | 数组结构，不是每个单元格 |
| 行内取最近的数组 / 行号 / 行值（无需 name） | [`useArrayField`](#usearrayfield)、[`useIndex`](#useindex)、[`useRecord`](#userecord) | 数组结构 / 不订阅 / 这一行的值 |
| 最近一层数组自己的错误（不含子字段） | [`useArrayField().errors`](#usearrayfield) | 只订阅该数组路径 |
| 树的增删、移动和拖动（`dragProps`）；可传 name，也可取最近一层 | [`useTreeField`](#usetreefield) | 树结构 |
| 当前树节点的 path / pos / index（无需 name） | [`useTreeField()`](#usetreefield) | 这个节点的值 |

除 `useForm` 外，本页 Hooks 都必须在 `<Form form={form}>` 后代中调用。**在一个组件中先调用 `useField`、再从它返回 `<Form>` 不算在 Provider 内**；把读字段的组件放到 Form 里面。

`useField(name)` 需要名字；不带参数的 [`useField()`](#usefield) 就是当前字段（与 Formily `useField()` 相同）。[`useArrayField(name?)`](#usearrayfield) 传了名字就解析那一条数组，不传就取最近一层。[`useTreeField(name)`](#usetreefield) 解析那棵树；不传名字的 [`useTreeField()`](#usetreefield) 只在树节点里用，返回当前节点并带上这棵树的增删和移动。[`useIndex()`](#useindex) / [`useRecord()`](#userecord) 不需要名字。`<Field>`、表格单元格里的 `<Field>` 都用无参 `useField()`，只有这一种写法。

## useForm

```ts
useForm<T>(options?: UseFormOptions<T>): FormInstance<T, T>        // 省略 options 等同 {}；提交类型就是 T
useForm<T, TSubmit>(options?): FormInstance<T, TSubmit>            // 第二个类型参数照写
typed<T>().useForm(options?): FormInstance<T, …>                   // 写了 T 仍按 fields 推断提交类型

interface UseFormOptions<T> extends FormOptions<T> { values?: T }
```

| 参数 / 返回 | 含义与默认 |
|---|---|
| `options` | 省略等同 `{}`；除 `values` 外仅第一次渲染读取 |
| `options.initialValues` | 省略时以空对象开始；建议完整写出值形状，让 `T` 可推断 |
| `options.values` | 外部拥有的数据（加载的记录、查询缓存）。第一次渲染当作初始值；之后内容变化时调 `reset(values)`（新基线，不 dirty）。内容相同的新对象不触发 |
| `TSubmit` | `submit` / `getSubmitValues` / `<Form onSubmit>` 的值类型。不写泛型或 `typed<T>().useForm(options)` 时，`fields` 里的 `omit: true` 变成可选；`useForm<T>(options)` 的提交类型就是 `T`。要自己列路径用 `SubmitValues<T, 'tmp'>`，见 [提交值类型](/api#提交值类型) |
| 返回值 | 稳定的 `FormInstance<T, TSubmit>`：状态 getter、`getValue` / `setValue` / `batch`、`submit` / `validate` / `reset`、`setErrors` 和订阅，见 [API 总览](/api#读写和提交)。数组和树的增删移动用 `useArrayField` / `useTreeField` |

`useForm` 本身不要求父级 Provider。后续渲染传入新 `initialValues` 不会重建实例，也不会生效；会变的数据用 `values`，或自己调 `reset(record)`。渲染需要实时值时用 `useField` / `useWatch`，不要期待读取 `form.values` 就自动重渲染。

完整选项、校验默认触发器和提交返回值见 [创建表单](/api#创建表单)。非 React 环境用 `createForm`。


内置文案用 `form.message(key, params)`（或 `useFormContext().message`）。解析顺序是这张表单的 `messages` → `setDefaultMessages` → `zhCN`。key 列表见 [内置文案](/guide/validation#内置文案)。


## typed

```ts
typed<T>(form: FormInstance<T>): TypedForm<T>       // 一张表单
typed<T, TRoot = T>(): TypedForm<T, TRoot>          // 没有实例时（行组件、可复用片段）

type TypedForm<T> = {
  Field, ObjectField, ArrayField        // name 按 T 检查；行 / 对象拿到按自身类型检查的同一组组件
  useField(name: FieldPath<T>, options?): FieldBinding<PathValue<T, name>>
  useArrayField(name: ArrayPath<T>, opts?: { rowKey?: string }): ArrayHandle<行类型>
  useWatch<S>(select: (d: Draft<TRoot>) => S): S
  Watch: <S>(props: { select: (d: Draft<TRoot>) => S; children: (value: S) => ReactNode }) => ReactNode
  createForm(options?), useForm(options?)   // T 已固定，fields 里的 omit: true 仍变成可选
}
```

普通的 `<Field>` / `useField` / `<ArrayField>` / `<ObjectField>` 读的是 React 上下文，拿不到表单的类型，所以不写泛型时 `name` 是任意字符串。`typed(form)` 返回**同一批组件和 Hooks**，只是带上了表单的类型：拼错的名字编译不过，`value` 有具体类型，`useWatch` 不用注解 `d`。

```tsx
const form = useForm({ initialValues: { email: '', items: [{ id: 1, name: '' }] } })
const F = typed(form)

<Form form={form}>
  <F.Field name="email" />                       {/* 'emial' 编译不过 */}
  <F.ArrayField name="items" rowKey="id">
    {(row) => <row.Field name="name" />}         {/* 按一行检查，绑定 items.<i>.name */}
  </F.ArrayField>
  <F.ObjectField name="profile">
    {(obj) => <obj.Field name="city" />}         {/* 按 profile 检查 */}
  </F.ObjectField>
  <F.Watch select={(d) => d.$canSubmit}>{(ok) => <button disabled={!ok}>提交</button>}</F.Watch>
</Form>
```

规则只有一条：**名字相对当前作用域**，类型也跟着作用域走。根上用 `F.*`，`ArrayField` 的行里用 `row.*`，`ObjectField` 的函数子节点里用 `obj.*`。在 `items.0` 行里写 `items.0.name` 会在开发环境抛 `ShikiUsageError`（它会被拼成 `items.0.items.0.name`）。

`<ObjectField name="group">` 里写 `F.Field name="group.inner"` 是同一个坑，而且类型检查能过：`F.Field` 按整张表的类型看，`group.inner` 确实存在。运行时名字相对 `group` 再拼一次，变成 `group.group.inner`。开发环境在拼出来的路径没有值、而从根上读 `group.inner` 有值时抛 `ShikiUsageError`。

```tsx
const F = typed(form)

// ✗ 类型能过，运行时 ShikiUsageError：解析成 group.group.inner
<F.ObjectField name="group">
  <F.Field name="group.inner" />
</F.ObjectField>

// ✓ 函数子节点拿到按这一层对象检查的 obj.Field，名字相对 group
<F.ObjectField name="group">
  {(obj) => <obj.Field name="inner" />}
</F.ObjectField>
```

普通 `<Field name="inner">` 也是相对路径。见 [数据结构](/guide/structures#作用域里的名字不要带前缀)。

- 行组件里没有表单实例：`const Row = typed<RowValue>()`，`Row.useField('price')` 按行检查。它的 `useWatch` 仍读根 draft，需要类型时写 `typed<RowValue, Values>()`。
- 可复用片段（地址块、联系人块）就是普通组件：`const A = typed<Address>()`，组件里写 `<A.Field name="city" …/>`，用的地方 `<ObjectField name="home"><AddressFields /></ObjectField>`。同一个片段放在不同的 `ObjectField` 里就绑定不同的路径；需要额外参数就是普通 props。
- 需要动态字符串（列定义、后端下发的路径）时继续用普通组件，`useField(name)` 返回 `FieldBinding<any>`。
- `<F.Field enum>` / `row.Field` 的 `enum` 按字段值检查选项的 `value`（数组字段按元素类型）。
- `typed` 没有新的运行时：同一个表单多次调用返回同一个对象。`typed<Values>().useForm({ fields })` / `typed<Values>().createForm({ fields })` 就是 `useForm` / `createForm`，只是 `Values` 已经写上，`fields` 里的 `omit: true` 仍会变成可选。


## useFormContext

```ts
useFormContext<T = any>(): FormInstance<T>
```

无参数。返回最近 `<Form>` 提供的同一个引擎；缺少 Provider 时抛错，不会偷偷创建表单。

`T` 是调用者对已有实例的类型说明，不做运行时转换。它不订阅字段值或 `submitting`，适合按钮事件里调用 `reset`、`submit`。要显示实时提交状态，配合 `useWatch`。

这是顶层公开 Hook；`useScope` 只是内部实现，不是 `@shikiform/react` 顶层导出。


## useField

```ts
useField<TValue = any>(): FieldBinding<TValue>        // 无参：当前字段
useField(name: string, options?: UseFieldOptions): FieldBinding<any>
useField<TScope>(
  name: FieldPath<TScope>,
  options?: UseFieldOptions
): FieldBinding<PathValue<TScope, FieldPath<TScope> & string>>
useField<TScope, N extends FieldPath<TScope>>(
  name: N,
  options?: UseFieldOptions
): FieldBinding<PathValue<TScope, N & string>>

interface UseFieldOptions<TValue = any> {
  ui?: UiName                    // 同一字段的另一个 UI 实例：d.x.$ui(ui)，见下文「UI 实例」
  enum?: FieldEnum<TValue>       // [{ label, value }] | 原始值数组 | SomeEnum.with(params)；挂载期生效
  rules?: RulesInput
  required?: boolean
  visible?: boolean              // false 不渲染；仍提交，除非 omit。继承，显式 false 退出
  disabled?: boolean             // 置灰。继承，显式 false 退出。跳过校验
  readOnly?: boolean             // 渲染预览，优先于 disabled。继承，显式 false 退出。跳过校验
  omit?: boolean                 // 不提交。从祖先继承；父级为 true 时子级 false 不能单独提交
  // UI 状态（渲染期的 JSX 层，不写进模型；reaction 的 $title / $componentProps 优先，fields 声明在下）
  title?: ReactNode
  description?: ReactNode
  component?: FieldSlot | RegisteredComponentSlot
  // Component、[Component, props]，或登记名 "Input" / ["Input", props]。props 是 JSX 层的 componentProps
  decorator?: FieldSlot | RegisteredDecoratorSlot | false
  // 同上。false 不用 <Form kit> / <FieldKit> 的默认装饰器
}

// <Field> / typed(form).Field / row.Field / <UI> 上，元组的 props 按组件检查（全部可选，字段会给 value / onChange；
// 允许 data-* 属性）。hook 的 options 和 fields 声明里是不带参数的 FieldSlot，不检查。
type FieldSlot<C extends ComponentType<any> = ComponentType<any>> =
  | C
  | readonly [C]
  | readonly [C, (Partial<ComponentProps<C>> & { [key: `data-${string}`]: unknown }) | undefined]
```

`options` 与 `<Field>` 同名属性语义相同：`rules` / `required` / `enum` 是挂载期 lease（调用组件卸载时释放；`enum` 的优先级是 reaction `$enum` > JSX > `fields` > 条目模板，reaction 写 `$enum = undefined` 回到 JSX 这一层，属性变化（深比较）会重新应用），`visible` / `disabled` / `readOnly` / `omit` 是持久字段标记，UI 选项合并进返回的 binding。`<Field>` 就是 `useField(name, options)` 加上「`visible` 为 false 时返回 null」。再渲染 `decorator` 包住的 `component`，并把 binding 提供给子树里不带参数的 `useField()`。

带 `name` 时，它是当前对象 / 行作用域下的**相对路径**。例如在 `items.0` 的行作用域（`<ArrayField>` 的第 0 行）下，`useField('price')` 绑定 `items.0.price`。在行里再写 `items.0.price` 会重复前缀；稳定行 ID 也不是路径。

| 写法 | 类型效果 |
|---|---|
| `useField('price')` | 动态路径可用，值是 `any` |
| `useField<Row>('price')` | 检查路径存在，但值类型是各可选路径值的联合 |
| `useField<Row, 'price'>('price')` | 检查路径，值精确为 `Row['price']` |

`FieldBinding`、`FieldPath`、`PathValue` 都可从 `@shikiform/react` 导入（`FieldPath` / `PathValue` 在 `@shikiform/core` 里是同一个类型）。

### 返回的 FieldBinding

| 属性 | 类型与用途 |
|---|---|
| `path` / `id` | `string`；完整数据路径 / 给 label 的 DOM id。在 `<Form>` 里 id 带表单前缀（`<Form id>`，没传则 React `useId()`）加净化路径：`user.name` → `<前缀>-user-name`。引擎 `binding().id` 不含前缀 |
| `value` | 当前路径值，类型由上述泛型决定 |
| `onChange(value)` | `(value: TValue) => void`；写入值，不接收 DOM event |
| `onBlur()` | `() => void`；标记 touched，并按配置触发校验 |
| `errors` / `warnings` | `string[]`；交给 UI 展示 |
| `visible` / `disabled` / `readOnly` / `omit` | `boolean`。四个都是沿字段路径算出的有效值。前三个显式 `false` 可退出；`omit` 任一祖先为 `true` 则子孙为 `true` |
| `required` | `boolean`；有效必填 |
| `touched` / `dirty` / `edited` / `validating` | `boolean`；失焦过、值与初始值不同（改回即 `false`）、用户编辑过（粘滞）、异步校验中 |
| `options` / `loading` | 枚举选项数组 / 枚举加载状态 |
| `title` / `description` | 装饰器的标题 / 说明（`FormItem` → `label` / `extra`）：reaction > JSX > `fields` |
| `component` / `decorator` | `<Field>` 渲染的控件 / 装饰器组件 |
| `componentProps` / `decoratorProps` | 合并后的控件 / 装饰器 props（`fields` ← JSX ← `$componentProps` / `$decoratorProps`，深合并） |
| `ui` | 仅 UI 实例有：实例名（`<Field ui="echo">`） |

`useField` 订阅该路径并注册基础字段模型，但**不会替你渲染或隐藏输入**。自定义 UI 看 `visible`：`false` 不画。`readOnly` 时画预览。需要 JSX `rules`、`required` 生命周期时传 `options`（或用 `<Field>`）。`visible: false`、`disabled`、`readOnly` 都跳过校验并清错，值仍提交，除非 `omit`。见 [四个布尔](/guide/concepts#四个布尔) 和 [未挂载规则](/guide/validation)。

### 无参 useField：当前字段

`useField()` 不带参数时，返回最近的 `<Field>` 正在渲染的字段 binding，与 Formily 的 `useField()` 一样。自定义控件、装饰器、表格单元格里的输入都用它，不用重复写 `name`；`useField<string>()` 给 `field.value` 定类型。

```tsx
function TextInput() {
  const field = useField<string>()
  return <input value={field.value ?? ''} onChange={(e) => field.onChange(e.target.value)} onBlur={field.onBlur} />
}
function MyDecorator({ children }: { children?: ReactNode }) {
  const field = useField()
  return <label>{field.title}{field.required ? ' *' : ''}{children}<small>{field.errors[0]}</small></label>
}
<Field name="email" title="邮箱" decorator={[MyDecorator]} component={[TextInput]} />
<Field name="phone"><TextInput /></Field>   {/* 作为子元素也一样 */}
```

- 不在任何 `<Field>` 内调用时抛出 `ShikiUsageError`，消息写明修法：放进 `<Field name="…">`，或改成 `useField('email')`。
- 它不另外订阅：值随外层 `<Field>` 重新渲染。只想在 Hook 里绑定一个字段时，直接 `useField('email', options)`；要把这个 binding 交给 connect 控件，传 `field` 属性（`<Input field={field} />`）。
- 同一调用处要么总带 `name`，要么总不带（两种形式使用不同的 Hooks）。

### UI 实例：`useField(name, { ui })` / `<Field name ui>`

同一个字段要显示成多个 UI（输入框 + 回显、滑块 + 数字框）时，第二个起带 `ui` 名。它们共享值、错误、规则、选项；各自有 `visible` / `disabled` / `readOnly` / `title` / `description` / `componentProps` / `decoratorProps`，在 effects 里是 `d.x.$ui(name)`。

```tsx
<Field name="amount" title="金额" decorator={[FormItem]} component={[InputNumber]} />
<Field name="amount" ui="slider" component={[Slider]} />           // d.amount.$ui('slider').$disabled = true
const field = useField('amount', { ui: 'slider' })                  // 同上的 Hook 写法
```

- 返回的 binding：`value` / `onChange` / `errors` / `required` / `options` 是字段的；`visible` / `disabled` / `readOnly` 和其余 UI 状态是实例的；`id` 是带表单前缀的 `<前缀>-<净化路径>--<ui>`（`<Form id="edit">` 下的 `amount` / `slider` 为 `edit-amount--slider`），label 不会指错；`ui` 是实例名。实例里的无参 `useField()` 返回这份 binding。
- 优先级：reaction（`$ui(name).$disabled`）> JSX（实例上的 `disabled` / `componentProps` …）> 回退。回退：`visible` / `disabled` / `readOnly` 取字段的有效值（字段继承根上的同名开关，实例也跟着）；`title` / `description` 取字段的声明 + reaction 值；`componentProps` / `decoratorProps` 不回退（是另一个组件的）。
- 实例**不**登记 JSX `rules` / `required` / `enum` / `omit`（开发期警告一次）：这些写在不带 `ui` 的 `<Field>` 上。
- 名字类型：默认任意字符串；在 `UiNames` 里登记后 `ui` / `<UI name>` / `$ui()` 都检查拼写（见 [UI 节点](/guide/ui#名字的类型)）。


## UI 组件（`<UI>`）

不是 Hook，列在这里因为它和 `useField(name, { ui })` 是一套：没有值的 UI 节点，在 effects 里是 `d.$ui(name)`（在行 / `<ObjectField>` 里是该作用域的 `row.$ui(name)`）。

```tsx
interface UIProps<C, D> {
  name: UiName
  component?: FieldSlot<C>        // [Alert, { type: 'warning' }]；children 渲染在它里面；props 按 Alert 检查
  decorator?: FieldSlot<D>        // [FormItem]：title → label，description → extra
  title?: ReactNode
  description?: ReactNode
  visible?: boolean               // false 隐藏；没写则回退到所在作用域
  disabled?: boolean
  readOnly?: boolean              // 渲染预览；没写则回退到所在作用域
  children?: ReactNode | ((ui: UiBinding) => ReactNode)
}
<UI name="approvalTip" component={[Alert, { type: 'warning', message: '需要审批' }]} />
reaction((d) => { d.$ui('approvalTip').$visible = d.amount.$value >= 50000 })
```

- 永远不进 `values` / 提交 / 校验。`$visible` / `$disabled` / `$readOnly` / `$title` / `$description` / `$componentProps` / `$decoratorProps`，读取是依赖。
- **隐藏不级联**：`<UI>` 隐藏时不渲染子元素，但里面字段的 `$visible`、校验、提交都不变。要藏字段再写字段自己的 `$visible = false`（值仍提交）；不提交再写 `$omit = true`。
- reaction 写了一个从没挂载过的 `$ui(name)`（拼错、忘了渲染）：挂载稳定后开发期警告一次，列出这个路径上已挂载的名字。


## useWatch

```ts
useWatch<T = any, S = unknown>(select: (draft: Draft<T>) => S): S
```

| 参数 / 返回 | 契约 |
|---|---|
| `select` | 必填同步 selector；读取 `$value`、`$errors`、`$submitting` 等状态并返回数据，不在里面写值或执行副作用 |
| 返回值 | selector 的结果 `S`；没有额外包装对象 |
| 依赖 | 自动跟踪本轮读到的 `$` 状态；分支变化后调整订阅 |

优先用 [`typed(form).useWatch((d) => d.name.$value)`](#typed)（`string`）。不注解时 `useWatch((d) => d.$submitting)` 可以编译，`d` 是 `any`，返回值也是 `any`。要给裸 `useWatch` 标表单类型，写成 `useWatch<Values>()((d) => d.name.$value)`：草稿是 `Draft<Values>`，返回值仍会推断。`useWatch<Values>(...)` 只写一个泛型时 TypeScript 不再推断返回值（它是 `unknown`），不要这样写。注解 `useWatch((d: Draft<Values>) => d.name.$value)` 也可以。

返回对象/数组可用，快照通过 `Object.is` / 深比较复用；不要返回每次新建的函数。没有读到任何 `$` 依赖时会退回整表通知，因此它不适合作为“零订阅”的替代品。

`useWatch` 是 React 中的读取/渲染；effects 里的 `watch(source, effect)` 是值变化后的动作，两者不是同一 API。参见 [联动](/guide/linkage)。


### 完整例子：一个绑定、一个 selector、一个操作按钮

```tsx preview
import { Form, useField, useForm, useFormContext, useWatch, type Draft } from '@shikiform/react';

type Values = { name: string };

function NameInput() {
  const field = useField<Values, 'name'>('name');
  if (!field.visible) return null;
  if (field.readOnly === true) return <p>姓名：{field.value}</p>;
  return (
    <label htmlFor={field.id}>
      姓名
      <input id={field.id} value={field.value} disabled={field.disabled} readOnly={field.readOnly}
        onChange={(event) => field.onChange(event.target.value)} onBlur={field.onBlur} />
      <span role="status">{field.errors.join('；')}</span>
    </label>
  );
}

function Greeting() {
  const name = useWatch((d: Draft<Values>) => d.name.$value);
  return <p>你好，{name || '还没有填写姓名'}</p>;
}

function ResetName() {
  const form = useFormContext<Values>();
  return <button type="button" onClick={() => form.reset('name')}>恢复初值</button>;
}

export default function HookExample() {
  const form = useForm({ initialValues: { name: 'Ada' }, fields: { name: { required: true } } });
  return <Form form={form}><NameInput /><Greeting /><ResetName /></Form>;
}
```

## useArrayField

```ts
useArrayField<TRow = unknown>(): ArrayHandle<TRow>
useArrayField(name: string, opts?: { rowKey?: string }): ArrayHandle<unknown>
useArrayField<TScope>(name: ArrayPath<TScope>, opts?: { rowKey?: string }): ArrayHandle<unknown>
useArrayField<TScope, N extends ArrayPath<TScope>>(
  name: N, opts?: { rowKey?: string }
): ArrayHandle<ArrayItemOf<TScope, N & string>>
```

一个 Hook。不传 `name` 时取最近一层 `<ArrayField>`（Formily `ArrayBase.useArray`：行、容器、工具栏都算；嵌套取最近的一层；不在数组里抛错）。传了 `name` 就按当前 scope 解析这条数组，并把路径登记进最近的字段组。

`ArrayHandle` 类型可从 `@shikiform/react` 导入，调用方通常直接用返回值推断。`ArrayPath` 从 `@shikiform/core` 导入，`ArrayItemOf` 也可从 `@shikiform/react` 导入。

| 参数 | 作用 / 默认 |
|---|---|
| `name` | 省略 = 最近一层数组。传入时是相对当前 scope 的数组路径 |
| `opts.rowKey` | 可选行标识属性名；省略时使用行的 `id`，没有 ID 的对象行使用对象身份。业务数据建议明确提供唯一稳定 ID |

返回 `{ path, keys, push, insert, remove, move, swap, replace, dragProps }`：

| 成员 | 签名 / 含义 |
|---|---|
| `path` | `string`，完整数组路径 |
| `keys` | `{ key: string; index: number }[]`；`key` 给 React，`index` 用于路径 |
| `push(row)` | 追加一行 → `void` |
| `insert(index, row)` | 在指定下标插入 → `void` |
| `remove(index)` | 删除一行 → `void` |
| `move(from, to)` | 移动到**最终下标** `to` → `void` |
| `swap(a, b)` | 交换两个下标 → `void` |
| `replace(index, row)` | 替换一行 → `void` |
| `errors` / `warnings` | 这一层数组自己的消息，不含子字段 |
| `dragProps(index)` | 这一行的原生 HTML5 拖动属性 `{ draggable, onDragStart, onDragOver, onDrop }`：展开到行上（既是拖动源也是放置目标），或把 `onDragOver` / `onDrop` 给行、`draggable` / `onDragStart` 给把手。把 A 行放到 B 行上 = `move(A, B)` |

写全 `useArrayField<Values, 'items'>('items')` 才能同时检查数组路径和行值类型；只写一个泛型时行操作参数为 `unknown`。

它只订阅结构（长度/顺序/行身份），不会因为单元格编辑就更新整个列表。单元格另用 `useField`，汇总另用 `useWatch`。不要原地修改返回的数组或 `getValue` 引用来代替操作方法。需要为每行提供相对路径作用域时直接使用 `<ArrayField>`。

`dragProps` 函数对同一数组路径保持同一个引用（拖动起点记在句柄内部），所以可以经 context 交给 `memo` 的行而不让它们重渲染；没有隐藏的拖拽库，把手、键盘和触屏交互由应用决定。事件没有 `dataTransfer` 时用句柄记下的起点。

## 数组句柄上的 errors

`errors` / `warnings` 是这一层数组**自己**的校验消息：写在这条数组路径上的规则、字段 schema、`form.setErrors`。子字段的消息不在里面（那些在行内 `FormItem` / `useField().errors` 上）。`d.items.$errors` 会把子孙字段的消息算进去，句柄不会。

只订阅该数组路径，改一个单元格不会让它重渲染。嵌套数组取最近的一层。

读它的组件必须渲染在 `<ArrayField>` 的子树里（容器，或容器里的 `footer` / 工具栏）。和 `<ArrayField>` 平级时 `useArrayField()` 抛 `ShikiUsageError`。行 children 里调用也在作用域内，但数组为空时行函数不执行，有多行时每行各画一次。数组这一层的提示放在容器上。`ArrayTable` 不画这条反馈，交给它的 `footer`（仍在 `<ArrayField>` 内）。

`ArrayItems` / `ArrayCards` 用它画反馈行。自己画时：

```tsx
import type { ReactNode } from 'react'
import { ArrayField, useArrayField } from '@shikiform/react'
import { ArrayTable, type ArrayTableColumn } from '@shikiform/antd'

function ListError() {
  const { errors, warnings } = useArrayField()
  const messages = errors.length ? errors : warnings
  if (!messages.length) return null
  return <p role="alert">{messages.join('、')}</p>
}

function MyList({ children }: { children?: ReactNode }) {
  return (
    <div>
      {children}
      <ListError />
    </div>
  )
}

const columns: ArrayTableColumn[] = [{ key: 'name', title: '名称', render: () => null }]

// ✓
function Correct() {
  return (
    <>
      <ArrayField name="tags" component={[MyList]}>{() => <span />}</ArrayField>
      <ArrayField name="list" component={[ArrayTable, { columns, footer: <ListError /> }]} />
    </>
  )
}

// ✗ 兄弟节点，渲染时抛 ShikiUsageError
function Wrong() {
  return (
    <>
      <ArrayField name="tags" component={[MyList]}>{() => <span />}</ArrayField>
      <ListError />
    </>
  )
}
```

已经显示的数组级错误，在 `push` / `insert` / `remove` / `move` / `swap` / `replace` 之后会重跑这一层规则（与改一个已经报错的输入相同）。改某一格不会重跑它。子字段要到下一次提交，或它们自己的校验时机，才校验。见 [数组自身的错误](/guide/arrays#数组自身的错误)。

## useIndex

```ts
useIndex(): number
```

当前行在数组中的下标（Formily `ArrayBase.useIndex`），来自外层 `<ArrayField>` 行作用域（`<ArrayField>` 的每一行与 `ArrayTable` 的单元格都会提供）。行移动后随新位置更新。不在行内时抛错。

```tsx
function RowNo() {
  return <span>第 {useIndex() + 1} 行</span>
}
```

## useRecord

```ts
useRecord<TRow = any>(): TRow
```

当前行的值（Formily `ArrayBase.useRecord`），**响应式**：这一行任一单元格变化都会重渲染，行移动后跟着行走；其他行的编辑不会唤醒它。不在行（或树节点）内时抛错。只读：要改值用 `useField` / 字段写入，不要修改返回的对象。

```tsx
function RowTitle() {
  const row = useRecord<{ name: string; qty: number }>()
  return <b>{row.name} × {row.qty}</b>
}
```


## useTreeField

```ts
useTreeField<TNode = unknown>(): TreeNodeHandle<TNode>   // 必须在 <TreeField> 的节点里
useTreeField(name: string, options?: { childrenKey?: string; rowKey?: string }): TreeHandle<unknown>
```

一个 Hook。句柄的 `path` 永远是它指向的东西，`treePath` 永远是树根。`useTreeField(name)` 按当前 scope 解析那棵树，`path` 和 `treePath` 都是树根，并把路径登记进最近的字段组。`useTreeField()` 不传名字时必须在 `<TreeField>` 的节点里：`path` 是当前节点，`treePath` 是树根，并带上 `pos`、`index`、`record`，以及这棵树的 `value`、`push`、`insert`、`remove`、`replace`、`move`、`dragProps`（`dragProps()` 不传坐标就指向当前节点）。两种句柄的 `errors` / `warnings` 都只算 `path` 这一层，不含子孙字段。不在节点里时抛错：开发构建是 `ShikiUsageError`，消息为 `useTreeField() must render inside a tree node (<TreeField>).`。

`<TreeField>` 在结构变化时重画。位置和子树都没变的兄弟，以及其他子树，沿用上一次的元素，不重新渲染。变了的是被移动的节点、坐标变了的节点，以及子树形状变了的祖先。`children` 渲染函数换了身份（父组件重渲染时写的内联函数）会把每个节点重画一遍。

`Pos` 是 `readonly number[]`，`MoveResult` 是 `{ ok: boolean; reason?: string }`，两者都从 `@shikiform/react` 导入。不传 name 时可以用 `useTreeField<Node>()` 标节点类型；传了 name 时返回的 `value` 是 `unknown[]`，按已知数据自行标注。

| 参数 / 返回 | 含义 / 默认 |
|---|---|
| `name` | 传入时是相对当前 scope 的树根路径，返回 `TreeHandle`。省略时必须在节点里，返回 `TreeNodeHandle` |
| `options.childrenKey` | 只在传入 `name` 时使用。优先用传入值；否则继承已有树配置，再默认 `'children'` |
| `options.rowKey` | 同上，默认 `'id'` |
| `path` | 句柄指向的路径。传了 `name`：树根。没传：当前节点 |
| `treePath` | 树根。树根句柄上和 `path` 相同 |
| `errors` / `warnings` | `path` 这一层自己的消息，不含子孙字段 |
| `value` | 当前根节点数组；当前值不是数组时返回 `[]`。不要原地修改 |
| `push(node, parentPos?)` | 追加到根，或作为 `parentPos` 的最后一个孩子。父节点没有 children 数组时会建一个 |
| `insert(pos, node)` | 插到 `pos`，后面的兄弟后移 |
| `remove(pos)` | 删掉这个节点，它的字段状态一起去掉 |
| `replace(pos, node)` | 换成另一个节点，旧节点的字段状态去掉 |
| `move(from, to)` | 使用移动后的最终索引坐标；拒绝移到自己的后代，失败看 `reason` |
| `dragProps(pos)` | 这个节点的原生 HTML5 拖动属性：拖到另一个节点上 = `move(源, 目标)`；拖动开始和放下都阻止冒泡，嵌套节点只处理自己。被拒绝的移动不提示，需要提示时自己调 `move` 看 `reason` |

字段状态跟着节点 id 走（没有 id 时移动仍改数据，但没有 id 可跟随）。`useTreeField` 与 `useField` / `useArrayField(name)` 一致：名字按当前 scope 解析（开发期名字重复 scope 前缀会抛 `ShikiUsageError` 并提示修法）。它只订阅树结构，不订阅每个节点的文字/勾选状态。节点编辑单独用 `useField`，读取选定值用 `useWatch`。要让 React 挂载前的树联动也认识自定义 `childrenKey`，在 `useForm({ trees: { ... } })` 里声明配置。

不传 name 时 `path` 是当前节点，`treePath` 是树根，`index` 是 `pos` 的最后一段（和 `useIndex()` 相同）。`errors` / `warnings` 是这个节点自己的消息。`dragProps()` 不传坐标指向当前节点。

```tsx
function MoveFirst() {
  const node = useTreeField<{ id: string }>()
  return <button type="button" onClick={() => node.move(node.pos, [0])}>移到最前</button>
}
```

`[0, 2]` 表示第一个根节点的第三个孩子，不是节点 ID。稳定 ID 用于移动时保持字段状态；不要用当前坐标代替业务 ID。

### 完整例子：同层拖动和显式移动结果

```tsx preview
import { useState } from 'react';
import { Form, useForm, useTreeField } from '@shikiform/react';

type Node = { id: string; title: string; children: Node[] };
type Values = { nodes: Node[] };

function Nodes() {
  const tree = useTreeField('nodes');
  const [message, setMessage] = useState('拖动节点，或用按钮移动第一个根节点。');
  // 当前 useTreeField 没有节点泛型；这里的类型来自本例已知的初始数据。
  const nodes = tree.value as Node[];
  const renderNodes = (rows: Node[], parent: number[] = []) => (
    <ul>{rows.map((node, index) => {
      const pos = [...parent, index];
      return <li key={node.id}><span {...tree.dragProps(pos)}>{node.title}</span>
        {node.children.length > 0 ? renderNodes(node.children, pos) : null}</li>;
    })}</ul>
  );
  return <section>{renderNodes(nodes)}
    <button type="button" disabled={nodes.length < 2} onClick={() => {
      const result = tree.move([0], [nodes.length - 1]);
      setMessage(result.ok ? '已移动' : result.reason ?? '没有移动');
    }}>第一个根节点移到最后</button>
    <p role="status">{message}</p>
  </section>;
}

export default function TreeHookExample() {
  const form = useForm<Values>({ initialValues: { nodes: [
    { id: 'a', title: '内容', children: [{ id: 'a1', title: '文章', children: [] }] },
    { id: 'b', title: '设置', children: [] },
  ] } });
  return <Form form={form}><Nodes /></Form>;
}
```

## useFieldDecorator

```ts
useFieldDecorator(options?: {
  field?: FieldBinding        // 默认：外层 <Field>
  label?: ReactNode           // 覆盖 field.title
  description?: ReactNode     // 覆盖 field.description
  asterisk?: boolean          // 强制星号；默认 field.required，readOnly 不显示
}): FieldDecorator
```

给自己的 UI 库画标签和错误，返回的是数据，不是 antd 的 `Form.Item` props。必须写在 `<Field>` 里，或传入 `useField(name)` 的 binding。

| 字段 | 含义 |
|---|---|
| `id` / `label` / `description` | 控件 id、标题、说明 |
| `required` | 要不要画星号（`readOnly` 默认不画） |
| `errors` / `warnings` / `error` | 全部错误、全部警告、第一条错误（Mantine 的 `error`） |
| `invalid` | `errors` 非空。只有警告不算 |
| `describedBy` | `aria-describedby` 用的 id，没有可指向的节点时是 `undefined` |
| `labelProps` | `{ id, htmlFor? }`。`readOnly` 不带 `htmlFor` |
| `descriptionProps` / `errorProps` / `warningProps` | 有内容才有。错误元素带 `role="alert"` |
| `control` | 控件自己画 label / error 时整包展开（`id`、`label`、`required`、`error`、`disabled`、`onBlur`、`aria-*`）。没有 `value` / `onChange`，这两项用 `useField()`。不要再叠到 `connect()` 过的控件上 |

```tsx
function FormItem({ children }: { children?: ReactNode }) {
  const d = useFieldDecorator()
  return (
    <div data-invalid={d.invalid || undefined}>
      <label {...d.labelProps}>{d.label}{d.required && <span>*</span>}</label>
      {children}
      {d.descriptionProps && <p {...d.descriptionProps}>{d.description}</p>}
      {d.errorProps && <p {...d.errorProps}>{d.errors.join('、')}</p>}
    </div>
  )
}

function MantineInput() {
  const field = useField<string>()
  const { control } = useFieldDecorator()
  return (
    <TextInput
      {...control}
      value={field.value ?? ''}
      onChange={(event) => field.onChange(event.currentTarget.value)}
    />
  )
}
```

## Submit

`<Submit>` 从 `@shikiform/react` 导入。三种外壳：默认 `<button>`（文案 `messages.submit`）、`asChild`（行为合并到唯一子元素）、render prop。不传 `onSubmit` 时是原生 submit，交给外层 `<Form onSubmit>`（回车同样提交），`$canSubmit` 为 false 时禁用，提交中显示 loading。传了 `onSubmit` 时点击自己跑 `form.submit`。`onClick` 先执行，`preventDefault` 会跳过这次自带的提交。`disabled` 覆盖「无效时不可点」；传 `false` 表示无效时仍可点。`@shikiform/antd` 的 `<Submit>` 是 antd `Button`，行为相同。

```tsx
<Submit asChild><button>保存</button></Submit>
<Submit onSubmit={saveDraft}>{(state) => <button type="button" disabled={state.disabled} onClick={state.onClick}>存草稿</button>}</Submit>
```


## Reset

`<Reset>` 从 `@shikiform/react` 导入，调用 `form.reset()`。`type` 固定 `'button'`，避免浏览器原生 reset 绕过 store。表单无效时仍然可点；`disabled` 只来自传入的选项。`onClick` 在重置前（读到的仍是旧值），`preventDefault` 跳过重置和 `afterReset`。`afterReset(values)` 在 `form.reset` 之后，参数已是重置后的值，查询页用它按清空后的条件再查。`asChild` / render prop 与 `<Submit>` 同一套外壳。antd 的 `<Reset>` 也接受 `afterReset` 和 `disabled`。

```tsx
<Reset afterReset={(values) => search(values)} asChild><button>重置</button></Reset>
```
