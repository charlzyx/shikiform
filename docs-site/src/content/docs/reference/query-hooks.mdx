从 `@shikiform/react` 导入，零 UI 库依赖：Hook 处理请求、分页、排序筛选和选择，视图层可自由接原生 `<table>` 或任意 UI 表格组件。完整场景见 [查询表](/play/query)。

## useQueryTable

三个公开重载按 `params` 的写法推断请求参数：

```ts
// 取一条字段路径：TParams = 该路径的值类型
useQueryTable<TValues, TRow, const P extends FieldPath<TValues>>(
  options: UseQueryTableOptions<TValues, PathValue<TValues, P & string>, TRow> & { params: P }
): QueryTableApi<TValues, PathValue<TValues, P & string>, TRow>

// 自己映射筛选值
useQueryTable<TValues, TParams, TRow>(
  options: UseQueryTableOptions<TValues, TParams, TRow> & { params: (values: TValues) => TParams }
): QueryTableApi<TValues, TParams, TRow>

// 省略 params：使用整个表单值
useQueryTable<TValues, TRow = unknown>(
  options: Omit<UseQueryTableOptions<TValues, TValues, TRow>, 'params'> & { params?: undefined }
): QueryTableApi<TValues, TValues, TRow>
```

`UseQueryTableOptions`、`QueryTableApi`、`QueryRequestArgs/Result`、`QueryHookArgs/Result` 都是本模块的类型导出；`FieldPath`、`PathValue` 从 `@shikiform/core` 导入。通常直接让 `initialValues`、`params` 和 `request` 推断，不需要手写三组泛型。空数组、空对象或联合字面量推断不准时，写成 `useQueryTable<Values>()({ initialValues, … })`：`Values` 检查 `initialValues`，行类型和 `params` 仍从参数推断。`useQueryTable<Values>(options)` 不会推断其余类型参数。

### 参数与默认

| 选项 | 默认 | 作用 / 边界 |
|---|---|---|
| `form` | 不传则创建表单 | 传入现有表单（`useForm` / `createForm` 的返回值）；这时不再用下面三项初始化它 |
| `initialValues`、`effects`、`fields` | 同表单创建选项 | 仅用于创建内部表单；后续渲染不重新初始化 |
| `params` | 整个 `form.values` | 字段路径，或把 values 映射为请求参数的函数；不是 `getSubmitValues()`，不要假定自动排除 `omit: true` |
| `page` | `'page'` | 页码字段路径；值不存在时初始化为 `1` |
| `pageSize` | `'pageSize'` | 页大小字段路径；值不存在时用 defaultPageSize |
| `defaultPageSize` | `10` | 缺失页大小时的默认值；已有字段值优先 |
| `selectedKeys` | `'selectedKeys'` | 选择字段路径；初始缺失时为 `[]`，读取时转换为 string[] |
| `mode` | `'server'` | server 模式由服务端分页；client 模式对请求结果的整个 data 做切片 |
| `validateOnSubmit` | `true` | 调用 `submit()` 时先校验筛选字段（`params` 为字段路径时仅校验该子树，避免行内编辑 `rows` 的错误阻塞搜索），校验未通过则跳过请求 |
| `request` | **必填** | 异步返回 `{ data, total, extra? }`，见协议 |
| `rows` | 不写回 | 数组字段路径：每页 `data` 写进这个字段并作为它的初始值，单元格可直接编辑 |
| `useQuery` | 内置 runner | 省略时用库内的最小请求实现（不从包入口导出）。可换成 TanStack Query 等兼容 Hook；每次渲染应传同一个 Hook，不要动态切换 Hook 实现 |

初始化时，client 的 page、pageSize 以及 selectedKeys 只从提交结果里拿掉（写上 `omit`），不改它们的 `visible`。server 的 page、pageSize 连这个都不写：调用方声明的 `visible: false` 保持不渲染。路径和模式等配置在同一实例生命周期内保持稳定。首次请求在 effect 中发起，SSR 不发送请求。

### 请求协议

```ts
interface QueryRequestArgs<TParams> {
  params: TParams;
  page: number;
  pageSize: number;
  sorter: { field: string; order: 'ascend' | 'descend' }[]; // 表头排序，未排序时 []
  filters: Record<string, (string | number | boolean)[]>;  // 表头列筛选，只含有选中值的列
  signal: AbortSignal;
}
interface QueryRequestResult<TRow, TExtra = unknown> {
  data: TRow[];
  total: number;
  extra?: TExtra; // 可选附加返回数据（如金额汇总、状态计数），通过 table.extra 读取
}
```

server 返回当前页 data 和未分页的 total；client 返回本次筛选下的完整 data，页面 total 使用 `data.length`。若服务端一并返回汇总统计信息，可放入 `extra`，无需在 `request` 内部手写外部 `setState`。把 signal 传给 fetch 等请求工具，才能实际取消网络工作；内置 runner 也会忽略已过期响应。

### 返回值与操作

| 返回成员 | 类型 / 行为 |
|---|---|
| `form` | 原表单实例，可以用正式 Field/Hook 接搜索控件 |
| `rows` | `rows` 选项的字段路径（没传为 `undefined`） |
| `data`、`total` | 当前页 `TRow[]`、总数；未取得数据时 `[]` / `0` |
| `extra` | `TExtra \| undefined`；最近一次成功响应返回的 `extra` 字段 |
| `loading` | 请求中且还没有旧数据时 true |
| `fetching` | 所有进行中的请求都为 true，包含保留旧结果的刷新 |
| `isPlaceholderData` | 是否正在展示兼容查询 Hook 标记的旧结果 |
| `page`、`pageSize` | 当前表单中的数值页码 / 页大小 |
| `selectedKeys` | `string[]`，跨页保留 |
| `submit(): Promise<void>` | 默认先校验筛选字段（`validateOnSubmit: false` 时跳过），校验通过后回第 1 页、清空选择并强制查询；校验未通过时不发起请求 |
| `reset(): void` | `form.reset()`，清空选择，再请求；建议初始页码设为 1 |
| `refresh(): void` | 保留已提交的筛选、当前页和选择，强制查询 |
| `setPage(page, pageSize?)` / `onPageChange(page, pageSize?): void` | 同一个函数：更新分页；未传 pageSize 沿用当前值。server 请求，client 只切片；`onPageChange` 用于直接透传给分页组件的 `onChange` |
| `setSelectedKeys(keys: string[]): void` | 更新选择，不触发请求 |
| `sorter`、`filters` | 当前表头排序 / 列筛选，与发给 `request` 的一致 |
| `setSorter(sorter): void` | 改排序：回第 1 页并请求；**保留选择**（结果集还是那些行） |
| `setFilters(filters): void` | 改列筛选：回第 1 页、**清空选择**并请求（结果集变了，旧选择可能指向看不见的行） |
| `onTableChange(pagination, filters, sorter, extra)` | 适配标准表格组件的 `onChange` 回调；`extra.action === 'paginate'` 时忽略（分页走 `onPageChange`），其余转成 `setSorter` / `setFilters`；值没变不请求 |
| `sortOrderOf(key)`、`filteredValueOf(key)` | 给受控列用的 `sortOrder` / `filteredValue`，`重置` 后表头随之清空（渲染期 getter） |

> 所有操作方法（`submit`、`reset`、`refresh`、`setPage` / `onPageChange`、`setSelectedKeys`、`setSorter`、`setFilters`、`onTableChange`）在组件生命周期内保持同一个引用，可直接放进 `useEffect` 依赖；返回值对象本身每次渲染新建，请依赖具体方法（如 `[table.refresh]`）而不要依赖 `table`。详见 [引用稳定性](/reference/react-hooks#引用稳定性)。

### 表头排序与列筛选

表格列的排序与筛选变化经 `onTableChange`（或直接调用 `setSorter` / `setFilters`）进入 Hook，再作为 `sorter` / `filters` 发给 `request`。排序和列筛选都回到第 1 页；列筛选和查询按钮一样清空选择，只翻页或只排序保留选择。`submit()` 保留当前排序和列筛选，`reset()` 一并清空。client 模式下排序 / 列筛选变化同样重新请求，由 `request` 返回排好、筛好的完整数据。

```tsx
const table = useQueryTable({
  initialValues: { query: {}, list: [] },
  params: 'query',
  rows: 'list',
  request: ({ params, page, pageSize, sorter, filters }) =>
    api.list({ ...params, page, pageSize, orderBy: sorter[0]?.field, order: sorter[0]?.order, status: filters.status }),
})
// 排序：table.setSorter([{ field: 'id', order: 'descend' }])
// 筛选：table.setFilters({ status: [1] })
```

**这里的 `submit()` 是查询动作，不是整表 `form.submit()`，返回类型仍是 `Promise<void>`。** 默认会先调用 `form.validate` 校验筛选参数路径（一个路径、一组路径，或全表；可通过 `validateOnSubmit: false` 关闭）。那次 `form.validate` 通过时 resolve 提交形状的值，本方法不把那份值交给调用方。校验未通过时不发送请求。

输入过滤条件不会立刻请求；查询动作才采用当前筛选。翻页/刷新使用上一次提交的筛选。筛选对象来自表单值，不要原地修改 `form.values` 或请求参数。

### 可运行的本地请求示例

这个例子不访问服务器。输入名称后点查询；client 模式每次筛选取完整数据，再在浏览器分页。移动页码不会再次运行 request。

```tsx preview
import { Field, Form } from '@shikiform/react';
import { useQueryTable } from '@shikiform/react';

type Row = { id: string; name: string };
type Values = { filters: { name: string }; list: Row[]; page: number; pageSize: number; selectedKeys: string[] };
const rows: Row[] = [
  { id: '1', name: 'Ada' }, { id: '2', name: 'Grace' },
  { id: '3', name: 'Alan' }, { id: '4', name: 'Edsger' },
];

export default function App() {
  const table = useQueryTable<Values>()({
    initialValues: { filters: { name: '' }, list: [], page: 1, pageSize: 2, selectedKeys: [] },
    params: 'filters',
    rows: 'list',
    mode: 'client',
    request: async ({ params }) => {
      const data = rows.filter((row) => row.name.toLowerCase().includes(params.name.toLowerCase()));
      return { data, total: data.length };
    },
  });
  const totalPages = Math.max(1, Math.ceil(table.total / table.pageSize));
  return (
    <Form form={table.form} onSubmit={() => table.submit()}>
      <div style={{ display: 'flex', gap: 8, marginBottom: 8 }}>
        <Field<Values, 'filters.name'> name="filters.name">
          {(field) => (
            <input aria-label="筛选名称" placeholder="输入后点查询" value={field.value}
              onChange={(event) => field.onChange(event.target.value)} onBlur={field.onBlur} />
          )}
        </Field>
        <button type="submit">查询</button>
        <button type="button" onClick={() => table.reset()}>重置</button>
      </div>
      <table>
        <thead><tr><th>名称</th></tr></thead>
        <tbody>
          {table.data.map((row) => <tr key={row.id}><td>{row.name}</td></tr>)}
        </tbody>
      </table>
      <div style={{ display: 'flex', gap: 8, marginTop: 8, alignItems: 'center' }}>
        <button type="button" disabled={table.page <= 1} onClick={() => table.setPage(table.page - 1)}>上一页</button>
        <span>第 {table.page} / {totalPages} 页（共 {table.total} 条）</span>
        <button type="button" disabled={table.page >= totalPages} onClick={() => table.setPage(table.page + 1)}>下一页</button>
      </div>
    </Form>
  );
}
```

## 默认请求

不传 `useQuery` 时，`useQueryTable` 用库内的最小 runner。它不从 `@shikiform/react` 导出。

| 输入 | 类型 / 作用 |
|---|---|
| `queryKey` | `readonly unknown[]`，必须可 JSON 序列化；用 `JSON.stringify` 后的字符串判断请求变化，首项 `'idle'` 表示不请求 |
| `queryFn` | `({ signal }) => Promise<{ data: TRow[]; total: number }>`；总是使用最新函数 |
| `placeholderData` | `(previous) => previous` 形状的兼容参数；内置 runner 直接保留旧数据，不调用这个函数 |

返回 `{ data, isFetching, isPlaceholderData }`。首次 data 为 undefined、两个状态为 false；后续请求中保留旧 data。key 变化或卸载时 abort 旧 signal，已过期结果不再更新。

**没有 `error` 字段、重试、缓存淘汰或跨组件查询缓存。** 请求失败会结束 fetching 并保留旧结果；业务错误展示需要在 request/页面自行处理，或提供兼容的查询 Hook。不要从 `isFetching=false` 推断请求成功。

兼容 Hook 接收同样的参数，返回同样的三个属性；库没有安装或导入 `@tanstack/react-query`，也不替应用创建它的 Provider。
