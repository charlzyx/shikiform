从 `@shikiform/antd` 导入。每个组件都是 [Pro Hooks](/reference/pro-hooks) 之上的薄封装。用法见 [Pro 组件](/guide/pro)，例子见 [Pro 示例](/examples/pro)。

## QueryList

```tsx
const table = useQueryTable({ initialValues: { query: {}, list: [] }, params: 'query', rows: 'list', request })
<QueryList table={table} columns={columns}>
  <Field name="query.domain" title="域名" decorator={[FormItem, { layout: 'vertical' }]} component={[Input]} />
  …
</QueryList>
```

Pro.formily `QueryList` + `QueryForm` + `QueryTable`：可折叠的查询栅格（展开 / 收起、重置、查询）加一张受控服务端分页的 [`ArrayTable`](/reference/antd#arraytable)，表头带刷新。状态全部在 `useQueryTable`；`rows` 选项必填，它把每页结果写进这个数组字段（单元格可以直接编辑），`QueryList` 渲染的就是它。children 是查询字段，放在一个 [`FormGrid`](/reference/antd-adapter#formgrid) 里，每个占一格（宽的用 `decorator={[FormItem, { gridSpan: 2 }]}` 或 `<GridColumn gridSpan>`）；列数随容器宽度变，`grid`（`maxColumns` / `minColumns` / `minWidth` / `breakpoints` / `columnGap`，默认 `{ maxColumns: 4, minWidth: 220 }`）可改。收起时只显示第一行，重置 / 查询在这一行末尾（antd Pro `QueryFilter` 的样子）；一行放不下才出现展开 / 收起，展开后按钮排在最后一行末尾。收起只隐藏不卸载，值照常参与查询。标签宽度等用外层 `FormLayout` 给。其余参数（`rowKey`、`columns`、`title`、`toolbar`、`extra`、`footer`、`expandable`、`rowSelection`、`settings`、`resizeable`）交给内部的 `ArrayTable`。选择存在 Hook 里，翻页保留、新查询清空。列上写 `sorter: true` / `filters`，表头排序和列筛选会作为 `sorter` / `filters` 发给 `request` 并回到第 1 页；列筛选和新查询一样清空选择，排序保留选择；表头状态受 Hook 控制，`重置` 一并清空（见 [表头排序与列筛选](/reference/query-hooks#表头排序与列筛选)）。

## ShadowModal

```tsx
// 1. 绑定宿主路径（自动继承规则、读写宿主路径，可省略 record / onOk）
<ShadowModal<Info> name="info" title="编辑" trigger={<Button>编辑</Button>}>
  <Field name="domain" decorator={[FormItem]} component={[Input]} />
</ShadowModal>

// 2. 放在数组行作用域内（如 ArrayTable 列内）直接绑定当前行
<ShadowModal<Row> title="编辑" trigger={<Button type="link">编辑</Button>}>
  <Field name="domain" decorator={[FormItem]} component={[Input]} />
</ShadowModal>

// 3. 非绑定模式（手动传 record / onOk）
<ShadowModal<Info> title="编辑" record={() => form.getValue('info')} onOk={(values) => save(values)} trigger={<Button>编辑</Button>}>
  <Field name="domain" title="域名" required decorator={[FormItem]} component={[Input]} />
</ShadowModal>
```

在 antd `Modal` 中渲染草稿表单。支持 `name` / `add` / `rowKey` / `merge` 及可选的 `record`（静态值或异步加载函数）与 `onOk`：绑定宿主路径或数组行时，打开自动复制宿主值、继承剥离前缀后的 `fields` / `trees` 配置及该路径的 `readOnly` / `disabled`；确认校验通过后写回宿主（`onOk` 返回 `false` 跳过默认写回）；取消则丢弃草稿，不修改原表单。传入 `useShadowForm` 创建的 `shadow` 时由外部受控，省略则组件内部维护实例。草稿处于 `readOnly` 且未传自定义 `footer` 时隐藏确定按钮，只显示关闭按钮（文案取 `messages.close`，默认 `关闭` / `Close`）；否则读取 `messages.ok` / `messages.cancel`（`确定` / `取消`），可用 `okText` / `cancelText` 覆盖。草稿内部（`ShadowBody`）隔离宿主表单、作用域、字段、分组与栅格上下文，保留外层 `FieldKit` 与 `FormLayout`，草稿内 `<Field>` 相对于草稿根路径解析。

## ShadowDrawer

```tsx
<ShadowDrawer name="info" title="编辑" okText="保存" trigger={<Button>编辑</Button>}>
  <Field name="domain" decorator={[FormItem]} component={[Input]} />
</ShadowDrawer>
```

与 `ShadowModal` 相同，换成 antd `Drawer`，底部是取消 / 确定（`readOnly` 且未传自定义 `footer` 时隐藏确定按钮，仅显示 `messages.close` 关闭按钮）。`ArrayTable.ShadowAddition` 的 `popType="drawer"` 就是它。适合字段较多、需要更大编辑区域的行编辑。

## ShadowPopconfirm

```tsx
<ShadowPopconfirm name="info" trigger={<Button>改名</Button>}>
  <Field name="domain" decorator={[FormItem]} component={[Input]} />
</ShadowPopconfirm>
```

把少量字段放进 antd `Popconfirm` 的气泡里编辑（Pro.formily `ShadowPopconfirm`）。支持 `name` / `add` / `rowKey` / `merge` 与可选 `record` / `onOk`；打开气泡时初始化草稿，确认校验后写回并调用 `onOk`，取消或点外面关闭都会丢弃草稿。`readOnly` 时隐藏确定按钮，仅保留 `messages.close` 关闭按钮。

## ShadowForm

```tsx
<ShadowForm<Info> name="info">
  {(shadow) => <>…fields… <Button onClick={() => shadow.confirm()}>提交</Button></>}
</ShadowForm>
```

内联草稿表单：挂载时初始化草稿（支持 `name` / `add` / `rowKey` / `merge` 或手动 `record` / `onOk`）并将子节点渲染在草稿实例下。可通过 render prop 接收 `shadow`，也可在子组件内调用 `useShadow()` 读取它。`ShadowForm` 不渲染原生 `<form>` 标签，并隔离宿主表单与作用域上下文（保留 `FieldKit` 与 `FormLayout`），可直接嵌在宿主 `<Form>` 内部。

## useShadow

```ts
useShadow<TValues, TContext>(): ShadowFormApi<TValues, TContext>
```

读取外层 `ShadowForm` / `ShadowModal` / `ShadowDrawer` / `ShadowPopconfirm` 正在渲染的草稿：`form`、`visible`、`loading`、`submitting`、`context`、`open()`、`confirm()`、`cancel()`。不在这些组件里调用会抛错，提示需要的外层组件。

## Suggestion

```tsx
<Field name="keyword" title="淘宝搜索" decorator={[FormItem]} component={[Suggestion, { fetch: search, debounce: 200, multiple: true, labelInValue: true }]} />
```

字段绑定的远程联想下拉（Pro.formily `Suggestion`），建立在 `useSuggestion` 上。值有四种形状：`string`、`{ label, value }`（`labelInValue`）、`string[]`（`multiple`）、`{ label, value }[]`（两者都开）。阅读态显示标签。

## SuggestionView

```tsx
<SuggestionView value={value} onChange={setValue} fetch={search} multiple />
```

`Suggestion` 的非字段版本：普通的受控 `value` / `onChange` 组件，其余属性透传给 antd `Select`。防抖、中止旧请求、记住已选标签的行为与 `Suggestion` 完全一样，可以在表单外单独使用。

## CascaderPlus

```tsx
<Field name="area" title="地区" decorator={[FormItem]} component={[CascaderPlus, { loadData: (path) => api.children(path), labelInValue: true }]} />
```

字段绑定的懒加载级联（Pro.formily `CascaderPlus`），建立在 `useLazyCascader` 上：一个 `loadData(path)` 服务所有层级，已有值打开时逐级加载以反显标签（已带 `children` 的节点不再加载，所以 `loadData([])` 一次返回整棵树也行，但选项一开始就齐全时用 [`Cascader`](/reference/antd-adapter#cascader) + `<Field enum>`）；支持 `multiple` 和 `labelInValue`（每一级 `{ label, value }`）。默认 `changeOnSelect`。阅读态（`readOnly`）与 `Cascader` 一样显示 `省 / 市 / 区`：`labelInValue` 的值自带标签；裸值（`['410000', '410600']`）用同一个 `loadData` 逐级加载后显示标签而不是编码。自绘阅读态对裸路径用 [`useLazyCascader`](/reference/pro-hooks#uselazycascader) 的 `labelsOf`。

## CascaderPlusView

```tsx
<CascaderPlusView value={['110000', '11000000', '110105']} onChange={setValue} loadData={loadArea} multiple={false} />
```

`CascaderPlus` 的非字段版本：受控 `value` / `onChange`，其余属性透传 antd `Cascader`。`/play/cascader-plus` 的三个例子（整棵树 / 懒加载切换、反显、labelInValue 反显）都直接用它。
