从 `@shikiform/antd` 导入。每个组件都是 [Pro Hooks](/reference/pro-hooks) 之上的薄封装。用法见 [Pro 组件](/guide/pro)，例子见 [Pro 示例](/examples/pro)。

## QueryList

```tsx
const table = useQueryTable({ initialValues: { query: {}, list: [] }, params: 'query', rows: 'list', request })
<QueryList table={table} columns={columns}>
  <Field name="query.domain" title="域名" decorator={[FormItem, { layout: 'vertical' }]} component={[Input]} />
  …
</QueryList>
```

Pro.formily `QueryList` + `QueryForm` + `QueryTable`：可折叠的查询栅格（展开 / 收起、重置、查询）加一张受控服务端分页的 [`ArrayTable`](/reference/antd#arraytable)，表头带刷新。状态全部在 `useQueryTable`；`rows` 选项必填，它把每页结果写进这个数组字段（单元格可以直接编辑），`QueryList` 渲染的就是它。children 是查询字段，放在一个 [`FormGrid`](/reference/antd-adapter#formgrid) 里，每个占一格（宽的用 `decorator={[FormItem, { gridSpan: 2 }]}` 或 `<GridColumn gridSpan>`）；列数随容器宽度变，`grid`（`maxColumns` / `minColumns` / `minWidth` / `breakpoints` / `columnGap`，默认 `{ maxColumns: 4, minWidth: 220 }`）可改。收起时只显示第一行，重置 / 查询在这一行末尾（antd Pro `QueryFilter` 的样子）；一行放不下才出现展开 / 收起，展开后按钮排在最后一行末尾。收起只隐藏不卸载，值照常参与查询。标签宽度等用外层 `FormLayout` 给。其余参数（`rowKey`、`columns`、`title`、`toolbar`、`extra`、`footer`、`expandable`、`rowSelection`、`settings`、`resizeable`）交给内部的 `ArrayTable`。选择存在 Hook 里，翻页保留、新查询清空。列上写 `sorter: true` / `filters`，表头排序和列筛选会作为 `sorter` / `filters` 发给 `request` 并回到第 1 页；列筛选和新查询一样清空选择，排序保留选择；表头状态受 Hook 控制，`重置` 一并清空（见 [表头排序与列筛选](/reference/query-hooks#表头排序与列筛选)）。

## ShadowModal

```tsx
<ShadowModal<Info> title="编辑" record={() => form.getValue('info')} onOk={(values) => form.setValue('info', values)} trigger={<Button>编辑</Button>}>
  <Field name="domain" title="域名" required decorator={[FormItem]} component={[Input]} />
</ShadowModal>
```

在 antd `Modal` 里编辑影子草稿（Pro.formily `ShadowModal`）。点 `trigger` 用 `record` 打开（值或加载函数）；确定先校验，再调 `onOk`，成功后关闭；取消什么都不写。传 `shadow`（来自 `useShadowForm` / `useArrayShadow`）时用外部草稿，否则组件自己持有一个。草稿字段从草稿的根开始解析，不继承所在行的作用域。按钮文字取 `messages.ok` / `messages.cancel`（确定 / 取消），`okText` / `cancelText` 覆盖。

## ShadowDrawer

```tsx
<ShadowDrawer shadow={editor} title="编辑" okText="保存">
  <Field name="domain" title="域名" decorator={[FormItem]} component={[Input]} />
</ShadowDrawer>
```

与 `ShadowModal` 相同，换成 antd `Drawer`，底部是取消 / 确定。`ArrayTable.ShadowAddition` 的 `popType="drawer"` 就是它。适合字段较多、需要更大编辑区域的行编辑。

## ShadowPopconfirm

```tsx
<ShadowPopconfirm record={() => ({ name: form.getValue('name') })} onOk={(v) => form.setValue('name', v.name)} trigger={<Button>改名</Button>}>
  <Field name="name" decorator={[FormItem]} component={[Input]} />
</ShadowPopconfirm>
```

把少量字段放进 antd `Popconfirm` 的气泡里编辑（Pro.formily `ShadowPopconfirm`）。打开气泡时用 `record` 初始化草稿，确认校验后调用 `onOk`，取消或点外面关闭都会丢弃草稿。

## ShadowForm

```tsx
<ShadowForm<Info> record={info} onOk={save}>
  {(shadow) => <>…fields… <Button onClick={() => shadow.confirm()}>提交</Button></>}
</ShadowForm>
```

内联的影子表单（Pro.formily 把 `ShadowForm` 用作 decorator / component 的两种写法）：挂载即用 `record` 打开，子节点渲染在草稿上。草稿通过 render prop 交给容器，或在任意子组件里用 `useShadow()` 取得，所以提交按钮可以放在任何位置。不渲染 `<form>` 元素，可以放在宿主 `<Form>` 里。

## useShadow

```ts
useShadow<TValues, TContext>(): ShadowFormApi<TValues, TContext>
```

读取外层 `ShadowForm` / `ShadowModal` / `ShadowDrawer` / `ShadowPopconfirm` 正在渲染的草稿：`form`、`visible`、`submitting`、`confirm()`、`cancel()`。不在这些组件里调用会抛错，提示需要的外层组件。

## Suggestion

```tsx
<Field name="keyword" title="淘宝搜索" decorator={[FormItem]} component={[Suggestion, { fetch: search, debounce: 200, multiple: true, labelInValue: true }]} />
```

字段绑定的远程联想下拉（Pro.formily `Suggestion`），建立在 `useSuggestion` 上。值有四种形状：`string`、`{ label, value }`（`labelInValue`）、`string[]`（`multiple`）、`{ label, value }[]`（两者都开）。阅读态显示标签。

## SuggestionView

```tsx
<SuggestionView value={value} onChange={setValue} fetch={search} multiple />
```

`Suggestion` 的非字段版本：普通的受控 `value` / `onChange` 组件，其余属性透传给 antd `Select`。防抖、中止旧请求、记住已选标签的行为与 `Suggestion` 完全一样，可以在表单外单独使用。

## CascaderPlus

```tsx
<Field name="area" title="地区" decorator={[FormItem]} component={[CascaderPlus, { loadData: (path) => api.children(path), labelInValue: true }]} />
```

字段绑定的懒加载级联（Pro.formily `CascaderPlus`），建立在 `useLazyCascader` 上：一个 `loadData(path)` 服务所有层级，已有值打开时逐级加载以反显标签（已带 `children` 的节点不再加载，所以 `loadData([])` 一次返回整棵树也行，但选项一开始就齐全时用 [`Cascader`](/reference/antd-adapter#cascader) + `<Field enum>`）；支持 `multiple` 和 `labelInValue`（每一级 `{ label, value }`）。默认 `changeOnSelect`。阅读态（`readPretty`）与 `Cascader` 一样显示 `省 / 市 / 区`：`labelInValue` 的值自带标签；裸值（`['410000', '410600']`）用同一个 `loadData` 逐级加载后显示标签而不是编码（[`useCascaderLabels`](/reference/pro-hooks#usecascaderlabels)）。

## CascaderPlusView

```tsx
<CascaderPlusView value={['110000', '11000000', '110105']} onChange={setValue} loadData={loadArea} multiple={false} />
```

`CascaderPlus` 的非字段版本：受控 `value` / `onChange`，其余属性透传 antd `Cascader`。`/play/cascader-plus` 的三个例子（整棵树 / 懒加载切换、反显、labelInValue 反显）都直接用它。
