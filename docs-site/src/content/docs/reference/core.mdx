`@shikiform/core` 是纯 TypeScript 表单引擎，不依赖 React 或任何 UI 库。`@shikiform/react` 重新导出了本页中常用的运行时 API，因此在 React 组件中也可以直接从 `@shikiform/react` 导入。

相关指南：[按路径读写](/basics/path)、[联动](/guide/linkage)、[核心概念](/guide/concepts)。

## createForm

```ts
function createForm<T, TSubmit = T>(options?: FormOptions<T>): FormInstance<T, TSubmit>

// @shikiform/react。V 写在 typed<V>() 上。
typed<V>().createForm<TSubmit = DefaultSubmit, const F extends FieldsInput<V> = {}>(
  options?: Omit<FormOptions<V>, 'fields'> & { fields?: F & FieldsInput<V> },
): FormInstance<V, ResolveSubmit<V, TSubmit, F>>

typed<V>().useForm<TSubmit = DefaultSubmit, const F extends FieldsInput<V> = {}>(
  options?: Omit<UseFormOptions<V>, 'fields'> & { fields?: F & FieldsInput<V> },
): FormInstance<V, ResolveSubmit<V, TSubmit, F>>
```

在组件外创建表单引擎实例，选项与 `useForm` 相同（`initialValues`、`effects`、`fields`、`validate`、`readOnly`、`disabled`、`messages`）。返回的 `FormInstance` 提供 `getValue`、`setValue`、`patchValues`、`setReadOnly`、`setDisabled`、`batch`、`submit`、`validate`、`reset` 等方法，以及 `values`、`readOnly`、`disabled`、`dirty`、`errors` 等只读属性。开发环境中 `getValue` 与 `values` 返回只读视图：对对象、数组、`Map`、`Set`、`Date` 原地写入会抛 `ShikiUsageError`，同一底层对象多次读取保持同一个引用，但视图和存储对象不是 `===`（生产环境是）。`snapshot(form.values)`（`@shikiform/core`）是含 omit 字段的纯数据副本，可 `structuredClone` / `postMessage` / 写入 IndexedDB；`getSubmitValues()` 是提交副本；`toRaw(value)` 是存储对象本身。生产环境返回存储的原值。其中 `patchValues(partial)` 在单次批处理中递归浅合并普通对象字段（未传入的兄弟字段保持不变，数组与原始值整体替换），适合 OCR 识别或接口局部字段回填；`setReadOnly(bool)` / `setDisabled(bool)` 用于切换整表根级阅读态或禁用态。`createForm()` 与 `createForm(undefined)` 等价于 `createForm({})`。

类型推导：不传泛型参数时，`fields` 中声明了 `omit: true` 的路径在提交类型中变为可选；写 `createForm<V>(options)` 时提交类型固定为 `V`；既要显式标注 `V` 又要按 `fields` 将 `omit` 路径推导为可选时，使用 `typed<V>().createForm({ fields })`（或 `typed<V>().useForm({ fields })`）；手动列出可选路径可在第二个泛型参数传入 `SubmitValues<V, 'tmp'>`。签名中的 `DefaultSubmit`、`FieldsInput` 与 `ResolveSubmit` 为内部推导类型，不从公开入口导出。

`validate` 的三个重载：

```ts
validate(): Promise<TSubmit>
validate<P extends FieldPath<T>>(path: P): Promise<PathValue<T, P>>
validate<const Paths extends readonly FieldPath<T>[]>(paths: Paths): Promise<ValidatePick<T, Paths>>
```

通过时 resolve 调用结束时的当前值。不传 path 是 `getSubmitValues()`（上面的提交类型）；一个 path 是该处的 `PathValue`（path 自身即使 `omit` 也返回，只因它而被 omit 的子孙仍在，子孙自己的 `omit` 才去掉）；路径数组是只含这些 path 的嵌套对象（`ValidatePick`）。返回值是副本：普通对象、数组、`Date`、`Map`、`Set` 会复制，类实例、函数和 React 元素仍是原来的引用，原地修改不会写回表单。开发环境里 `getValue` 的只读视图原地改会抛 `ShikiUsageError`。失败 reject `FieldError[]`，表单级 `validate` 抛错原样 reject。详见 [API 总览](/api#读写和提交)。

```ts
const values = await form.validate()
```

```ts
import { createForm } from '@shikiform/core'

const form = createForm<{ name: string }>({ initialValues: { name: '' } })
form.setValue('name', 'Ada')
```

```ts
import { typed } from '@shikiform/react'

type Values = { name: string; confirm: string }
const fields = { confirm: { omit: true as const } }

const form = typed<Values>().createForm({ initialValues: { name: '', confirm: '' }, fields })

form.submit((values) => {
  values.name // string
  values.confirm // string | undefined
})

function Demo() {
  const live = typed<Values>().useForm({ initialValues: { name: '', confirm: '' }, fields })
  live.submit((values) => {
    values.name // string
    values.confirm // string | undefined
  })
  return null
}
```

## defineEffects

`defineEffects<T>(factory)` 用于定义一组可复用的联动模块。`factory` 会收到 `reaction`、`watch`、`draft` 和 `query`。`draft` 是根路径 handle，用来在注册时点名：`reaction.each(draft.items, …)`、`watch(draft.city, …)`（监听该字段的 `$value`）、`watch([draft.a, draft.b], …)`。selector `(d) => d.items` 仍然可用。`query(path)` 只用于路径已经是字符串的情况（`pathOf`、配置、props）。详见 [联动](/guide/linkage)。

```ts
import { defineEffects } from '@shikiform/core'

const effects = defineEffects<{ qty: number; total: number }>(({ reaction }) => {
  reaction((d) => {
    d.total.$value = (d.qty.$value ?? 0) * 2
  })
})
```

## 值的复制与相等比较

表单值必须是无环数据：传入含循环引用的对象时，`createForm` 与写入入口会抛出 `ShikiUsageError`（开发与生产均检查）。

- **初值与基线复制**：`initialValues` 入库、`reset(values)` 与 `validate()` 返回副本采用同一套表单复制语义——深拷贝普通对象（保留包括 `__proto__` 在内的自有数据属性，不改变对象原型）、数组、`Date`、`Map` 与 `Set`；`File`、`Blob`、自定义类实例、函数、`Symbol` 与 React 元素保持原引用。需要可被 `structuredClone` / `postMessage` / IndexedDB 序列化的副本时，调用 `snapshot(value)`。
- **深比较与 `dirty`**：变化检测与 `dirty` 比较按内容递归对比 `Map`（键值逐项）与 `Set`（成员），用 `Object.is` 比较 `Date` 时间戳（两个无效日期视为相等）；`File`、`Blob` 及其他非普通对象按引用比较，替换为新实例时会被识别为变化。
- **稀疏数组空洞**：数组比较区分“空洞（hole）”与显式 `undefined` 槽位；向稀疏空洞显式写入 `undefined` 视为一次值变化，会触发订阅并影响 `dirty`。

## EnumSource

用于定义异步选项源。带参数时通过 `source.with(params)` 绑定到字段的 `enum`（含 `fields.x.enum` 与 `<Field enum>`）或 `$enum`；无参选项源（`EnumSource<void>`）也可直接传给 `enum` 或 `$enum`，无需调用 `.with()`。在请求尚未完成前，读取 `$enum` 会返回空数组 `[]`。

多个字段共用同一个 `EnumSource` 与相同参数键时，引擎按消费者引用计数共享在途请求。移除数组行或树节点时会释放对应消费者的请求（并在最后一个消费者退出时中止请求），不影响其他仍存活的消费者；保留节点在数组重排或树移动时若来源键不变，会继续复用同键的在途加载而不重发请求。

## 错误类

引擎导出 `ShikiUsageError`、`ShikiConflictError`、`ShikiCycleError`、`SubmitSupersededError`、`SubmitUnstableError` 与类型守卫 `isFieldErrors`（用于识别校验失败 reject 的 `FieldError[]`），错误类均可使用 `instanceof` 判断。用法误用和反应式写冲突仅在开发环境校验，循环依赖与提交状态错误在生产环境也会抛出。

## 文案

内置文案默认使用中文 `zhCN`，同时也提供了英文 `enUS`。调用 `setDefaultMessages(enUS)` 会修改此后创建的所有表单的默认文案，单个表单可通过 `messages` 选项进行局部覆盖，`getDefaultMessages()` 用于读取当前生效的全局默认文案。

## 树坐标

提供 `moveNode`、`pathOf` 和 `posOf` 工具函数用于操作树形节点的坐标路径（`pos` 为下标数组，如 `[0, 2]`）。`moveNode` 只改数据、不迁移字段状态。在表单里移动数组或树节点请使用 `useArrayField().move` 或 `useTreeField().move`。
