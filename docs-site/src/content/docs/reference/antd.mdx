从 `@shikiform/antd` 导入。字段只有一种写法：`<Field decorator={[FormItem]} component={[Input]} />`（适配层见 [Ant Design 适配层参考](/reference/antd-adapter)），按表单类型检查名字用 [`typed(form)`](/reference/react-hooks#typed)。本页是按钮、控件的取值契约、数组容器和表格组件。用法见 [Ant Design 适配](/guide/antd)。

## Submit

```ts
Submit<T = any>(props: Omit<ButtonProps, 'onSubmit'> & {
  onSubmit?: (values: T) => void | Promise<void>;
  onInvalid?: (errors: FieldError[]) => void;
  onSubmitError?: (error: unknown) => void;
})
```

当前表单（`<Form>` 提供）的主按钮。默认 `type="primary"`，文字取 `messages.submit`（`提交` / `Submit`）。`disabled` 默认 `!$canSubmit`（已有错误或正在提交时不可点；还没校验过的空必填项不挡它，第一次点击仍会跑校验），显式传 `disabled` 覆盖；`loading` 是 `$submitting || props.loading`。它只订阅表单元数据，不订阅输入值。

| 写法 | 行为 |
|---|---|
| 不传 `onSubmit` | 原生 `htmlType="submit"`，交给外层 `<Form onSubmit>`；回车同样提交 |
| 传 `onSubmit`（可加 `onInvalid` / `onSubmitError`） | `htmlType="button"`，点击时自己调用 `form.submit(onSubmit)`，结果分发同 `<Form>`；不需要外层 `<form>` 元素，适合弹窗页脚 |

`onClick` 先执行；在里面 `event.preventDefault()` 会跳过自带的提交。表单外渲染会抛错并提示用 `<Form form={form}>` 包住。

## Reset

```ts
Reset<T = any>(props: ButtonProps & {
  values?: T
  afterReset?: (values: T) => void
})
```

点击调用 `form.reset(values)`：不传 `values` 回到初始值；传了则把它设为新的初始值再重置（编辑页回填）。touched、edited 和全部消息一并清空。文字取 `messages.reset`（`重置` / `Reset`），`htmlType="button"`，不会触发原生 reset。`onClick` 先执行（读到的仍是旧值），`event.preventDefault()` 跳过重置。`afterReset` 在重置之后调用，参数已是恢复后的值，查询页用它再查一次，不必 `queueMicrotask`。不装 antd 时用 `@shikiform/react` 的 `<Reset afterReset>`。

```tsx preview
import { useState } from 'react';
import { Space } from 'antd';
import { Field, Form, useForm } from '@shikiform/react';
import { FormItem, FormLayout, Input, Reset, Submit } from '@shikiform/antd';

export default function App() {
  const [saved, setSaved] = useState('还没有提交');
  const form = useForm({ initialValues: { name: 'Ada' } });
  return (
    <Form form={form} onSubmit={(values) => setSaved(JSON.stringify(values))}>
      <FormLayout labelCol={{ span: 4 }} wrapperCol={{ span: 20 }}>
        <Field name="name" title="姓名" required decorator={[FormItem]} component={[Input]} />
      </FormLayout>
      <Space>
        <Submit />
        <Reset />
        <Submit onSubmit={(values) => setSaved(`草稿：${JSON.stringify(values)}`)}>存草稿</Submit>
      </Space>
      <pre aria-live="polite">{saved}</pre>
    </Form>
  );
}
```

## 控件取值契约

`Input`、`Select` 等是 `connect()` 过的控件（[适配层参考](/reference/antd-adapter#input)）。值和 ID 由字段绑定负责，传入的 `value` / `checked` / `id` 不能覆盖字段状态。字段内部 change/blur 通知先执行，调用方对应回调随后以原始参数执行一次；不要在回调里再次写回同一个字段。

| 控件 | UI 属性类型 | 写回值 / 重要默认 |
|---|---|---|
| `Input` | `InputProps` | `event.target.value`；空显示为 `''` |
| `Select` | `SelectProps` | antd 的选择值；优先用 `props.options`，否则映射 `field.options` 的 label/value |
| `InputNumber` | `InputNumberProps` | 写入 antd 给出的原始值（数字；`stringMode` 下是字符串）；**清空为 `null`** |
| `Switch` | `ComponentProps<typeof Switch>`，另支持 `onBlur?: React.FocusEventHandler<HTMLButtonElement>` | `checked` 布尔值；失焦从真实 button 透传，先通知字段再通知调用方 |
| `Checkbox` | `ComponentProps<typeof Checkbox>`；`Checkbox.Group` 绑数组 | `event.target.checked`；Group 写入选中值数组 |
| `Radio`（= `Radio.Group`） | antd `RadioGroupProps` | 选中值；`options` 默认取字段枚举 |
| `DatePicker` | `DatePicker` 的 props；`DatePicker.RangePicker` 为区间 | 格式化字符串（默认 `YYYY-MM-DD`），不是 dayjs；清空为 `undefined` |
| `Input.Password` / `Input.TextArea` | 同 `Input` 的对应变体 | 与 `Input` 一样写回字符串；Password 的阅读态是 `******` |

`InputNumber` 的转换是正式适配器契约。需要不同的空值、字符串精度策略时，用 `connect(AntInputNumber, mapProps({ parse }))`，或 `<Field>` + 无参 `useField()` 自己接线。

字段 `disabled` 和控件 `disabled` 合并。`readOnly` 渲染 `preview`：Switch / Checkbox 显示「是 / 否」，Input 显示文本，Select 显示选项 label。`disabled` 与 `readOnly` 同时为真时以阅读态为准。这些 UI 状态不禁止程序调用 `form.setValue()`。

### 完整例子：状态与事件回调

点击开关一次，change 计数只加一次；聚焦开关后按 Tab，blur 计数只加一次且 `currentTarget` 是真实 button。设为只读后开关换成阅读态文本（是 / 否），隐藏后再显示仍是同一字段值。

```tsx preview
import { useState } from 'react';
import { Field, Form, useForm } from '@shikiform/react';
import { FormItem, Switch } from '@shikiform/antd';

export default function App() {
  const form = useForm({ initialValues: { notify: true } });
  const [changes, setChanges] = useState(0);
  const [blurs, setBlurs] = useState(0);
  const [target, setTarget] = useState('尚未失焦');
  return (
    <Form form={form}>
      <section aria-label="适配状态与事件">
        <Field name="notify" decorator={[FormItem]}>
          <Switch aria-label="通知开关"
            onChange={() => setChanges((count) => count + 1)}
            onBlur={(event) => {
              setBlurs((count) => count + 1);
              setTarget(event.currentTarget.tagName);
            }} />
        </Field>
        <button type="button" onClick={() => form.batch((d) => { d.notify.$readOnly = true; })}>设为只读</button>
        <button type="button" onClick={() => form.batch((d) => { d.notify.$readOnly = true; })}>设为展示</button>
        <button type="button" onClick={() => form.batch((d) => { d.notify.$readOnly = false; d.notify.$disabled = false; })}>恢复编辑</button>
        <button type="button" onClick={() => form.batch((d) => { d.notify.$visible = false; })}>隐藏通知控件</button>
        <button type="button" onClick={() => form.batch((d) => { d.notify.$visible = true; })}>显示通知控件</button>
        <pre data-testid="adapter-event-counts">{JSON.stringify({ changes, blurs, target })}</pre>
      </section>
    </Form>
  );
}
```

## MergedTable

```ts
MergedTable<T extends { id: string }>({ rows, groupOf, columns, rowKey? })
```

`rows: readonly T[]`，`groupOf(row): string`，`columns: { title: string; key: string; merge?: boolean; render(row, index): ReactNode }[]` 必填；`rowKey` 默认 `'id'`，也可以是 `(row) => string`（组的首行换了 id 时传稳定的 key，合并单元格里的字段才不会重新挂载）。

使用 antd Table，`pagination={false}`。列 `merge` 默认 false；true 时以 `groupOf` 的**连续相邻分组**计算 rowSpan，非连续同名组不会跨行合并。它不排序、不扁平化嵌套对象、不维护编辑值；行模型由调用方准备。表格的行不是一个数组字段，单元格里的字段用 `<ObjectField name="suppliers.0.products.1">`（见 [API 总览](/api#react-组件)）指到它对应的路径，里面写相对名字，例如 `<Field name="price">` 绑定 `suppliers.0.products.1.price`。见 [供应商和产品](/play/merged)。

## groupRowSpan

```ts
groupRowSpan<T>(rows: readonly T[], groupOf: (row: T) => string): number[]
```

返回与 rows 等长的数组：每个连续组首项为组长度，后续项为 0。空 rows 返回 `[]`，不修改输入。例如分组 `[A, A, B, A]` 返回 `[2, 0, 1, 1]`。合并列和过滤后的行必须使用同一份 rows。

## ArrayItems

```tsx
<ArrayField name="contacts" component={[ArrayItems, { addition: <ArrayItems.Addition />, empty?: ReactNode | false }]}>
  {(row) => (
    <ArrayItems.Item>
      <ArrayItems.SortHandle /> <ArrayItems.Index /> {/* 行字段 */} <ArrayItems.MoveUp /> <ArrayItems.MoveDown /> <ArrayItems.Remove />
    </ArrayItems.Item>
  )}
</ArrayField>
```

数组容器（Formily `ArrayItems`），作为 `<ArrayField>` / `F.ArrayField` 的 `component`。`<ArrayField>` 提供数组上下文并为 `children` 的每一行注入行作用域，所以下面的成员都只是 `useArrayField()` + `useIndex()`。

| 成员 / 参数 | 行为 |
|---|---|
| `addition` | 渲染在各行下方，通常是 `<ArrayItems.Addition />` |
| `feedback` | 默认 `true`：在各行和 `addition` 之间显示**这一层数组自己的**错误 / 警告（颜色与 `FormItem` 的反馈文字相同，`data-testid="array-feedback"`）。子字段的消息不在这里。`false` 不显示；外层 `FormLayout` 的 `feedbackLayout: 'none'` 同样不显示。见 [数组句柄的 errors](/reference/react-hooks#usearrayfield) |
| `empty` | 没有行时显示；默认 antd `Empty`（简洁图），`false` 不显示 |
| `className` / `style` | 外层纵向 flex 容器（间距 8） |
| `ArrayItems.Item` | 一行横排（flex，间距 8），也是拖拽的放置目标 |
| `ArrayItems.SortHandle` | `⋮⋮` 拖拽把手，放到另一行上 = `array.move(from, to)`（HTML5 拖放） |
| `ArrayItems.Index` | `#序号`（从 1 开始），`prefix` 换前缀；不可编辑时也显示 |
| `ArrayItems.Remove` | `title?`、`confirm?: boolean \| string`（先 `Popconfirm`） |
| `ArrayItems.MoveUp` / `MoveDown` | `title?`；首行 / 末行禁用 |
| `ArrayItems.Addition` | `title?`、`defaultValue?`（值每次克隆，或函数；默认 `{}`）、`method?: 'push' \| 'unshift'` |

`SortHandle`、`Remove`、`MoveUp`、`MoveDown`、`Addition` 只在数组可编辑时渲染（`visible` 且不是 `readOnly` / `disabled`，见 [useArrayEditable](#usearrayeditable)）。按钮文案走表单 `messages`（`add`、`remove`、`removeConfirm`、`moveUp`、`moveDown`、`dragSort`）。行可以没有 id：对象行的身份是稳定的对象身份，`rowKey` 只在行里有业务 id 时传。

## ArrayCards

```tsx
<ArrayField name="items" component={[ArrayCards, { title: '商品', extra?: ReactNode, addition: <ArrayCards.Addition />, empty? }]}>
  {(row) => /* 卡片内容：行字段 */}
</ArrayField>
```

每行一张 antd `Card`（`size="small"`，Formily `ArrayCards`）。不需要行包装组件：容器把每行内容包进卡片，卡片仍在该行的作用域里。

| 参数 | 行为 |
|---|---|
| `title` | 卡片标题前缀，后面跟 `#序号`；可编辑时标题前有拖拽把手 |
| `extra` | 卡片右上角；默认 `MoveUp` + `MoveDown` + `Remove` |
| `addition` / `empty` / `feedback` / `className` / `style` | 同 `ArrayItems`（含数组自身的错误行） |

静态成员 `SortHandle`、`Index`、`Remove`、`MoveUp`、`MoveDown`、`Addition` 与 `ArrayItems` 的是同一批组件。

## ArrayTable

```tsx
<ArrayField name="list" rowKey="id" component={[ArrayTable, {
  columns: [
    { key: 'sort', width: 50, render: () => <ArrayTable.SortHandle /> },
    { key: 'a1', title: 'A1', render: () => <Field name="a1" component={[Input]} /> },   // 单元格可以不要装饰器
    { key: 'a2', title: 'A2', render: () => <Field name="a2" required decorator={[FormItem, { feedbackLayout: 'terse' }]} component={[Input]} /> },
    { key: 'act', title: '操作', render: () => <ArrayTable.Remove confirm /> },
  ],
  pagination: { pageSize: 10 },
  rowSelection: true,
  expandable: {
    rowExpandable: (record) => !!record.children,
    render: () => <ArrayField name="children" component={[ArrayTable, { columns: childColumns }]} />,   // 只读：childColumns 的单元格写 readOnly
  },
  extra: <ArrayTable.Addition />,
  onRemove: (index, record) => api.remove(record.id),
}]} />
```

数组上的 antd 表格（Formily `ArrayTable`，带 Pro.formily `ProArrayTable` 的功能），是 `<ArrayField>` 的容器，和 `ArrayItems` / `ArrayCards` 同一种写法。数组路径和 `rowKey` 来自外层 `<ArrayField>`；单元格来自 `columns`，所以 `<ArrayField>` 不写行 children（写了开发期警告一次）。分页、选择、展开的无 UI 状态是 [`useArrayTable`](/reference/pro-hooks#usearraytable)；列显隐、排序、列宽和密度是表格自己的状态，在 `toolbar` / `footer` / 单元格里用 `ArrayTable.useTable().settings` 读取。这些状态都不进表单值。

`ArrayTable` 不画数组路径自己的错误。要显示时在 `footer` 里读 `useArrayField().errors`：它出现在表格下方，并且仍由 `ArrayTable` 渲染，所以在 `<ArrayField>` 里面。和 `<ArrayField>` 平级再写一个组件会抛 `ShikiUsageError`。写法见 [数组自身的错误](/guide/arrays#数组自身的错误)。

列的 `render(cell)` 渲染在行作用域里：`<Field name="a1">` 就是 `list.N.a1`，展开区里的 `<ArrayField name="children">` 也相对这一行。`cell` 是 `{ key, index, position, record, table }`；`component` 的属性按 `ArrayTableProps` 检查（少写 `columns` 是类型错误），要让 `record` 有类型，写 `const columns: ArrayTableColumn<Row>[] = […]`。

| 参数 | 行为 |
|---|---|
| `columns` | 必填。`{ key, title?, width?, align?, fixed?, ellipsis?, hidden?, sorter?, sortOrder?, filters?, filterMultiple?, filteredValue?, render(cell) }`；`hidden` 只是列配置里初始隐藏；`sorter: true` 只上报变化，比较函数在本页内排序 |
| `pagination` | 默认每页 10 条的前端分页；`false` 关闭；带 `total` 时是受控服务端页（数组只放这一页） |
| `rowSelection` | `true` 或 `{ type?, showPro?, selectedKeys?, onChange?, preserve? }`；多选默认带「选中 N 项 / 清空 / 全选 / 反选」条，`preserve` 翻页保留选择 |
| `expandable` | `{ render(cell), rowExpandable?, defaultExpandAll? }`；`render` 在行作用域里 |
| `onRemove` | `(index, record) => void \| Promise`；删除前执行，按钮转圈，reject 则保留这一行 |
| `createRowKey` | 复制行（及没有 id 的新增行）的新 id，见 [useArrayTable](/reference/pro-hooks#usearraytable) |
| `title` / `toolbar` / `extra` / `footer` | 表头左 / 中 / 右（列配置按钮之前）/ 表尾左（分页器之前） |
| `settings` | 默认 `true`：列显隐、排序（拖动 ⋮⋮，↑ ↓ 给键盘）、密度 |
| `resizeable` | 拖动表头右边缘改列宽 |
| `onTableChange` | 表头排序 / 筛选变化，参数同 antd `Table` `onChange`（分页由底部分页器负责）；`useQueryTable().onTableChange` 可直接接 |
| `loading` / `bordered` / `showHeader` / `scroll` / `size` / `testId` | 交给 antd `Table` / 外层容器 |

| 成员 | 行为 |
|---|---|
| `ArrayTable.SortHandle` | `⋮⋮` 拖拽把手，放到另一行上移动过去 |
| `ArrayTable.Index` | 跨页的 1 起序号 |
| `ArrayTable.Remove` | `title?`、`confirm?: boolean \| string`；`onRemove` 执行时转圈 |
| `ArrayTable.MoveUp` / `MoveDown` | 首行 / 末行禁用 |
| `ArrayTable.Copy` | 在下方插入这一行的副本（id 由 `createRowKey` 生成，否则去掉） |
| `ArrayTable.Addition` | `title?`、`defaultValue?`（值每次克隆，或函数；默认 `{}`，同 `ArrayItems.Addition`，没有 `method`）；追加后跳到它所在的页 |
| `ArrayTable.ShadowAddition` | 使用草稿表单在弹窗（`popType="modal"`，默认）或抽屉中填写新行，自动继承外层数组的行模板规则，确认后追加；`onOk(values, table)` 返回 `false` 可自行处理；其余参数同 [useShadowForm](/reference/pro-hooks#useshadowform) |
| `ArrayTable.useTable()` | 在 `toolbar` / `footer` / 单元格里读表格状态 + 列配置（`useArrayTable` 的返回值加 `settings`） |
| `ArrayTable.useRow()` | 单元格里的 `{ key, index, position, record }`，建立在 [`useIndex`](/reference/react-hooks#useindex) / [`useRecord`](/reference/react-hooks#userecord) 上，`record` 是响应式的 |

行操作（`SortHandle`、`Remove`、`MoveUp`、`MoveDown`、`Copy`、`Addition`、`ShadowAddition`）和 `ArrayItems` 一样，只在数组可见、且不是 `readOnly` / `disabled` 时渲染（写在 `d.list.$readOnly` / `$disabled`，或 `fields: { list: { readOnly } }`；单元格各自用 `<Field readOnly>`）。`Index` 一直显示。

单元格里同样可以直接用 [`useArrayField()`](/reference/react-hooks#usearrayfield) / `useIndex()` / `useRecord()`。行操作按钮的文案走表单 `messages`（`add`、`remove`、`removeConfirm`、`moveUp`、`moveDown`、`copy`、`dragSort`、`selection*`、`density`、`columnSettings`）。可点的例子：[/play/array-table](/play/array-table)、[/play/array-table-shadow](/play/array-table-shadow)。

## useArrayEditable

```ts
useArrayEditable(): boolean
```

最近一层数组（`<ArrayField>` 的容器或行内）是否可编辑：`visible` 且不是 `readOnly` / `disabled`（自己的、祖先的、根上的，含 `useForm({ readOnly: true })` / `{ disabled: true }`）。为 false 时 `ArrayItems` / `ArrayCards` / `ArrayTable` 的动作按钮不渲染；自己写的行操作也用它。在数组外调用抛错。

## FormTab

```tsx
<FormTab activeKey? defaultActiveKey? onChange?={(key: string) => …} {...TabsProps}>
  <FormTab.Pane name?="base" tab="基本信息" disabled?>{/* 任意字段与布局 */}</FormTab.Pane>
</FormTab>
```

标签页容器（Formily `FormTab`）。子元素必须是 `FormTab.Pane`（可包在 Fragment 里，`false` / `null` 跳过；其他元素抛错）。每个面板都渲染（antd `forceRender`），不活动的只是隐藏：字段的值、JSX 规则、错误都在，提交照常校验和提交。标签标题带错误数徽标：面板里有错的字段数（`visible: false` 的字段错误已清掉，不会计入），`0` 时不显示。`submit()` 校验失败或 `form.validate()` 发现错误时，切到**第一个**含有这次错误的面板（受控时只调用 `onChange`），随后 `<Form>` 聚焦第一个有错的字段。

| 参数 | 行为 |
|---|---|
| `Pane.name` | 标签 key；默认下标字符串 |
| `Pane.tab` / `Pane.disabled` | 标题 / 禁用 |
| `activeKey` + `onChange` | 受控；`onChange(key)` 不改内部状态 |
| `defaultActiveKey` | 不受控初始页；默认第一个 |
| 其余 | 交给 antd `Tabs`（`items` 由面板生成） |

只是布局：不占值路径，也不改字段的四个布尔。`visible` / `disabled` / `readOnly` 沿字段路径继承（`useForm({ readOnly: true })` 时面板里的字段也是阅读态）。

## FormCollapse

```tsx
<FormCollapse activeKey?={string[]} defaultActiveKey?={string[]} onChange?={(keys: string[]) => …} accordion? {...CollapseProps}>
  <FormCollapse.Panel name?="base" header="基本信息" extra? collapsible?>{/* 字段 */}</FormCollapse.Panel>
</FormCollapse>
```

折叠面板容器（Formily `FormCollapse`），子元素规则、挂载与错误徽标同 `FormTab`（收起的面板 `forceRender`）。默认全部展开；`accordion` 时默认只展开第一个。`onChange` 总是给 `string[]`。提交 / `form.validate()` 失败时展开所有含有这次错误的面板（已展开的保持；`accordion` 时只展开第一个），受控时只调用 `onChange`。

## FormStep

```tsx
const step = useFormStep()
<FormStep step={step} {...StepsProps}>
  <FormStep.Step name? title="账号" description? subTitle? icon?>{/* 字段 */}</FormStep.Step>
</FormStep>
{step.isLast ? <Submit /> : <Button onClick={step.next}>下一步</Button>}
```

分步容器（Formily `FormStep`）：antd `Steps` 条 + 每步一个主体。所有主体都挂载，非当前步加 HTML `hidden`，所以前面步的值一直在；最后一步用普通 `<Submit />` / `<Form onSubmit>`，校验并提交全部步骤。某一步里有字段有错时，它在步骤条上是 `error` 状态。提交 / `form.validate()` 失败时回到**最早**含有这次错误的那一步（`step.goTo`，受控时只调用 `onChange`）；`next()` 只校验当前步，所以它的错误不会让你离开当前步。`current` / `items` / `onChange` 由容器控制，其余 props 交给 antd `Steps`。

## useFormStep

```ts
useFormStep(options?: { defaultCurrent?: number; current?: number; onChange?: (current: number) => void }): FormStepHandle

interface FormStepHandle {
  current: number      // 0 开始
  count: number        // <FormStep> 挂载前为 0
  isFirst: boolean
  isLast: boolean      // count 为 0 时也是 true
  next(): Promise<boolean>
  back(): void
  goTo(index: number): void
}
```

分步状态（Formily `FormStep.createFormStep()`）。在渲染按钮的组件里调用，不需要在 `<Form>` 里面；交给 `<FormStep step>` 后它才知道步数和表单。

- `next()`：取当前步里挂载的字段中可编辑的路径（`visible` 且不是 `readOnly` / `disabled`），`form.validate(paths)` 一次校验；无错前进一步并返回 `true`，有错停留返回 `false`。最后一步、`<FormStep>` 未挂载时返回 `false`。表单级 `validate` 抛错时 `console.error` 并返回 `false`，从不 reject。等待校验期间步数已被别处改变则不再前进（双击只前进一步）。
- `back()` / `goTo(i)`：不校验；`goTo` 夹在 `[0, count - 1]`。
- 受控（传 `current`）时三个方法只调用 `onChange`。
