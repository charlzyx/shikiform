## Test a form

Use the engine directly to test calculations, validation and submit values. For a React integration, render the form and drive its controls as a user would.

```tsx
import { fireEvent, render, screen, waitFor } from '@testing-library/react'
import { expect, test, vi } from 'vitest'
import { Form, Submit, typed, useField, useForm } from '@shikiform/react'

function EmailInput() {
  const field = useField<string>()
  return (
    <div>
      <label htmlFor={field.id}>{field.title}</label>
      <input
        id={field.id}
        value={field.value ?? ''}
        onChange={(e) => field.onChange(e.target.value)}
        onBlur={field.onBlur}
      />
      {field.errors[0] && <span role="alert">{field.errors[0]}</span>}
    </div>
  )
}

function Login({ onSubmit }: { onSubmit: (values: { email: string }) => void }) {
  const form = useForm({ initialValues: { email: '' } })
  const F = typed(form)
  return (
    <Form form={form} onSubmit={onSubmit}>
      <F.Field name="email" title="Email" required rules={{ format: 'email' }} component={[EmailInput]} />
      <Submit>Submit</Submit>
    </Form>
  )
}

test("Submit after validating email", async () => {
  const onSubmit = vi.fn()
  render(<Login onSubmit={onSubmit} />)
  const email = screen.getByRole('textbox', { name: "Email" })
  fireEvent.change(email, { target: { value: 'ada@example.com' } })
  fireEvent.blur(email)
  fireEvent.click(screen.getByRole('button', { name: "Submit" }))
  await waitFor(() => {
    expect(onSubmit).toHaveBeenCalledWith({ email: 'ada@example.com' })
  })
})
```

<Aside type="tip" title="Blur validation and submission timing">
Fields validate on `onBlur` and on submit by default. Trigger `fireEvent.blur` or submit before asserting error messages, and await `waitFor` because `form.submit()` resolves asynchronously. Remember that `omit: true` fields are excluded from `onSubmit`, while `$visible = false` fields still submit.
</Aside>

## Large lists

Each field state is tracked individually: editing one input re-runs only the reactions that read it and re-renders only components subscribed to that field.

- **Avoid watching whole arrays**: reading `d.items.$value` in a `reaction` subscribes to the whole array. Use `reaction.each` for per-row calculations—when rows move, insert, or get removed, row listeners follow their rows in linear O(n) time (~28 ms for 5,000 rows), and editing row 3 re-runs only row 3.
- **Do not `useWatch` an entire array and `.map` in the parent**: `<ArrayField>` subscribes only to row count, order, and keys while each cell updates through its own `<Field>`. The [large form example](/en/play/large) exposes per-cell render counts.
- **Virtual scrolling for long lists**: enable `virtualScroll={{ height: 400 }}` on `<ArrayField>` to mount only visible rows. Rules declared in `fields` and `reaction.each` calculations still run for offscreen rows.

## Server rendering

`useForm` runs directly during SSR (every live preview on this site is server-rendered before hydration). Keep SSR forms safe by following five rules:

- **One engine per form or request**: keep initial values deterministic so server HTML matches the browser, and never call `onChange` / `form.setValue` during render.
- **Pass an explicit `<Form id>` on React 16.8 / 17**: React 18+ auto-generates matching server/client field IDs via `useId()`. In React 16.8 or 17 SSR apps, pass a fixed `<Form id="...">` to avoid hydration mismatches.
- **Keep `reaction` synchronous**: do not read browser globals (`window`, `document`) or start fetches inside `reaction`. Run async work in `watch` and write responses back with `form.batch`. `useForm`-owned `EnumSource` loaders wait until client mount, avoiding leaked requests during SSR.
- **Honor abort signals in async validators**: when superseded (`signal.aborted`), clean up timers and resolve `undefined`; see [cross-field and async validation](/en/examples/forms#cross-field-and-asynchronous-validation).
- **Keep form values serializable**: store plain JSON data in the engine and convert rich widget objects inside `mapProps({ format, parse })`.
