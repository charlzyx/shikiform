title: "Common pitfalls"
description: "Recognize incorrect draft reads, path writes, scope names and field bindings."
---

Some mistakes throw `ShikiUsageError` in development; others quietly subscribe an effect to a wider path than you intended.

## Destructure child handles

Destructuring is only for picking child field handles; always read or assign `$` state directly on a handle.

### Do not reassign a destructured `$value`

Reassigning a local variable only changes that variable. Write through the handle to update the field.

```ts
let { $value } = d.user.name
$value = 'Ada'
```

```ts
const { name } = d.user
name.$value = 'Ada'
// Or write d.user.name.$value = 'Ada' directly.
```

### Enumerating a handle

Spread, rest and `Object.keys` enumerate a path proxy and throw in development. Pick child handles by name.

```ts
const { name, ...rest } = d.user
const copy = { ...d.user }
Object.keys(d.user)
```

```ts
const { name } = d.user
name.$value
const keys = Object.keys(d.user.$value)
```

### Destructuring an array

Use an indexed handle for a row or read the array's `$value`.

```ts
const [first] = d.items
```

```ts
const { name } = d.items[0]
name.$value
d.items.$value
reaction.each(draft.items, (row) => {
  row.name.$value
})
```

## Mutating stored values

Inside `reaction`, `watch`, and `batch`, an object or array `$value` is a writable draft. `d.user.$value.name = 'Ada'` is the path write `d.user.name.$value = 'Ada'`. `d.items.$value.push(row)` uses the same row operation as `useArrayField().push`. `getValue`, `form.values`, and a validator's `value` are not that draft:

```ts
// ✗ Throws ShikiUsageError in development; does not notify subscribers
form.getValue('user').name = 'Ada'
form.values.tags.push('x')
```

In development, those reads are read-only proxies: mutating them (including `value`, `ctx.root`, or `ctx.get()` inside a validator, as well as `Map.set/delete/clear`, `Set.add/delete/clear`, `Date.set*`, or `Object.setPrototypeOf`) throws `ShikiUsageError` and never notifies subscribers. In production, reads outside effects return the raw stored object. Update values outside effects with `form.setValue` or `useArrayField().push(row)`:

```ts
d.user.$value.name = 'Ada'
d.items.$value.push(row)
form.setValue('user.name', 'Ada')
```

The development read-only proxy is not `===` to the stored object (in production, outside an effect, it is). `indexOf`, `includes`, and `deepEqual` unwrap it automatically, so `rows.indexOf(rawRow)` still finds the row. Do not pass `useField().value` (or `form.binding(path).value`) to a table library that `push`es or `sort`s in place; the error names the field path.

`structuredClone(form.values)`, `postMessage`, and IndexedDB throw `DataCloneError` on that proxy in development only. Use `snapshot(form.values)` from `@shikiform/core` for a plain copy (including omitted fields), `getSubmitValues()` for final submitted data, and `toRaw(value)` for the live stored object.

Deep-frozen objects (such as Immer or Redux state) can still be read safely without triggering browser Proxy errors. Non-configurable, non-writable properties are returned as-is.

## Writing dynamic keys without subscribing to the whole record

`d.overrides[id].$value = price` navigates to a field and writes it. Spreading `d.overrides.$value` first reads the entire record. In a reaction, that read makes changes to other prices a dependency too. Spell indexes and keys on the draft (`d.items[i].qty`, `d.extra[key]`). `query(path)` is only for a path that is already a string, such as `query(pathOf('menus', pos)).$disabled = true` inside an effect. Outside an effect, use `form.getValue`.

```ts
watch.each(draft.rows, (row, { d }) => {
  const id = row.id.$value
  if (id) d.overrides[id].$value = row.price.$value
})
```

When a new row appears, `watch.each` does one dry run to record which fields you read (ignoring field writes during that dry run). Whenever that row actually triggers later, its tracked fields refresh and follow the row if rows move, insert, or get removed. Here each row watches only its own ID and price. Assign target fields through a handle (`d.overrides[id].$value = ...`); mutating an object read from `$value` or calling `push` during that first dry run throws in development.

For a one-time append when a source changes, call `d.items.$value.push(row)` in the action of `watch(source, action)`. An unconditional `push` inside a `reaction` reads and changes the same array on every pass and can cause a cycle. The [dynamic fields example](/en/guide/linkage#dynamic-object-fields) shows how to derive state per object key and render the current fields.

## Reading a buffered write

Within the same pass, reading `$value`, `$enum`, `$rules`, or UI state immediately reflects what you just wrote: `d.total.$value = price * qty` followed by `d.tax.$value = d.total.$value * 0.1` uses the new total, and two `d.rows.$value.push(...)` calls append both rows.

Boolean flags (`$visible`, `$disabled`, `$readOnly`, `$omit`, `$required`) do not immediately reflect earlier writes in the same pass—reading one back sees the old value and throws `ShikiUsageError` in development. Store the new flag in a local variable first.

## Do not mutate a Date, Map, Set, or class instance inside `$componentProps`

Those values are not plain objects, so the draft returns them raw. `date.setMonth(1)`, `map.set(key, value)`, and `box.n = 1` edit the declared instance: nothing is written and no reaction is notified. Replace the value:

```ts
d.city.$componentProps.date = new Date('2021-05-01')
const cache = d.city.$componentProps.cache as Map<string, number>
d.city.$componentProps.cache = new Map(cache).set('a', 1)
```

`structuredClone` cannot clone a draft (`DataCloneError`). Spread or `JSON.stringify` copies the plain data you read; do not pass the draft proxy to `structuredClone`.

## Repeating the scope prefix

Names inside object and row scopes are relative. Repeating the prefix creates an invalid nested path.

```tsx
<ObjectField name="address">
  <Field name="address.city" />
</ObjectField>
```

```tsx
<F.ObjectField name="address">
  {(obj) => <obj.Field name="city" decorator={[FormItem]} component={[Input]} />}
</F.ObjectField>
```

## Hiding a field and submitting it

Set `$omit` separately when hidden data should be removed from the payload.

```ts
d.taxId.$visible = false
```

```ts
d.taxId.$visible = false   // Hidden and unvalidated, still included on submit.
d.taxId.$omit = true       // Render and validate, exclude from submission.
d.taxId.$visible = false   // Together these flags skip rendering, validation and submission.
d.taxId.$omit = true
```

There is no "hidden yet still validated" flag. Keep fields mounted if they should still validate (for example, hiding inactive tabs with CSS or declaring rules in `useForm({ fields })`; see [Tabs and unmounted fields](/en/examples/forms#tabs-and-unmounted-fields)).

## Using decorator props as a value binding

A decorator's `control` supplies label and error information. Connect `value` and `onChange` with `useField` or `connect`.

```tsx
function Bad() {
  const { control } = useFieldDecorator()
  return <input {...control} />
}
```

```tsx
function NameInput() {
  const field = useField<string>()
  return (
    <input
      id={field.id}
      value={field.value ?? ''}
      onChange={(event) => field.onChange(event.target.value)}
      onBlur={field.onBlur}
    />
  )
}
```

## Computing a value in a watch

A watch skips initialization. Use a reaction to derive state from the first pass onward.

```ts
watch((d) => d.price.$value, (d) => {
  d.total.$value = d.price.$value * 2
})
```

```ts
reaction((d) => {
  d.total.$value = (d.price.$value ?? 0) * 2
})

watch((d) => d.province.$value, (d) => {
  d.city.$value = undefined
})
```

## Calling `onChange` or `form.setValue` during render

```tsx
// ✗ Mutating the form during render also writes during SSR or discarded concurrent renders
function BadInput() {
  const field = useField<string>()
  if (!field.value) field.onChange('default')
  return <input value={field.value ?? ''} onChange={(e) => field.onChange(e.target.value)} />
}
```

Never call `field.onChange` or `form.setValue` directly inside render. Server-side rendering or abandoned React renders will still execute those writes and mutate the form store. Set defaults via `initialValues` or `reaction`, and move imperative writes into event handlers or `useEffect`:

```tsx
// ✓ Write from an event handler or useEffect
function GoodInput() {
  const field = useField<string>()
  useEffect(() => {
    if (!field.value) field.onChange('default')
  }, [field.value, field.onChange])
  return <input value={field.value ?? ''} onChange={(e) => field.onChange(e.target.value)} />
}
```

## Using a reaction draft across `await` or calling `form.reset` / `submit` inside a `reaction`

Keep `reaction` synchronous:

- Do not make `reaction` `async`—its draft handle expires as soon as the function returns. Writing through `d` after `await` throws `ShikiUsageError` in development and is ignored in production.
- Calling `form.reset` or `form.submit` synchronously inside a `reaction` interrupts the active update pass and throws `ShikiUsageError` in development (development-only check). Calling `form.setValue`, `form.patchValues`, or `form.getValue` during a `reaction`, `watch`, or `batch` reads and writes the same temporary state as the draft: reads immediately see edits made so far, and writes apply or roll back together when the batch finishes.

Prefer direct draft assignments (`d.x.$value = …`) inside `reaction`, and move async requests or `reset` / `submit` actions into `watch` (writing async results back with `form.setValue` or `form.batch`).

## Bare property writes and misspelled `$` states

```ts
// ✗ Missing `$`
d.user.name.value = 'Ada'

// ✗ Misspelled state name
d.user.name.$valeu = 'Ada'
const v = d.user.name.$valeu
```

- Assigning a non-`$` property on a handle throws `ShikiUsageError` in development and is ignored in production (without throwing a native `TypeError`).
- Reading or writing a missing near-spelling of a reserved `$` state throws `ShikiUsageError` in development; in production, reads return `undefined` (never a truthy child handle) and writes are ignored. Existing non-reserved own data keys starting with `$` (like `$values`) still resolve as normal child fields.
