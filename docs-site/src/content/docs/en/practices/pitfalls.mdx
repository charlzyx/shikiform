title: "Common pitfalls"
description: "Recognize incorrect draft reads, path writes, scope names and field bindings."

## Destructure child handles

Destructuring `$value` gives a snapshot. Assign to the handle's state to update the field. In each pair below, the second snippet shows the correction.

```ts
const { $value } = d.user
$value = 'Ada'
```

```ts
const { name } = d.user
name.$value = 'Ada'
// Or write d.user.name.$value = 'Ada' directly.
```

### Enumerating a handle

Spread, rest and `Object.keys` enumerate a path proxy and throw in development. Pick child handles by name.

```ts
const { name, ...rest } = d.user
const copy = { ...d.user }
Object.keys(d.user)
```

```ts
const { name } = d.user
name.$value
const copy = d.user.$value
```

### Destructuring an array

Use an indexed handle for a row or read the array's `$value`.

```ts
const [first] = d.items
```

```ts
const { name } = d.items[0]
name.$value
d.items.$value
reaction.each((d) => d.items, (row) => {
  row.name.$value
})
```

## Mutating stored values

Inside `reaction`, `watch`, and `batch`, an object or array `$value` is a writable draft. `d.user.$value.name = 'Ada'` is the path write `d.user.name.$value = 'Ada'`. `d.items.$value.push(row)` uses the same row operation as `useArrayField().push`.

```ts
d.user.$value.name = 'Ada'
d.items.$value.push(row)
```

`getValue`, `form.values`, and a validator's `value` are not that draft. In development those reads are read-only views. The view is not `===` to the stored object (it is, in production, outside an effect). `indexOf` / `includes` and `deepEqual` peel the view, so `rows.indexOf(rawRow)` still matches. Do not pass `binding().value` to a table that `push`es or `sort`s it; the error names the field path.

`structuredClone(form.values)`, `postMessage`, and IndexedDB throw `DataCloneError` on that view in development only. `snapshot(form.values)` from `@shikiform/core` is a plain copy, including omitted fields. `getSubmitValues()` is the submit payload. `toRaw(value)` is the live stored object.

A deep-frozen tree (immer / Redux) can be read. A non-configurable, non-writable child is returned raw because wrapping it would throw a proxy `TypeError`.

## Reading a buffered write

`$value`, `$enum`, `$rules`, and UI state replay pending writes, so a second read in the same pass sees the new value. `d.total.$value = price * qty` then `d.tax.$value = d.total.$value * 0.1` uses that total. `d.rows.$value.push(a)` then `d.rows.$value.push(b)` appends both.

Flags (`$visible`, `$disabled`, `$readOnly`, `$omit`, `$required`) do not replay. Reading one after writing it in the same pass sees the old value and throws `ShikiUsageError` in development. Keep the new flag in a local.

## Do not mutate a Date, Map, Set, or class instance inside `$componentProps`

Those values are not plain objects, so the draft returns them raw. `date.setMonth(1)`, `map.set(key, value)`, and `box.n = 1` edit the declared instance: nothing is written and no reaction is notified. Replace the value:

```ts
d.city.$componentProps.date = new Date('2021-05-01')
const cache = d.city.$componentProps.cache as Map<string, number>
d.city.$componentProps.cache = new Map(cache).set('a', 1)
```

`structuredClone` cannot clone a draft (`DataCloneError`). Spread or `JSON.stringify` copies the plain data you read; do not pass the draft proxy to `structuredClone`.

## Repeating the scope prefix

Names inside object and row scopes are relative. Repeating the prefix creates an invalid nested path.

```tsx
<ObjectField name="address">
  <Field name="address.city" />
</ObjectField>
```

```tsx
<F.ObjectField name="address">
  {(obj) => <obj.Field name="city" decorator={[FormItem]} component={[Input]} />}
</F.ObjectField>
```

## Hiding a field and submitting it

Set `$omit` separately when hidden data should be removed from the payload.

```ts
d.taxId.$visible = false
```

```ts
d.taxId.$visible = false   // Hidden and unvalidated, still included on submit.
d.taxId.$omit = true       // Render and validate, exclude from submission.
d.taxId.$visible = false   // Together these flags skip rendering, validation and submission.
d.taxId.$omit = true
```

## Using decorator props as a value binding

A decorator's `control` supplies label and error information. Connect `value` and `onChange` with `useField` or `connect`.

```tsx
function Bad() {
  const { control } = useFieldDecorator()
  return <input {...control} />
}
```

```tsx
function NameInput() {
  const field = useField<string>()
  return (
    <input
      id={field.id}
      value={field.value ?? ''}
      onChange={(event) => field.onChange(event.target.value)}
      onBlur={field.onBlur}
    />
  )
}
```

## Computing a value in a watch

A watch skips initialization. Use a reaction to derive state from the first pass onward.

```ts
watch((d) => d.price.$value, (d) => {
  d.total.$value = d.price.$value * 2
})
```

```ts
reaction((d) => {
  d.total.$value = (d.price.$value ?? 0) * 2
})

watch((d) => d.province.$value, (d) => {
  d.city.$value = undefined
})
```
