## Configure rules

Declare rules on `<Field>` or in `fields`:

- **Empty values** (`''`, `null`, `undefined`) are checked only by `required` (`min`, `max`, `minLength`, `pattern`, and `format` pass empty values). When `min` or `max` is set, `NaN` fails the range check. Regexes with `g` or `y` flags always test from index `0` without changing your `lastIndex`.
- **Warnings** (`level: 'warning'`) write messages to `$warnings` / `field.warnings` without blocking submission or turning `canSubmit` off. Async warnings can finish after `submit()` resolves, while explicit `form.validate()` still waits for them.
- **Custom `validator(value, ctx)`** works the same for sync and async functions: return a non-empty string or `string[]` to fail with those messages; return `false` to fail with the rule's `message` (or fallback); return `true`, `null`, `undefined`, or `''` to pass. Any other return value throws `ShikiUsageError` in development (and fails with the fallback message in production).
- **Dynamic `$rules`** in effects expects an array of rule objects (assign `[]` to clear). Invalid values throw `ShikiUsageError` in development and are ignored in production.
- **Schemas**: pass a Standard Schema (Zod, Valibot, ArkType) to a field's `rules` or to form-level `validate`. Errors from form validation or field schemas — including async checks still running — follow array rows and tree nodes as they move, and are dropped if the row or node is removed or replaced.

```tsx preview play=schema
import { useState } from 'react';
import { z } from 'zod';
import { enUS, Field, Form, Watch, useForm, type Draft } from '@shikiform/react';
import { Button, FieldCheckbox, FieldInput, siteKit } from '@site/ui';

type Values = { username: string; email: string; password: string; confirm: string; agree: boolean };
const TAKEN = ['admin', 'root'];

export default function App() {
  const [result, setResult] = useState('');
  const form = useForm<Values>({
    messages: enUS,
    initialValues: { username: '', email: '', password: '', confirm: '', agree: false },
    fields: {
      username: { asyncDebounceMs: 300 }, // Run async rules after 300 ms without new input.
      confirm: { omit: true }, // Validate but exclude from submission.
    },
    // Cross-field validation returns messages by path.
    validate: (values) => (values.confirm && values.confirm !== values.password ? { confirm: "Passwords do not match" } : undefined),
  });
  return (
    <Form form={form} kit={siteKit} onSubmit={(values) => setResult(JSON.stringify(values))} style={{ maxWidth: 420 }}>
      <Field
        name="username"
        title="Username"
        required
        component={[FieldInput, { placeholder: 'Try typing admin' }]}
        rules={[
          { minLength: 3, message: "At least 3 characters" },
          {
            validator: (value, { signal }) => new Promise<string | null>((resolve) => {
              const timer = setTimeout(() => resolve(TAKEN.includes(String(value)) ? "Username already taken" : null), 400);
              signal?.addEventListener('abort', () => clearTimeout(timer));
            }),
          },
        ]}
      />
      <Field
        name="email"
        title="Email"
        required
        rules={z.string().email("Invalid email address").or(z.literal(''))}
        component={[FieldInput, { placeholder: 'ada@example.com' }]}
      />
      <Field
        name="password"
        title="Password"
        required
        component={[FieldInput, { type: 'password', placeholder: 'At least 6 characters' }]}
        rules={[
          { minLength: 6, message: "At least 6 characters" },
          // Show a warning and allow submission.
          { validator: (value) => (/\d/.test(String(value)) && /[a-z]/i.test(String(value)) ? null : "Use both letters and digits"), level: 'warning' },
        ]}
      />
      <Field name="confirm" title="Confirm password" required component={[FieldInput, { type: 'password' }]} />
      <Field name="agree" rules={{ isTrue: true, message: "Confirm that you accept the terms" }}>
        <FieldCheckbox>I have read and accept the terms</FieldCheckbox>
      </Field>
      <div>
        <Watch select={(d: Draft<Values>) => d.$submitting}>
          {(submitting) => (
            <Button variant="primary" type="submit" loading={submitting}>
              {submitting ? "Submitting…" : "Register"}
            </Button>
          )}
        </Watch>
      </div>
      {result && <pre aria-live="polite">{result}</pre>}
    </Form>
  );
}
```

## Triggers and asynchronous validation

The defaults are blur and submit. Add change validation where needed. `asyncDebounceMs` delays asynchronous rules. Pass the validator's abort signal to requests so newer input can cancel obsolete work. Hidden, disabled and read-only fields skip validation.

## Handle submission

- **Calling `form.validate(...)`**:
  - `validate()` validates the whole form and resolves `getSubmitValues()` (`TSubmit`; `{}` when root `$omit` is `true`).
  - `validate(path)` validates that path and resolves its value (`PathValue`; dot and bracket paths are equivalent). Even if that path is omitted, it is still validated and returned; only descendants with their own `omit` are stripped.
  - `validate([paths])` resolves a nested object containing only those paths (`ValidatePick`).
  - Every resolved value is a safe copy (plain objects, arrays, `Date`, `Map`, and `Set` are cloned; class instances, functions, and React elements stay by reference), so mutating it does not touch form state. Rules inspect the snapshot taken when validation starts, and `validate()` does not rerun if values change mid-flight.
  - Failures reject `FieldError[]` (a thrown error from form-level `validate` rejects as-is). If a checked row moves while a scoped `validate(...)` is running, errors report at the row's new position while a passing call returns current values at the requested paths; keyed tree nodes moved across parents remain part of the scoped check.
- **Submitting (`form.submit`)**:
  - Waits for running async rules (excluding async warnings). If values change while waiting, or if the enabled option set changes under `enumPolicy: 'error'` (reordering or label edits do not trigger a retry), validation reruns up to 3 rounds so the submitted payload always matches the validated data.
  - Resolves `onValid`'s return value (or the submit values when `onValid` returns `undefined`). A newer `submit()` immediately rejects an earlier call still validating with `SubmitSupersededError`, while an already-running `onValid` keeps `$submitting` `true`.
- **Scoped `reset(path)` during async checks**:
  - Cancels pending debounced or async checks only for overlapping paths, leaving unrelated fields and form-level checks alone.
  - A form validation started before a full `reset()` still settles its own promise without writing stale errors back to the reset form; if `reset()` runs while an async `warning` is pending, keyed rows map their result to their restored positions.
  - Resetting a single cell (e.g. `reset('rows.0.note')`) keeps running checks on sibling fields, primitive array slots, and untouched rows outside the reset scope. Whole-row, whole-array, or full-form resets discard stale results when anonymous rows are re-cloned and cannot be uniquely matched. Partial tree resets match keyed nodes across parents (on duplicate `rowKey`, only a surviving object with the original reference is matched).
  - Aborted checks never count as passed — even if reset to the same values, the next `submit()` runs them again. Replacing a parent object restarts pending validation only for descendants whose values actually changed.

```ts
const values = await form.validate()
const user = await form.validate('user')
const picked = await form.validate(['name', 'user.city'])
```

try {
  const values = await form.submit(async (draft) => {
    await api.save(draft)
  })
  form.setInitialValues(form.values)
} catch (error) {

Use `onInvalid` for field errors and `onSubmitError` for other failures. The form focuses the first invalid control when its ID is connected correctly.

```tsx
<Form
  form={form}
  id="profile"
  onSubmit={save}                                   // Called after validation. Async callbacks are supported.
  onInvalid={(errors) => scrollToField(errors[0].path)}
  onSubmitError={(error) => message.error(String(error))}  // Handles save errors. Defaults to console.error.
>
  …
</Form>
<button type="submit" form="profile">Save</button>   {/* Other native props pass through to the form. */}
```

## Built-in messages and localization

The library defaults to Chinese. Set `messages: enUS` on an English form or use `setDefaultMessages(enUS)` for an application. Override individual messages with text or a function. A rule's own message takes precedence.

```ts
import { createForm, enUS, setDefaultMessages } from '@shikiform/react'

createForm({ messages: enUS })                       // Select English for one form.
createForm({
  messages: {
    required: 'Required',
    minLength: ({ minLength }) => `At least ${minLength} characters`,  // Message functions receive rule parameters.
    enum: ({ value }) => `${value} is not an option`,
  },
})
setDefaultMessages(enUS)                              // Set the application default once at startup.
```

## Server errors

Map server errors to field paths with `setErrors`. Use the empty path `''` for a form-wide message and `null` to clear one field. Changing a related value, validating again, or resetting clears an external error. Inside `batch` or `watch`, `setErrors` and `clearErrors` apply in call order to whichever field is currently at that path (for example, after a row move they target the row now at that index) and roll back if a nested `batch` throws; reading `form.errors` or `$errors` during the batch still shows the previously committed errors until the batch finishes.

```ts
await form.submit(async (values) => {
  const res = await api.register(values)
  if (res.status === 409) form.setErrors({ username: "Username already exists" })
  // Set several errors at once. The empty path addresses the form.
  // form.setErrors({ email: ['Invalid format'], '': 'Server busy' })
})
```

## Validate unmounted fields

Rules in `fields` or effects survive component unmounting. JSX declarations last for the current mount. A tab that only hides its content keeps the field mounted. For a virtual list, declare rules in the model so offscreen rows validate.
