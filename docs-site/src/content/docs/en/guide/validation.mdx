## Configure rules

Declare rules on a field or in `fields`. Empty strings, null and undefined are checked by `required` alone; when `min` or `max` is set, `NaN` fails the range check; stateful `pattern` regexes (`g` / `y`) always test from index `0` and preserve the caller's `lastIndex`. Set `level: 'warning'` for a message that allows submission (async warnings may publish after `submit()` finishes without blocking it, while explicit `validate()` still awaits warnings). Sync and async `validator` functions share one runtime return contract: a non-empty string or `string[]` fails with those messages, `false` fails with the rule's `message` or fallback message, `true` / `null` / `undefined` / `''` passes, and any other value throws `ShikiUsageError` in development (or fails with fallback in production). In effects, `$rules` expects an array of rule objects (use `[]` to clear); invalid shapes throw `ShikiUsageError` in development and are ignored in production. Give a field or the whole form a Standard Schema validator for more complex checks. Form-level validation and field Schema errors (including in-flight async results) follow surviving array rows and tree nodes as they move, and are discarded when a row or node is removed or replaced.

```tsx preview play=schema
import { useState, type ReactNode } from 'react';
import { z } from 'zod';
import { Checkbox, CheckboxIndicator } from '@ui-sdk/react/checkbox';
import { enUS, Field, Form, Watch, useField, useFieldDecorator, useForm, type Draft } from '@shikiform/react';

type Values = { username: string; email: string; password: string; confirm: string; agree: boolean };
const TAKEN = ['admin', 'root'];

function FieldItem({ children }: { children?: ReactNode }) {
  const d = useFieldDecorator();
  return (
    <div style={{ marginBottom: 8 }}>
      {d.label && (
        <label {...d.labelProps} style={{ display: 'inline-block', width: 72 }}>
          {d.required && <span style={{ color: 'crimson' }}>* </span>}
          {d.label}
        </label>
      )}
      {children}
      {d.errorProps && <small {...d.errorProps} style={{ color: 'crimson', marginLeft: 8 }}>{d.errors[0]}</small>}
      {!d.errorProps && d.warningProps && <small {...d.warningProps} style={{ color: '#b45309', marginLeft: 8 }}>{d.warnings[0]}</small>}
    </div>
  );
}

function TextInput({ type = 'text' }: { type?: string }) {
  const field = useField<string>();
  return (
    <input id={field.id} type={type} value={field.value ?? ''}
      onChange={(e) => field.onChange(e.target.value)} onBlur={field.onBlur} />
  );
}

function AgreeCheckbox({ children }: { children?: ReactNode }) {
  const field = useField<boolean>();
  return (
    <label style={{ display: 'inline-flex', alignItems: 'center', gap: 6, cursor: 'pointer' }}>
      <Checkbox id={field.id} checked={Boolean(field.value)} onCheckedChange={(checked) => field.onChange(checked === true)}>
        <CheckboxIndicator>✓</CheckboxIndicator>
      </Checkbox>
      {children}
    </label>
  );
}

export default function App() {
  const [result, setResult] = useState('');
  const form = useForm<Values>({
    messages: enUS,
    initialValues: { username: '', email: '', password: '', confirm: '', agree: false },
    fields: {
      username: { asyncDebounceMs: 300 }, // Run async rules after 300 ms without new input.
      confirm: { omit: true }, // Validate but exclude from submission.
    },
    // Cross-field validation returns messages by path.
    validate: (values) => (values.confirm && values.confirm !== values.password ? { confirm: "Passwords do not match" } : undefined),
  });
  return (
    <Form form={form} onSubmit={(values) => setResult(JSON.stringify(values))}>
      <Field name="username" title="Username" required decorator={[FieldItem]} component={[TextInput]}
        rules={[
          { minLength: 3, message: "At least 3 characters" },
          { validator: (value, { signal }) => new Promise<string | null>((resolve) => {
            const timer = setTimeout(() => resolve(TAKEN.includes(String(value)) ? "Username already taken" : null), 400);
            signal?.addEventListener('abort', () => clearTimeout(timer));
          }) },
        ]} />
      <Field name="email" title="Email" required rules={z.string().email("Invalid email address").or(z.literal(''))} decorator={[FieldItem]} component={[TextInput]} />
      <Field name="password" title="Password" required decorator={[FieldItem]} component={[TextInput, { type: 'password' }]}
        rules={[
          { minLength: 6, message: "At least 6 characters" },
          // Show a warning and allow submission.
          { validator: (value) => (/\d/.test(String(value)) && /[a-z]/i.test(String(value)) ? null : "Use both letters and digits"), level: 'warning' },
        ]} />
      <Field name="confirm" title="Confirm password" required decorator={[FieldItem]} component={[TextInput, { type: 'password' }]} />
      <Field name="agree" rules={{ isTrue: true, message: "Confirm that you accept the terms" }} decorator={[FieldItem]}>
        <AgreeCheckbox>I have read and accept the terms</AgreeCheckbox>
      </Field>
      <Watch select={(d: Draft<Values>) => d.$submitting}>
        {(submitting) => <button type="submit" disabled={submitting}>{submitting ? "Submitting…" : "Register"}</button>}
      </Watch>
      <pre aria-live="polite">{result}</pre>
    </Form>
  );
}
```

## Triggers and asynchronous validation

The defaults are blur and submit. Add change validation where needed. `asyncDebounceMs` delays asynchronous rules. Pass the validator's abort signal to requests so newer input can cancel obsolete work. Hidden, disabled and read-only fields skip validation.

## Handle submission

`validate()` resolves `getSubmitValues()` (`TSubmit`; root `$omit: true` yields `{}`). `validate(path)` resolves that value (`PathValue`; bracket and dot paths normalize identically at runtime). The path itself is returned even when it is omitted, including descendants omitted only because of that path; a descendant's own `omit` is removed. `validate([paths])` resolves a nested object of only those paths (`ValidatePick`). Each result is a copy of the values current when the call finishes. Plain objects, arrays, `Date`, `Map`, and `Set` are copied. Class instances, functions, and React elements keep the same reference. Editing the copy does not write back. Rules read the snapshot from the start of the pass, and `validate()` does not rerun if values change during it. All three reject `FieldError[]` on failure; a throw from a form-level `validate` rejects as-is. If a checked row moves while a scoped `validate(path)` or `validate([paths])` is in flight, failures reject at the row's current coordinates, whereas passing calls still resolve the current values at the requested paths; keyed tree nodes moved across parents still belong to the original scoped validation. `submit(onValid?)` waits for validation (excluding async warnings) and reruns if values change or if the enabled option value set changes under `enumPolicy: 'error'` (reordering or label-only updates do not trigger retries), then returns the callback's result or the submit values if the result is undefined. A later `submit()` immediately rejects an earlier call still in validation with `SubmitSupersededError`, while an already-started `onValid` continues counting toward `submitting`. Scoped `reset(path)` cancels queued debounced validation and invalidates in-flight validation only for overlapping scopes; pre-reset form validation still settles its own promise without writing stale state, and if `reset` occurs while awaiting an async `warning`, the original call's verdict maps keyed rows to their restored coordinates; resetting only a single field within a row (e.g. `reset('rows.0.note')`) preserves in-flight validation verdicts for other untouched fields in the same row, stale verdicts are discarded only when a whole-row reset leaves a cloned anonymous row without a unique match, and primitive array entries preserve in-flight validation verdicts by index slot. A partial tree `reset` matches keyed nodes moved across parents within the scope of the entire registered tree; when duplicate `rowKey` values occur, the original validation verdict follows only a surviving object that keeps its original reference, and is discarded when no unique match exists. Resetting to identical values still reruns previously aborted validation on the next submit. Replacing a parent object restarts pending validation only for descendants whose values actually changed.

```ts
const values = await form.validate()
const user = await form.validate('user')
const picked = await form.validate(['name', 'user.city'])
```

try {
  const values = await form.submit(async (draft) => {
    await api.save(draft)
  })
  form.setInitialValues(form.values)
} catch (error) {
  if (isFieldErrors(error)) console.log(error[0]?.path)

Use `onInvalid` for field errors and `onSubmitError` for other failures. The form focuses the first invalid control when its ID is connected correctly.

```tsx
<Form
  form={form}
  id="profile"
  onSubmit={save}                                   // Called after validation. Async callbacks are supported.
  onInvalid={(errors) => scrollToField(errors[0].path)}
  onSubmitError={(error) => message.error(String(error))}  // Handles save errors. Defaults to console.error.
>
  …
</Form>
<button type="submit" form="profile">Save</button>   {/* Other native props pass through to the form. */}
```

## Built-in messages and localization

The library defaults to Chinese. Set `messages: enUS` on an English form or use `setDefaultMessages(enUS)` for an application. Override individual messages with text or a function. A rule's own message takes precedence.

```ts
import { createForm, enUS, setDefaultMessages } from '@shikiform/react'

createForm({ messages: enUS })                       // Select English for one form.
createForm({
  messages: {
    required: 'Required',
    minLength: ({ minLength }) => `At least ${minLength} characters`,  // Message functions receive rule parameters.
    enum: ({ value }) => `${value} is not an option`,
  },
})
setDefaultMessages(enUS)                              // Set the application default once at startup.
```

## Server errors

Map server errors to field paths with `setErrors`. Use the empty path for a form-wide message and `null` to clear one field. Changing a related value, validating again or resetting can clear an external error. Inside `batch` or `watch`, `setErrors` and `clearErrors` target fields in call order using the working tree coordinates at that point (after a row move, hitting the row currently at that coordinate) and roll back if a nested `batch` throws; reading `form.errors` or `$errors` inside the batch still returns the committed state, and changes settle together when the batch finishes.

```ts
await form.submit(async (values) => {
  const res = await api.register(values)
  if (res.status === 409) form.setErrors({ username: "Username already exists" })
  // Set several errors at once. The empty path addresses the form.
  // form.setErrors({ email: ['Invalid format'], '': 'Server busy' })
})
```

## Validate unmounted fields

Rules in `fields` or effects survive component unmounting. JSX declarations last for the current mount. A tab that only hides its content keeps the field mounted. For a virtual list, declare rules in the model so offscreen rows validate.
