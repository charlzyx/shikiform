The form engine owns the value tree and field state. The view subscribes to the paths it displays.

## Vocabulary

| Term | Meaning |
|---|---|
| Form instance | The engine returned by `createForm` or `useForm`. |
| Draft | The argument to `reaction`, `watch` and `form.batch`. |
| Handle | A path such as `d.user.name`. Access a `$` member to read or write state. |
| Decorator and component | The field's label/error wrapper and its input respectively. |
| Effects | `reaction` derives state. `watch` runs an action when its source changes. `each` scopes an effect to each row. |

## Handles and values

```ts
d.user.name.$value            // Read the value and register a dependency in reactions.
d.user.name.$value = 'Ada'    // Update the field value.
d.user.name.$required = true  // Change whether this field is required.
d.items.$value                // Read the array data through the handle's $value.
```

Inside a reaction, a watch action or a batch, `d.user.$value.name = 'Ada'` and `d.user.name.$value = 'Ada'` both update `user.name`. Outside those callbacks, use `form.setValue('user.name', 'Ada')`. For an array, read `d.items.$value` or use `reaction.each`. A field named `value` still uses `d.value.$value`; existing non-reserved own data keys starting with `$` (such as `$values`) also resolve as child field paths (`d.$values.$value`), while missing near-spellings of reserved state names are flagged as typos.

### Destructuring

Destructure child handles, then read or write their state.

```ts
const { name } = d.user // name is still a handle for d.user.name.
name.$value = 'Ada'
```

Spreading a handle, collecting rest properties, calling `Object.keys` or destructuring it as an array throws in development. Try changing several fields together with `form.batch`.

```tsx preview
import { enUS, Field, Form, Watch, useForm, type Draft } from '@shikiform/react';
import { Button, FieldInput, siteKit } from '@site/ui';

type Values = { user: { name: string; email: string } };

export default function App() {
  const form = useForm<Values>({ messages: enUS, initialValues: { user: { name: 'Ada', email: '' } } });
  return (
    <Form form={form} kit={siteKit} style={{ maxWidth: 420 }}>
      <Field name="user.name" title="Name" component={FieldInput} />
      <Field name="user.email" title="Email" component={[FieldInput, { placeholder: 'ada@example.com' }]} />
      <div style={{ display: 'flex', gap: 8, flexWrap: 'wrap' }}>
        <Button size="sm" onClick={() => form.batch((d) => { d.user.name.$value = 'Grace'; })}>Write user.name</Button>
        <Button size="sm" onClick={() => form.batch((d) => { d.user.email.$required = !d.user.email.$required; })}>Toggle required email</Button>
        <Button size="sm" onClick={() => form.batch((d) => { d.user.email.$readOnly = !d.user.email.$readOnly; })}>Toggle read-only mode</Button>
      </div>
      <Watch select={(d: Draft<Values>) => d.user.$value}>{(user) => <pre>{JSON.stringify(user)}</pre>}</Watch>
    </Form>
  );
}
```

## Field state

| State | Purpose |
|---|---|
| `$value` | Current data. Computed fields remain editable and submit by default. |
| `$required`, `$rules` | Validation configuration, including effects that survive unmounting. |
| `$enum` | Static or asynchronous options. Assign `[]` to clear or `undefined` to restore the lower layer. |
| `$title`, `$description` | Label and help text. |
| `$component`, `$decorator` and their props | Select or configure the control and its wrapper. |
| `$errors`, `$warnings`, `$validating`, `$touched` | Read-only validation and interaction state. |
| `$dirty`, `$edited` | Difference from the baseline, and whether a user has edited the field since reset. |
| `d.$canSubmit`, `d.$submitting`, `d.$submitCount` | Form-wide submission state. |

## Four independent flags

Four independent switches control display and submission: `visible`, `disabled`, `readOnly`, and `omit`.

- A hidden (`visible: false`), `disabled`, or `readOnly` field skips validation and clears existing errors, while still submitting its value.
- `omit` alone controls whether a field is excluded from submission. Setting `$omit = true` on the root submits `{}` and keeps `form.dirty` `false` (explicit `validate(path)` still validates and returns that path).
- All four inherit from parent paths: `visible`, `disabled`, and `readOnly` can be overridden per child, while an omitted ancestor always removes its whole subtree from submission. [Compare the four states](/en/basics/state).

## Declare fields before they mount

Use `fields` for rules and options that apply even when their components are absent. Use `rows.*.name` for settings that follow each row. An exact index belongs to the path.

```tsx preview play=tabs
import { enUS, Field, Form, Watch, useForm, type Draft } from '@shikiform/react';
import { Badge, Button, FieldSelect, FieldTextarea, FormItem } from '@site/ui';

type Values = { city: string; note: string; items: { name: string }[] };

export default function App() {
  const form = useForm<Values>({
    messages: enUS,
    initialValues: { city: 'sh', note: '', items: [{ name: '' }, { name: '' }] },
    fields: {
      city: {
        title: "City",
        decorator: [FormItem],
        component: [FieldSelect],
        enum: [{ label: "Shanghai", value: 'sh' }, { label: "Beijing", value: 'bj' }],
      },
      note: {
        title: "Notes",
        description: "Description from fields",
        decorator: [FormItem],
        component: [FieldTextarea, { rows: 2, placeholder: "Optional notes…" }],
      },
      // A template applies to every current and future row.
      'items.*.name': { required: true },
    },
  });
  return (
    <Form form={form} style={{ maxWidth: 420 }}>
      <Field name="city" />
      <Field name="note" />
      <div style={{ display: 'flex', alignItems: 'center', gap: 10, flexWrap: 'wrap' }}>
        <Button variant="outline" onClick={() => { void form.validate().catch(() => {}); }}>
          Validate unmounted items
        </Button>
        <Watch select={(d: Draft<Values>) => d.items.$errors}>
          {(errors) => (
            <Badge variant={errors.length ? 'danger' : 'default'}>
              Errors: {errors.join('; ') || "None"}
            </Badge>
          )}
        </Watch>
      </div>
    </Form>
  );
}
```

The `void` on the button discards the returned promise. `form.validate()` still resolves the submit values when those unmounted rows are valid, and rejects `FieldError[]` otherwise. The messages are read from `d.items.$errors`.

## From input to render

The control writes a value, dependent reactions run and their writes propagate in the same flush. Components subscribed to affected paths receive an update. A watch handles actions after a change. See [reactions and watches](/en/guide/linkage).
