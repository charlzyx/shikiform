## 为什么字段自动变成了只读？

只要某个字段的 `$value` 在 `reaction` 中被赋值过，引擎就会自动把它标记为计算字段，默认将 `$pattern` 设为 `'readPretty'`（防止手动编辑与计算结果冲突，但提交时仍会包含该值）。如果这个派生结果仅用于展示、不需要提交给后端，可以给它配置 `omit: true`。

## 隐藏的字段为什么还在阻止表单提交？

`visible: false`（或 `$hidden = true`）的语义是「隐藏界面渲染，但字段仍然有效」，因此它会继续参与校验并出现在提交结果中。如果希望字段在隐藏时跳过校验且不提交，请使用 `$visible = false`（等价于 `visible: false, omit: true`），引擎会保留它的值并在重新显示时恢复。

## 确认密码等辅助字段怎么从提交数据中剔除？

给辅助字段声明 `omit: true` 即可：这样输入框依然正常显示、也能执行「两次密码一致」的校验规则并拦住非法提交，但在调用 `getSubmitValues()` 或 `onSubmit` 时会被自动剔除。此时读取它的 `$visible` 依然为 `true`。

## 可以不引入 React 单独使用表单引擎吗？

可以。安装 `@shikiform/core` 后直接调用 `createForm` 即可，所有联动、校验、路径读写和数组操作都不依赖 React。使用 React 时直接安装 `@shikiform/react`，其中已经重导出了核心 API。

## 如何让字段名获得 TypeScript 类型检查？

通过 `const F = typed(form)` 获取绑定当前表单类型的组件集合，然后使用 `<F.Field name="..." />`、`F.useWatch(...)` 即可。对于需要动态拼接路径的场景，继续使用普通的 `<Field>`。

## 自定义组件怎么接入表单的值和错误提示？

- 如果组件只负责输入部分，推荐用 `connect(Control, mapProps({ ... }))` 包装，外部再套 `decorator={[FormItem]}`。
- 如果在自定义渲染函数或独立组件内部接线，直接调用 `useField()` 读写 `value`、`onChange`、`onBlur`。注意 `useFieldDecorator().control` 只包含标签、无障碍属性和错误信息，**不包含 `value` 与 `onChange`**。

## 查询列表和弹窗草稿表单在哪个包？

无 UI 的状态 Hook（`useQueryTable`、`useShadowForm`）位于 `@shikiform/hooks`，开箱即用的 Ant Design 组件（`QueryList`、`ShadowModal`、`ShadowDrawer`）位于 `@shikiform/antd`。详见 [查询列表与 Pro 组件](/guide/pro)。
