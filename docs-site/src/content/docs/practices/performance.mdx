ShikiForm 的依赖追踪精确到字段状态键：修改某一个输入框的值，只会重新执行读取过它的 `reaction`，并只重渲染订阅了该字段的组件。

## 避免整体订阅数组

在联动中读取 `d.items.$value` 会把整张数组都记为依赖——哪怕只修改了其中某一行的一个单元格，所有读过 `d.items.$value` 的 `reaction` 都会重新计算。因此针对行内字段的联动，请统一使用 `reaction.each`：它为每一行独立追踪依赖，修改第 3 行的数量时只会重跑第 3 行的回调。

在 React 视图层也是同样的道理：不要在父组件里通过 `useWatch` 读取整棵数组再手动 `.map` 渲染行。`<ArrayField>` 自身只订阅数组的长度、顺序和行身份标识，每个单元格通过自己的 `<Field>` 独立更新。

当数组行数较多时，可以直接在 `<ArrayField>` 上开启虚拟滚动，仅挂载可视区域内的行组件：

```tsx
<ArrayField name="rows" virtualScroll={{ height: 400 }}>
  {() => <Field name="name" component={[Input]} />}
</ArrayField>
```

即使部分行暂时未挂载到 DOM 中，通过 `reaction.each` 和 `fields` 声明的校验与计算规则依然会在引擎中正常生效。

## 服务端渲染（SSR）

`useForm` 支持在服务端渲染环境中直接运行（本文档站的在线预览示例就是先在服务端完成渲染再输出 HTML 的）。在编写服务端兼容的表单代码时，注意以下几点：

- **`reaction` 保持同步**：不要在 `reaction` 里发异步请求或访问 `window` 等浏览器全局对象；接口请求应放在 `watch` 中，拿到响应后再通过 `form.batch` 写回状态。
- **及时响应异步校验取消**：当异步校验在请求途中被新输入中止（`signal.aborted`）时，引擎会自动丢弃过期结果，但校验函数自身的 Promise 仍应妥善结束，参见 [跨字段与异步校验](/examples/async-rules)。
- **保持表单值可序列化**：建议让表单字段中始终保存纯 JSON 数据（如日期、颜色等控件将字符串存入表单，组件所需的 `Dayjs` / `Color` 对象仅在适配器层的 `format` / `parse` 中按需转换）。
