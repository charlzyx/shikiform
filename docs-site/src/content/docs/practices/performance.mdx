ShikiForm 的依赖追踪精确到字段状态键：修改某一个输入框的值，只会重新执行读取过它的 `reaction`，并只重渲染订阅了该字段的组件。

## 避免整体订阅数组

在联动中读取 `d.items.$value` 会把整张数组登记为依赖，任意一行的单个单元格变更都会重跑所有读取过 `d.items.$value` 的 `reaction`。行内字段联动请使用 `reaction.each`：引擎为每一行独立追踪依赖，修改第 3 行的数量只重跑第 3 行的回调。

React 视图层同样不要在父组件里用 `useWatch` 读取整张数组再手动 `.map` 渲染。`<ArrayField>` 只订阅数组长度、顺序与行键，每个单元格通过各自的 `<Field>` 独立更新。

当数组行数较多时，可以直接在 `<ArrayField>` 上开启虚拟滚动，仅挂载可视区域内的行组件：

```tsx
<ArrayField name="rows" virtualScroll={{ height: 400 }}>
  {() => <Field name="name" component={[Input]} />}
</ArrayField>
```

即使部分行暂时未挂载到 DOM 中，通过 `reaction.each` 和 `fields` 声明的校验与计算规则依然会在引擎中正常生效。

## 服务端渲染（SSR）

`useForm` 支持在服务端渲染环境中直接运行（本文档站的在线预览示例就是先在服务端完成渲染再输出 HTML 的）。在编写服务端兼容的表单代码时，注意以下几点：

- `reaction` 保持同步：不要在 `reaction` 内发起异步请求或读取 `window` 等浏览器全局对象；接口请求放在 `watch` 中，拿到响应后通过 `form.batch` 写回。
- 响应异步校验中止：异步校验被新输入中止（`signal.aborted`）后，引擎会丢弃过期结果，校验函数内的 Promise 仍应调用 `resolve(undefined)` 并清理定时器，见 [跨字段与异步校验](/examples/async-rules)。
- 保持表单值可序列化：表单字段中保存纯 JSON 数据（如日期、颜色存为字符串，`Dayjs` / `Color` 实例仅在适配器 `format` / `parse` 中转换）。
