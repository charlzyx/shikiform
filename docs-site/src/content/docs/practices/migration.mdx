---
title: 从 Formily 或 react-hook-form 迁移
description: 对照 Formily 与 react-hook-form 的核心概念差异，快速迁移字段模型、显隐控制与联动逻辑。
---

迁移现有表单时，建议先保证数据结构与最终提交结果一致，再逐步将联动与校验逻辑迁移到 ShikiForm 的机制上。

## 从 display / pattern 迁到四个布尔

`display`、`pattern`、`readPretty`、`virtual`、`$hidden`、`$display`、`$pattern` 已经删除，没有兼容别名。

| 旧写法 | 现在 |
|---|---|
| `display: 'visible'` | 默认。`visible` 默认为 `true` |
| `display: 'hidden'` / `$hidden = true` | 没有单独的 hidden。不渲染写 `visible: false`（同时跳过校验，值仍提交） |
| `display: 'none'` / `$visible = false`（旧语义：不提交） | `visible: false`，不提交再加 `omit: true` |
| `display: 'virtual'` | `omit: true`（仍渲染、仍校验、不提交、不计入 dirty） |
| `pattern: 'editable'` | `disabled` 和 `readOnly` 都不是 `true` |
| `pattern: 'disabled'` | `disabled: true`（置灰，仍提交） |
| `pattern: 'readOnly'` | `readOnly: true`。现在直接渲染预览，不再是禁用的原控件 |
| `pattern: 'readPretty'` | `readOnly: true` |
| `useForm({ pattern: 'readPretty' })` | `useForm({ readOnly: true })` |
| `mapProps({ readPretty })` | `mapProps({ preview })` |
| 计算字段默认 `readPretty` | 不再自动只读。要预览再写 `readOnly`，不提交再写 `omit` |

`visible` / `disabled` / `readOnly` 沿字段路径继承：这一层写了 `true` 或 `false` 就用这一层。`omit` 不继承。校验只在 `visible && !disabled && !readOnly` 时运行，否则清掉已有错误；重新打开后不会自动重跑。

## 从 Formily 迁移

ShikiForm 延续了「`<Field>` 绑定路径，`decorator` 包裹 `component`」的渲染模型，`FormItem`、`FormLayout`、`ArrayTable` 等核心组件名称也保持一致，主要差异在于联动与展示状态：

| Formily 概念 | ShikiForm 对应写法 |
|---|---|
| `reactions` / `x-reactions` | 在 `defineEffects` 中编写 `reaction((d) => ...)`，直接给 `$` 状态赋值 |
| `visible: false` | `$visible = false`（不渲染、不校验，值仍提交）。不提交再加 `$omit = true` |
| `hidden`（隐藏且跳过校验） | 没有单独的 hidden。不渲染用 `$visible = false`，它同时跳过校验，值仍提交 |
| 单独的虚拟字段标记 | 使用 `omit: true`（正常渲染和校验，但不参与提交与 `dirty` 统计） |
| `onFieldValueChange` 中清空关联字段 | 使用 `watch(source, effect)` 监听变化后执行一次性重置 |
| 数组行内 `map` 联动 | 使用 `reaction.each(select, fn)`（只接收两个参数） |

另外，在 ShikiForm 中被 `reaction` 赋值的计算字段默认仍会随表单提交，也不会自动变成预览；如果原本在 Formily 中是通过不注册字段来丢弃展示值，迁移后加上 `omit: true`。要阅读态再写 `readOnly`。`disabled` 的字段照常提交，这和 react-hook-form 相反。

## 从 react-hook-form 迁移

在 react-hook-form 中通过 `register` 或 `Controller` 绑定控件，在 ShikiForm 中统一替换为 `<Field>`，所有表单数据均由引擎统一托管。

| react-hook-form 概念 | ShikiForm 对应写法 |
|---|---|
| `watch('email')` | 在组件中用 `useWatch((d) => d.email.$value)`，在联动中直接读 `d.email.$value` |
| `setValue('city', '')` | 外部调用 `form.setValue('city', '')`，联动中赋值 `d.city.$value = ''` |
| `resolver`（如 Zod） | 直接传给 `useForm({ validate: schema })`（支持所有 Standard Schema 规范的校验库） |
| 条件渲染卸载输入框 | 还要校验就保持挂载（`$visible` 为 false 会跳过校验）。不提交写 `$omit = true` |

`form.setValue` 同样支持嵌套下标语法，例如 `orders[0].lines[2].qty`。
