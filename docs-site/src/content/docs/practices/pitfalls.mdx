有些误用会在开发环境抛出 `ShikiUsageError`，有些只是让联动订阅了意料之外的路径。

## 解构 handle

解构操作只用来提取子字段的 handle，任何 `$` 状态都必须直接在 handle 上读取或赋值。

### 不要解构 `$value` 后再尝试赋值

```ts
let { $value } = d.user.name
$value = 'Ada'
```

上例只改变局部变量，表单里的姓名保持原值。正确做法是保留子字段的 handle 再赋值：

```ts
const { name } = d.user
name.$value = 'Ada'
// 或者直接写：d.user.name.$value = 'Ada'
```

### 不要对 handle 使用展开运算符、rest 或 `Object.keys`

```ts
const { name, ...rest } = d.user
const copy = { ...d.user }
Object.keys(d.user)
```

`d.user` 只是指向字段位置的句柄，不是普通数据对象，因此不能展开或列出它的属性键。在开发环境执行以上写法会直接抛 `ShikiUsageError`。要列出对象的键，对 `d.user.$value` 调用 `Object.keys`：

```ts
const { name } = d.user
name.$value
const keys = Object.keys(d.user.$value)
```

### 不要对数组字段的 handle 进行数组解构

```ts
const [first] = d.items
```

数组 handle 同样不是原生数组，不能进行数组解构、`for…of` 遍历或调用 `.map`。需要操作特定下标、读取数组数据或逐行联动时，请使用下标访问、`$value` 或 `reaction.each`：

```ts
const { name } = d.items[0]
name.$value
d.items.$value
reaction.each(draft.items, (row) => {
  row.name.$value
})
```

能写在 draft 上的路径直接走 handle：`d.user.name.$value`、`d.items[i].qty.$value`、`d.extra[key].$value`。组件外用 `form.getValue('items[0].name')`。`query(path)` 只用于路径已经是字符串的时候（`pathOf`、配置、props），例如 effect 里 `query(pathOf('menus', pos)).$disabled = true`。见 [按路径读写](/basics/path)。

## 在 effect 外原地修改读到的值

`reaction` / `watch` / `batch` 里，对象或数组的 `$value` 是可写 draft：`d.user.$value.name = 'Ada'` 等于 `d.user.name.$value = 'Ada'`，`d.items.$value.push(row)` 和 `useArrayField().push(row)` 走同一套行操作。`getValue`、`form.values` 和校验器里的 `value` 不是这层 draft。

```ts
form.getValue('user').name = 'Ada'
form.values.tags.push('x')
```

这些读在开发环境都是只读保护（Proxy）：直接原地改属性（包括在校验器里改 `value` / `ctx.root` / `ctx.get()`）会抛 `ShikiUsageError`，也不会通知组件更新。`Map` 的 `set` / `delete` / `clear`、`Set` 的 `add` / `delete` / `clear`、`Date` 的 `set*`、`Object.setPrototypeOf` 同样会抛错；其他类实例不包装。生产环境在联动外直接返回原始对象。要在联动外改值，用 `form.setValue`；在组件里追加行，用 `useArrayField().push(row)`。

```ts
d.user.$value.name = 'Ada'
d.items.$value.push(row)
form.setValue('user.name', 'Ada')
```

注意：开发环境返回的只读代理和底层原对象不是同一个引用（`getValue('user') === toRaw(getValue('user'))` 为 `false`），生产环境则是同一个。`indexOf` / `includes` 和 `deepEqual` 都会自动解包比较，所以 `rows.indexOf(rawRow)` 照常能找到。不要把 `useField().value`（或 `form.binding(path).value`）直接交给会原地 `push` / `sort` 的表格库；报错信息会指明是哪个字段，改用 `useArrayField().push` 或 `form.setValue` 即可。

在开发环境把 `form.values` 直接传给 `structuredClone`、`postMessage` 或 IndexedDB 会抛 `DataCloneError`（因为带了只读 Proxy），生产环境不会。要拿纯数据副本用 `snapshot(form.values)`（含 `omit` 字段，从 `@shikiform/core` 导入）；要拿提交结果用 `getSubmitValues()`；`toRaw(value)` 返回底层原对象，直接改它不会触发更新。

被 `Object.freeze` 冻结的数据（如 Immer / Redux 里的对象）也能正常读取，不会触发浏览器 Proxy 报错。不可改写的属性会按原对象返回。

## 动态键写入时，留意读了哪一级

`d.overrides[id].$value = price` 直接定位并写入一个字段。如果先展开 `d.overrides.$value` 再赋值，就额外读取了整张价格表；在 reaction 里，其他 SKU 的价格变化也会唤醒它。

```ts
watch.each(draft.rows, (row, { d }) => {
  const id = row.id.$value
  if (id) d.overrides[id].$value = row.price.$value
})
```

数组新增一行时，`watch.each` 会先试跑一次回调来记下你读了哪些字段（这次试跑里的赋值不会生效）；之后每当这行真正触发时都会更新它盯着的字段，就算行被移动或增删，监听也会跟着那一行走。上例里每行只盯着自己的 `id` 和 `price`。回调里写目标字段时直接走 handle 赋值（如 `d.overrides[id].$value = ...`）；首次试跑期间如果直接改读出的 `$value` 对象或调用数组 `push`，开发环境会报只读错误。

如果要在来源变化时追加一次行，把 `d.items.$value.push(row)` 放在 `watch(source, action)` 的动作回调里。在 `reaction` 中无条件 `push` 会反复读取并改变同一个数组，可能形成循环。按对象键派生状态、渲染动态输入框的完整示例见[动态对象字段](/guide/linkage#动态对象字段)。

## 在同一轮联动中读回刚写入的旗标

同一轮联动里，写完 `$value`、`$enum`、`$rules` 或 UI 状态后立刻再读，能直接拿到刚写进去的新值：

```ts
d.total.$value = d.price.$value * d.qty.$value
d.tax.$value = d.total.$value * 0.1
d.rows.$value.push(row)
d.rows.$value.push(row2)
```

但布尔开关（`$visible` / `$disabled` / `$readOnly` / `$omit` / `$required`）在当前轮不会立刻回显，马上再读只会看到旧值，开发期会直接抛 `ShikiUsageError`。把算好的布尔先存进局部变量再用：

```ts
const shown = d.price.$value > 0
d.tax.$visible = shown
```

`$componentProps` / `$decoratorProps` 同样会在当前轮叠加，所以可以先写 `props.style ??= {}` 再改里面的键。

## 不要原地修改 `$componentProps` 里的 Date、Map、Set 或类实例

这些值不是普通对象，draft 会原样交出来。`date.setMonth(1)`、`map.set(key, value)`、`box.n = 1` 改的是声明里的那一份，没有 `write`，也不会通知依赖它的 reaction。要换成新值：

```ts
d.city.$componentProps.date = new Date('2021-05-01')
const cache = d.city.$componentProps.cache as Map<string, number>
d.city.$componentProps.cache = new Map(cache).set('a', 1)
```

`structuredClone` 不能克隆 draft（抛 `DataCloneError`）。要拷贝读到的普通数据时，展开或 `JSON.stringify` 即可；别把 draft 代理本身交给 `structuredClone`。

## 在作用域内部重复书写父级路径前缀

```tsx
<ObjectField name="address">
  <Field name="address.city" />
</ObjectField>
```

`<ObjectField>` 和 `<ArrayField>` 内部使用的 `name` 是相对于当前作用域解析的。上面的写法会拼接成 `address.address.city`（哪怕外层使用 `typed(form)` 的根 `F.Field` 通过了类型检查，运行时依然会重复拼接并在开发模式报错）。在强类型写法中，应当使用作用域回调提供的子组件来约束相对路径：

```tsx
<F.ObjectField name="address">
  {(obj) => <obj.Field name="city" decorator={[FormItem]} component={[Input]} />}
</F.ObjectField>
```

在数组行中同理，应当直接写 `name`，而不是 `items.0.name`。

## 误以为 `$visible = false` 会从提交结果里去掉

```ts
d.taxId.$visible = false
```

`$visible = false` 只是不渲染、跳过校验。值仍然提交。不进提交结果要再写 `$omit`：

```ts
d.taxId.$visible = false   // 不渲染、不校验，仍然提交
d.taxId.$omit = true       // 仍然渲染、仍然校验，不提交
d.taxId.$visible = false   // 两个一起：不渲染、不校验、不提交
d.taxId.$omit = true
```

没有「藏起来但继续校验」的开关。仍需校验的字段应保持挂载（例如多标签页表单中仅用 CSS 隐藏非激活页签，或把规则声明在 `useForm({ fields })` 中，见 [标签页与未挂载字段](/examples/forms#标签页与未挂载字段)）。

## 把 `useFieldDecorator().control` 当成数据绑定传给控件

```tsx
function Bad() {
  const { control } = useFieldDecorator()
  return <input {...control} />
}
```

`control` 只包含标签、错误文案、`id`、`onBlur` 和无障碍属性，**里面没有 `value` 和 `onChange`**。自己写原生或第三方受控组件时，需要通过 `useField()` 手动接入值和变更回调，或者直接使用 `connect` 包装组件：

```tsx
function NameInput() {
  const field = useField<string>()
  return (
    <input
      id={field.id}
      value={field.value ?? ''}
      onChange={(event) => field.onChange(event.target.value)}
      onBlur={field.onBlur}
    />
  )
}
```

如果控件自己渲染标签，请配合 `useField()` + `control`；若想统一复用属性映射与 `format`/`parse` 转换，请使用 `connect`，详见 [接入组件库](/guide/headless#接自己的组件库)。

## 把派生计算写进 `watch`

```ts
watch((d) => d.price.$value, (d) => {
  d.total.$value = d.price.$value * 2
})
```

`watch` 在初始化时不会执行，因此页面刚打开时 `total` 不会得到计算值。凡是「B 始终由 A 推导得出」的逻辑都应该用 `reaction`；`watch` 仅用于「当 A 发生变化时执行一次动作」（例如切换省份时清空城市）：

```ts
reaction((d) => {
  d.total.$value = (d.price.$value ?? 0) * 2
})

watch((d) => d.province.$value, (d) => {
  d.city.$value = undefined
})
```

## 在渲染期调用 `onChange` 或 `form.setValue`

```tsx
// ✗ 渲染期间写入表单：SSR 或被 React 放弃的并发渲染也会改写 store
function BadInput() {
  const field = useField<string>()
  if (!field.value) field.onChange('default')
  return <input value={field.value ?? ''} onChange={(e) => field.onChange(e.target.value)} />
}
```

不要在组件渲染期间直接调用 `field.onChange` 或 `form.setValue`。服务端渲染或 React 并发模式下被放弃的渲染依然会执行这段代码并污染表单状态。默认值请通过 `initialValues`、`reaction` 设置，副作用写入请放在事件处理器或 `useEffect` 中：

```tsx
// ✓ 在事件或 useEffect 中写入
function GoodInput() {
  const field = useField<string>()
  useEffect(() => {
    if (!field.value) field.onChange('default')
  }, [field.value, field.onChange])
  return <input value={field.value ?? ''} onChange={(e) => field.onChange(e.target.value)} />
}
```

## 在 `reaction` 中跨 `await` 写草稿，或直接调用 `form.reset` / `submit`

`reaction` 必须是同步函数：

- 不能把 `reaction` 写成 `async` 函数，回调一返回，草稿 `d` 就会失效。在 `await` 之后再给 `d` 赋值，开发环境会抛 `ShikiUsageError`，生产环境直接忽略。
- 在 `reaction` 里同步调用 `form.reset` 或 `form.submit` 会打断当前这一轮联动更新，开发环境会抛 `ShikiUsageError`（仅开发期检查）。而在 `reaction` / `watch` / `batch` 里调用 `form.setValue`、`form.patchValues`、`form.getValue` 时，它们和草稿 `d` 读写同一份临时数据：立刻能读到刚改的值，整轮结束时一起生效，中途报错一起撤销。

联动赋值推荐统一直接写草稿（`d.x.$value = …`）；异步请求或 `reset` / `submit` 等动作请放进 `watch`，接口返回后再调用 `form.setValue` 或 `form.batch`。

## 漏写 `$` 或拼错 `$` 状态名

```ts
// ✗ 漏写 $，直接给 handle 的普通属性赋值
d.user.name.value = 'Ada'

// ✗ 拼错保留状态名
d.user.name.$valeu = 'Ada'
const v = d.user.name.$valeu
```

- 直接给 handle 的普通属性（没带 `$`）赋值时，开发环境抛 `ShikiUsageError`，生产环境直接忽略，不会抛原生 `TypeError`。
- 拼错带 `$` 的状态名（如 `$valeu`、`$requird`）且数据里本来就没有这个字段名时，开发环境抛 `ShikiUsageError` 并提示正确拼写；生产环境读取返回 `undefined`，写入被忽略。如果业务数据本身确有 `$` 开头的普通字段名（如 `$values`），照常按子字段处理。
