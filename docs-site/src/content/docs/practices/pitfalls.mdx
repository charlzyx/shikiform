开发模式下，下面提到的许多误用都会直接抛出 `ShikiUsageError` 并在错误消息中给出修改建议（生产环境出于性能考虑会跳过这些运行时检查）。对照下面的正误案例，可以避开绝大多数踩坑点。

## 解构 handle

解构操作只用来提取子字段的 handle，任何 `$` 状态都必须直接在 handle 上读取或赋值。

### 不要解构 `$value` 后再尝试赋值

```ts
const { $value } = d.user
$value = 'Ada'
```

`$value` 返回的是当前值的快照副本，对局部变量重新赋值不会改变表单内部的状态。正确做法是保留子字段的 handle 再赋值：

```ts
const { name } = d.user
name.$value = 'Ada'
// 或者直接写：d.user.name.$value = 'Ada'
```

### 不要对 handle 使用展开运算符、rest 或 `Object.keys`

```ts
const { name, ...rest } = d.user
const copy = { ...d.user }
Object.keys(d.user)
```

draft handle 是路径代理而不是普通数据对象，因此不支持枚举属性键或展开。在开发环境下执行以上操作会直接抛出 `ShikiUsageError`。需要读取或拷贝整份数据时，应访问 `d.user.$value`：

```ts
const { name } = d.user
name.$value
const copy = d.user.$value
```

### 不要对数组字段的 handle 进行数组解构

```ts
const [first] = d.items
```

数组 handle 同样不是原生数组，不能进行数组解构、`for…of` 遍历或调用 `.map`。需要操作特定下标、读取数组数据或逐行联动时，请使用下标访问、`$value` 或 `reaction.each`：

```ts
const { name } = d.items[0]
name.$value
d.items.$value
reaction.each((d) => d.items, (row) => {
  row.name.$value
})
```

对于动态嵌套路径，也可以使用 [`get`](/basics/path)：`get(d, 'user.name').$value` 或 `get(d, 'items[0].name').$value`。

## 直接修改 `$value` 上的对象或数组

```ts
d.user.$value.name = 'Ada'
d.items.$value.push(row)
```

`$value` 返回的是不可变快照：直接原地修改它在开发环境的 `reaction`、`watch` 和 `form.batch` 中会直接报错，在其他地方也不会触发任何组件重渲染。更新时应直接给对应字段赋值，或在外部调用数组操作方法：

```ts
d.user.name.$value = 'Ada'
d.items.$value = [...d.items.$value, row]
// 在组件或外部逻辑中追加行：form.pushArray('items', row)
```

## 在同一轮联动中读回刚写入的 `$value`

```ts
d.total.$value = d.price.$value * d.qty.$value
d.tax.$value = d.total.$value * 0.1
```

在 `reaction` 中，数据写入会缓冲到本轮函数返回后才统一生效，因此第二行读到的 `d.total.$value` 依然是旧值（开发模式下会报错提示）。正确的做法是先把计算结果存进局部变量：

```ts
const total = d.price.$value * d.qty.$value
d.total.$value = total
d.tax.$value = total * 0.1
```

唯一的例外是 `$componentProps` / `$decoratorProps` 等 UI 状态：它们的写入会在当前轮次内即时叠加，因此可以先写 `props.style ??= {}` 再修改里面的样式属性。

## 在作用域内部重复书写父级路径前缀

```tsx
<ObjectField name="address">
  <Field name="address.city" />
</ObjectField>
```

`<ObjectField>` 和 `<ArrayField>` 内部使用的 `name` 是相对于当前作用域解析的。上面的写法会拼接成 `address.address.city`（哪怕外层使用 `typed(form)` 的根 `F.Field` 通过了类型检查，运行时依然会重复拼接并在开发模式报错）。在强类型写法中，应当使用作用域回调提供的子组件来约束相对路径：

```tsx
<F.ObjectField name="address">
  {(obj) => <obj.Field name="city" decorator={[FormItem]} component={[Input]} />}
</F.ObjectField>
```

在数组行中同理，应当直接写 `name`，而不是 `items.0.name`。

## 误把 `$visible = false` 当成 `hidden`

```ts
d.taxId.$visible = false
```

`$visible = false` 对应的是 `display: 'none'`——不仅不渲染，还会**跳过校验并从提交结果中剔除**（虽然值仍留在引擎里）。如果你的目的是「隐藏界面但依然参与校验和提交」，应当使用 `$hidden = true`：

```ts
d.taxId.$hidden = true       // 隐藏界面，但保留校验与提交
d.taxId.$display = 'virtual' // 正常渲染并校验，但不提交（$visible 仍为 true）
d.taxId.$visible = false     // 即 none：不渲染、不校验、不提交
```

## 把 `useFieldDecorator().control` 当成数据绑定传给控件

```tsx
function Bad() {
  const { control } = useFieldDecorator()
  return <input {...control} />
}
```

`control` 只包含标签、错误文案、`id`、`onBlur` 和无障碍属性，**里面没有 `value` 和 `onChange`**。自己写原生或第三方受控组件时，需要通过 `useField()` 手动接入值和变更回调，或者直接使用 `connect` 包装组件：

```tsx
function NameInput() {
  const field = useField<string>()
  return (
    <input
      id={field.id}
      value={field.value ?? ''}
      onChange={(event) => field.onChange(event.target.value)}
      onBlur={field.onBlur}
    />
  )
}
```

如果控件自己渲染标签，请配合 `useField()` + `control`；若想统一复用属性映射与 `format`/`parse` 转换，请使用 `connect`，详见 [接入组件库](/guide/headless#接自己的组件库)。

## 把派生计算写进 `watch`

```ts
watch((d) => d.price.$value, (d) => {
  d.total.$value = d.price.$value * 2
})
```

`watch` 在初始化时不会执行，因此页面刚打开时 `total` 不会得到计算值。凡是「B 始终由 A 推导得出」的逻辑都应该用 `reaction`；`watch` 仅用于「当 A 发生变化时执行一次动作」（例如切换省份时清空城市）：

```ts
reaction((d) => {
  d.total.$value = (d.price.$value ?? 0) * 2
})

watch((d) => d.province.$value, (d) => {
  d.city.$value = undefined
})
```
