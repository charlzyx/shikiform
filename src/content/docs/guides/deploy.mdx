## 路线已定

Cloudflare Pages 的 GitHub 联动。Chao 自己在 Cloudflare 后台连仓库，Muse 不持有 Cloudflare 账号或 token。

## 为什么构建能直接被 CF 联动部署

- Astro Starlight 默认静态构建，输出目录就是 `dist/`，不需要 adapter、不需要 server。
- `astro.config.mjs` 里 `base: '/'`，没有写死成 GitHub Pages 子路径（如 `/shiki/`）。CF Pages 在项目根域名下提供服务，base 必须是根路径。
- `SITE_URL` 可选，只影响 sitemap / 规范链接，不影响路由；不填也能正常跑。

## Chao 在 CF 后台的操作步骤

1. 把本项目作为仓库根推到 GitHub（仓库根下就是 `package.json`、`astro.config.mjs`；若作为子目录推，Root directory 就填那个子目录）。
2. Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git，选择该仓库。
3. Build settings：
   - Production branch：主分支（通常是 `main`）
   - Framework preset：`Astro`（若预设填的不对，按下面手动改）
   - Build command：`npm run build`（`npm run build:cf-pages` 完全等价）
   - Build output directory：`dist`
   - Root directory：留空（仓库根就是本项目时）
4. Environment variables：可不填。`SITE_URL` 可选，拿到 `https://<项目名>.pages.dev` 后如需规范 sitemap 再填入并重新部署。
5. Save and Deploy。之后每次推到生产分支，CF 自动重新部署。

## 验证

- 首页 SKU 编辑器能点，任意顺序联动都对
- `/guides/field-tree/`、`/guides/linkage/`、`/guides/tables/` 都能打开
- 静态资源路径是根路径（如 `/_astro/...`），不是 `/shiki/_astro/...`

## 排障

- 资源 404 且带 `/shiki/` 前缀：base 被改成了子路径，改回 `'/'` 再推。
- 构建报 Node 版本过低：在 CF Environment variables 里加 `NODE_VERSION=22`。
- 产物不对：确认输出目录是 `dist`，不是 `storybook-static` 或 `build`。

## 不需要做的事

不需要 API token，不需要 wrangler 登录，不需要 GitHub Actions 部署工作流，不需要 Muse 替你接 CF 账号。
