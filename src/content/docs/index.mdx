# 这一轮：先写用例，再写实现

旧实现已经全部删除。这一轮先站在应用开发者的角度，用理想 API 把场景写出来。`packages/core`、`packages/react`、`packages/antd` 现在是按这个 API 做的引擎，查询表单的浏览器用例在 `apps/e2e`。本站这些页面仍然只展示 `usage/` 规格，不是可运行示例。

- `usage/*.tsx` 仍是**伪代码**：不参与 `tsc`，不能当示例运行。实现在 `packages/`，不在这些页面里。
- 每个用例页 = 一个真实场景的完整 `.tsx`（源文件在仓库 `usage/` 目录，页面直接引用源文件，只有一份）。
- 代码里所有 `// ❓` 都是我拿不准的 API 点，会在每页顶部汇总；跨用例的汇总、选项和建议在 **[待拍板](/decisions/)**。
- 这些用例隐含的完整公开 API 整理在 **[API 草案](/api/)**。

## 怎么看（建议顺序）

1. **[待拍板](/decisions/)**：顶部是 2026-10-27 已拍板的 D1（删 Void / Transient / Computed 类型）、D2（树节点 pos）、D3–D8（effects 语法、UI Brand、pattern、表格列、删 scope、`virtual`），然后是仍开放的 Q0 / Q5 / Q10 与新的待拍板。
2. **[16 effects 参考](/usage/16-effects-reference/)**：一页看完 `autorun` / `autorun.each` / `watch` + draft 代理的全部写法。
3. **[07 SKU 选择器](/usage/07-sku-editor/)**、**[09 查询表单 + 表格](/usage/09-query-table/)**、**[10 行展开二级表格](/usage/10-expandable-nested-table/)**：最能检验 API 的三个场景。
4. 其余用例按需翻；**[API 草案](/api/)** 当索引查。
